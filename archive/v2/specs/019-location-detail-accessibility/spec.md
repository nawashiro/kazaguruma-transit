## User Scenarios & Testing *(mandatory)*

### User Story 1 - 場所詳細を迷わず読み取る (Priority: P1)

利用者は、場所一覧から開いた場所詳細ページで、場所名をページの主見出しとして一度だけ確認し、説明、地域、提供情報、ライセンス、外部サイトを文書の順序に沿って読み取れる。場所名と同じ内容を重複見出しとして読まされたり、画像のために同じ場所名を二重に聞かされたりしない。

**Why this priority**: 見出しと情報の関係は、視覚表示だけでなくスクリーンリーダーのページ内移動と直接アクセス時の理解を左右する、場所詳細の中心的な契約である。

**Independent Test**: 完全な場所fixtureを使って詳細ページをレンダリングし、`h1`、`h2`、`dl/dt/dd`、画像の`alt`、外部リンクをRTLで検証できる。

**Acceptance Scenarios**:

1. **Given** 有効な場所の詳細ページを表示している、**When** 見出し一覧を確認する、**Then** 場所名を名前とする`h1`がちょうど1つ存在し、同じ場所名の重複見出しと「説明」見出しは存在しない。
2. **Given** 場所に地域情報がある、**When** 詳細情報を読む、**Then** 「地域」が`dt`、地域名が対応する`dd`として同じ`dl`に表示される。
3. **Given** 場所に提供情報がある、**When** 提供情報を読む、**Then** 「提供情報」は`h2`であり、座標データ、画像、説明文、ライセンスが条件に応じた`dt`/`dd`の組で表示される。
4. **Given** 場所に画像がある、**When** 支援技術が画像を解釈する、**Then** 場所名を重複して読み上げる代替テキストではなく空の`alt`を持つ装飾画像として扱われる。
5. **Given** 場所に画像がある、**When** 画像を狭い画面で表示する、**Then** 固定高さによる過度な切り抜きではなく、明示した画像比率を持つレスポンシブな表示領域に収まる。

### User Story 2 - 標準リンクで安全に移動する (Priority: P1)

利用者は、ページ上部の「場所一覧に戻る」リンクから一覧へ戻り、主要操作の「ここへ行く」から既存の目的地設定へ移動できる。JavaScriptのrouter操作や、見た目だけボタンにした移動操作に依存しない。

**Why this priority**: ネイティブリンクは、キーボード操作、リンクのコピー、ブラウザ履歴、支援技術のリンク一覧を標準動作で利用できるためである。

**Independent Test**: ページをレンダリングし、戻るリンクが上部に1つだけあること、目的地操作が`a`要素であること、既存の`destination`クエリのシリアライズが保たれていることを検証できる。

**Acceptance Scenarios**:

1. **Given** 成功した場所詳細ページを表示している、**When** ページ上の戻る導線を確認する、**Then** 上部に「場所一覧に戻る」という`a`要素が1つだけあり、`/locations`へリンクする。下部に同じリンクを重複配置しない。
2. **Given** 有効な場所の目的地設定操作が表示されている、**When** 利用者が操作を確認する、**Then** 「ここへ行く」は`button`ではなくネイティブ`a`要素で、既存の場所オブジェクトをエンコードした`destination`クエリを持つ。
3. **Given** 利用者が目的地リンクをキーボードで操作する、**When** フォーカスを移動して起動する、**Then** ネイティブリンクのフォーカス表示と標準の履歴・リンク操作が利用できる。
4. **Given** 外部サイトまたはライセンスへのリンクが表示されている、**When** 利用者がリンク目的を確認する、**Then** リンク名から目的を識別でき、外部タブを開く既存方針を維持しつつ安全な`rel`属性を持つ。

### User Story 3 - 読みやすい文字と十分なコントラストで操作する (Priority: P1)

利用者は、場所詳細の本文、操作、定義リスト、リンクを標準の本文サイズと通常の文字色で読み取れる。小さな文字や低コントラストの装飾指定に依存せず、モバイルでも操作できる。

**Why this priority**: 文字サイズとコントラストは、視力・表示倍率・屋外利用などの条件にかかわらず、詳細情報と主要操作へ到達できるための基礎である。

**Independent Test**: 詳細ページのTSX/CSSクラスを静的契約で検査し、ページ固有の通常本文・操作文字が16px相当以上であること、通常文字が適切な色トークンを使うこと、ボタン既定値に任せないことを確認できる。アプリ全体の監査では、ルビ補助文字を除く通常UIの16px未満を検出できる。

**Acceptance Scenarios**:

1. **Given** 場所詳細の本文または操作文字を表示している、**When** 算出サイズまたは対応するユーティリティ指定を確認する、**Then** 16px相当以上を原則`text-base`以上で表示し、詳細ページの通常UIに`text-sm`、`text-xs`、16px未満の任意サイズ指定を残さない。
2. **Given** DaisyUIの標準ボタン相当の見た目を持つ操作がある、**When** 文字サイズを確認する、**Then** 標準既定値に依存せず、操作文字が16px相当以上になる明示的な指定を持つ。
3. **Given** 通常の本文、リンク、定義項目、状態メッセージを表示している、**When** light/dark両テーマの文字色と背景色を確認する、**Then** `text-base-content`等の通常文字用トークンを使い、`text-black/60`のような低コントラスト色や通常文字へのopacity utilityを使わず、通常文字4.5:1以上、大きな文字3:1以上のコントラストを満たす。必要な非テキスト要素は3:1以上とする。
4. **Given** アプリ全体の文字サイズ監査を実行する、**When** `src/app`、`src/components`、対象CSSを検査する、**Then** ルビの補助テキストとして許可した厳密な`rt`例外を除き、16px未満の指定を検出して失敗できる。解析不能な任意値を成功扱いにしない。
5. **Given** 利用者がモバイル画面で主要リンクを操作する、**When** 実ブラウザの表示領域を確認する、**Then** リンクと主要操作の表示領域は幅・高さとも44 CSS px以上を確保し、キーボードフォーカスを視認できる。

### User Story 4 - ページ状態とタイトルを一貫して理解する (Priority: P1)

利用者は、有効な場所、存在しない場所、取得失敗、読み込み中のいずれであっても、ページの状態、主見出し、一覧へ戻る導線を一貫して確認できる。有効な場所を共有・再読み込みした場合は、場所名に基づくページタイトルを確認できる。

**Why this priority**: 直接アクセス可能な動的ページでは、成功時だけでなく失敗・待機状態の文書構造とタイトルが、利用者の現在地と次の行動を決めるためである。

**Independent Test**: 成功、未知ID、データ取得失敗、ローディングのfixtureまたは境界を個別に表示し、各状態の`h1`、戻るリンク、日本語メッセージ、metadataを検証できる。

**Acceptance Scenarios**:

1. **Given** 場所データが正常に解決される、**When** `千代田区役所`の詳細ページを開く、**Then** document titleは`千代田区役所 - 場所詳細`となり、主見出しも`千代田区役所`となる。
2. **Given** URL識別子が存在しない、**When** 詳細ページを開く、**Then** 空の詳細を表示せず、「場所が見つからない」ことを説明する日本語の`h1`、alert、上部の一覧リンクを表示する。
3. **Given** CDN等から場所データを取得できない、**When** 詳細ページを開く、**Then** 未知IDとは異なる取得失敗の日本語説明を表示し、空の詳細へフォールバックしない。
4. **Given** 詳細データを読み込み中である、**When** loading状態を表示する、**Then** 読み込み中であることを示す日本語の主見出しまたは状態メッセージと、一覧へ戻る導線の位置を成功・失敗状態と一貫させる。
5. **Given** 成功・not-found・取得失敗・loadingのいずれかを表示している、**When** 見出しと戻る導線を確認する、**Then** ページごとに主`h1`は1つだけで、戻るリンクは上部に1つだけ配置される。

### User Story 5 - 振る舞いを保ったままページ実装を単純化する (Priority: P2)

開発者は、場所詳細の振る舞いがすべてGreenになった後、ページ側に詳細表示を統合し、不要なクライアントコンポーネント分離とその専用テストを整理できる。利用者から見える情報、リンク、状態、目的地設定は変わらない。

**Why this priority**: これは利用者向け契約の修正ではなく、ページの責務とテスト境界を単純化する保守上の改善である。先に行うと、見出しやリンクの回帰原因を追いにくくするため、P1のGreen後に限定する。

**Independent Test**: ページレベルの振る舞いテストを維持した状態で、`LocationDetailContent`のクライアント依存がなくなり、不要な公開コンポーネントとテストが削除またはページ契約へ移行されていることを静的検査とfocused Jestで確認できる。

**Acceptance Scenarios**:

1. **Given** 見出し、情報構造、リンク、文字サイズ、色、状態、タイトルのテストがGreenである、**When** 実装を整理する、**Then** `LocationDetailContent`の責務をページ側へ統合し、不要な`useRouter`・クライアント境界・専用コンポーネントを残さない。
2. **Given** ページ統合リファクタリングが完了している、**When** ページレベルのテストと関連回帰テストを実行する、**Then** 成功・任意項目欠落・目的地リンク・状態表示・metadataの公開挙動がリファクタリング前と同じ契約で通過する。
3. **Given** 共通レイアウトがKo-fi支援欄を表示している、**When** ページ統合を行う、**Then** `KoFiSupport`のカード構造、見出し、iframe、表示位置をこのfeatureの都合で変更しない。

## Edge Cases

- 場所名が日本語または記号を含む場合でも、表示上の`h1`と動的タイトルが同じ場所名を使う。
- 場所IDが空、空白、`/`、バックスラッシュ、`?`、`#`、制御文字を含む場合は、成功詳細を表示せず、不正IDとして一覧へ戻れる。
- 同じIDがデータ内に複数存在する場合は、未知IDと混同せず、重複・不正データとして空詳細を表示しない。
- 画像、説明、地域、外部URI、画像提供者、説明文提供者の一部またはすべてが欠落しても、存在する主要情報と提供情報を保つ。欠落した任意項目の空ラベルを表示しない。
- `description`がない場合は「説明」見出しを表示せず、`descriptionCopyright`だけを単独表示しない。
- 外部サイトURIまたはライセンスURIが存在しても、リンク目的、focus、`noopener noreferrer`を失わない。
- ルビの`rt`補助文字の小ささは許可するが、通常要素に`text-sm`を付ける理由としてルビクラスを使わない。
- 静的監査が解釈できないarbitrary値、動的クラス、opacity指定を安全側に扱い、検査不能を違反見逃しとして通過させない。
- DaisyUIカードのクラスは提供情報の通常表示には使わないが、共通レイアウトのKo-fiカードには適用し続ける。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 場所詳細の成功状態は、場所名を名前とする一意な`h1`を1つだけ提供し、場所名の重複見出しと「説明」見出しを提供してはならない。
- **FR-002**: 場所詳細の成功状態は、地域を`dl`内の`dt`/`dd`の組として表示しなければならない。地域がない場合は空の地域ラベルを表示してはならない。
- **FR-003**: 提供情報は`h2`「提供情報」と、それに対応する`dl`内の`dt`/`dd`の組で表示しなければならない。通常の提供情報にはカード表現を使ってはならない。
- **FR-004**: 共通レイアウトのKo-fi支援カードは、このfeatureの情報構造変更によって変更してはならない。
- **FR-005**: 詳細画像は装飾情報として空の`alt`を持たなければならず、場所名を重複する`alt`や不要な`role="img"`を付与してはならない。画像表示領域は固定高さではなく、明示した比率でレスポンシブに表示しなければならない。
- **FR-006**: 成功状態の上部には`/locations`への「場所一覧に戻る」ネイティブリンクを1つだけ表示し、下部に同じ戻るリンクを重複表示してはならない。not-found、取得失敗、loading状態も同じ位置契約を保たなければならない。
- **FR-007**: 「ここへ行く」はネイティブ`a`要素として表示し、既存の`convertToLocation`相当の値をJSONエンコードした`destination`クエリを維持しなければならない。移動のために`useRouter`またはクリック処理付きボタンを使ってはならない。
- **FR-008**: 外部サイトとライセンスのリンクは、リンク目的を識別できるアクセシブルな名前、キーボードフォーカス、既存の外部タブ遷移時の安全な`rel`属性を維持しなければならない。主要リンクと操作の実ブラウザ表示領域は幅・高さとも44 CSS px以上でなければならない。
- **FR-009**: 場所詳細の通常本文、定義項目、リンク、状態メッセージ、操作文字は16px相当以上とし、原則として`text-base`以上の指定を使用しなければならない。詳細ページの通常UIに`text-sm`、`text-xs`、16px未満の任意サイズ指定を残してはならない。
- **FR-010**: 場所詳細の通常文字は`text-base-content`等の通常文字用トークンを使わなければならず、`text-black/60`等の低コントラスト色、通常文字へのopacity utility、同等の低コントラスト指定を使ってはならない。light/dark両テーマで、通常文字は4.5:1以上、大きな文字は3:1以上、必要な非テキスト要素は3:1以上のコントラストを満たさなければならない。
- **FR-011**: アプリ全体の静的文字サイズ監査は、認証UIを含む`src/app`、`src/components`および対象CSSを検査し、ルビ補助文字として明示的に許可した`src/app/globals.css`の厳密な`rt { font-size: 70%; }`だけを例外として、16px未満を検出しなければならない。検査不能な値をfail-openで許可してはならない。認証UIの対象は通常文字のサイズ・色に限り、認証の振る舞い・データフローを変更してはならない。
- **FR-012**: loading、成功、not-found、取得失敗の各状態は、空の詳細を誤表示せず、日本語の状態説明、主`h1`、上部の一覧リンクを提供しなければならない。取得失敗と未知IDは同じ状態として扱ってはならない。
- **FR-013**: 有効な場所の動的metadata titleは`${location.name} - 場所詳細`形式とし、`千代田区役所`の場合は`千代田区役所 - 場所詳細`を返さなければならない。invalid、unknown、duplicate、data-load-errorでデータを解決できない状態には、raw IDを含まない既存値`場所詳細 | 風ぐるま乗換案内`を共通のフォールバックタイトルとして返さなければならない。
- **FR-014**: `LocationDetailContent`の統合・削除は、FR-001〜FR-013の振る舞いがGreenになった後にだけ行い、ページレベルの公開契約テストを維持しなければならない。統合後に不要なクライアント境界、`useRouter`、専用コンポーネントテストを残してはならない。
- **FR-015**: 本featureは、新しい場所データ形式、永続化、目的地クエリ形式、認証の振る舞い・データフロー、レート制限、共通Ko-fi支援欄を導入・変更してはならない。認証UIの通常文字に対するFR-011の監査・是正はこの制約に反しない。
- **FR-016**: 本featureのテストは、実装前に意味のあるREDを確認し、テストコードの読み取り専用レビューが`VERDICT: PASS`となるまで本番コードを変更してはならない。各本番実装後はfocused Jest、TypeScript、対象Lint、`git diff --check`を実行し、独立した本番コードレビューを`VERDICT: PASS`まで完了扱いにしてはならない。

### Key Entities

- **Location Detail Document**: 場所名、説明、地域、画像、外部サイト、目的地設定、提供情報を、通常の文書構造で提供する詳細ページ。
- **Location Detail State**: `loading`、`success`、`not-found`、`data-load-error`、不正・重複IDを含む`error`を、利用者向けに区別して表示するページ状態。
- **Destination Link**: 既存の場所オブジェクトを`destination`クエリへシリアライズし、ホーム画面の目的地設定へ移動するネイティブリンク。
- **Typography Audit Contract**: 詳細ページとアプリ全体の通常UIに対する16px相当以上契約を担い、ルビ補助文字だけを例外として検出する静的監査。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 完全な場所fixture、任意項目欠落fixture、未知ID、重複ID、取得失敗、loadingの各状態で、ページのfocused Jestがすべて成功し、各状態に主`h1`が1つ、上部の一覧リンクが1つ存在する。
- **SC-002**: 場所詳細の成功状態で、見出し一覧に場所名の`h1`が1つ、「提供情報」の`h2`が1つあり、場所名の重複見出しと「説明」見出しが0件になる。
- **SC-003**: 成功状態の「地域」と「提供情報」のすべての表示項目が、対応する`dt`の直後の`dd`として検証でき、通常の提供情報にカード表現が0件になる。Ko-fi支援カードの既存契約は維持される。
- **SC-004**: 成功状態の「ここへ行く」が100%のfixtureで`a`要素として描画され、既存の`destination`クエリ値と一致する。`button`および`useRouter`による目的地移動の実行時依存は0件になる。
- **SC-005**: 場所詳細の通常本文・操作文字について、実ブラウザの算出`font-size`が対象表示幅で16px以上となり、light/dark両テーマで通常文字4.5:1以上、大きな文字3:1以上、必要な非テキスト要素3:1以上のコントラストを満たし、通常文字の算出色が低コントラスト指定に依存しない。詳細ページの静的な16px未満指定は0件になる。
- **SC-006**: アプリ全体の静的文字サイズ監査が、ルビ補助文字以外の16px未満、未知のarbitrary font-size、解析不能な文字サイズ指定を検出して失敗できる。監査テスト自身のテストコードは監査対象から除外される。
- **SC-007**: `千代田区役所`のmetadata titleが厳密に`千代田区役所 - 場所詳細`となり、場所名を含む有効な場所で同形式が返る。invalid、unknown、duplicate、data-load-errorでは厳密に`場所詳細 | 風ぐるま乗換案内`となり、raw IDを含まない。
- **SC-008**: focused Jest、TypeScript、対象Lint、`git diff --check`、最終Jest、Lint、実ブラウザ確認が、未実行・timeout・warningだけの状態を成功と混同せず記録される。

## Assumptions

- `specs/018-accessible-route-pages/`で定義済みの`loadKeyLocationsDataResult`、`resolveLocationDetail`、場所IDの不正・重複・取得失敗分類を再利用する。
- `PageHeader`はページの主見出しを生成する既存共通部品として利用でき、詳細ページの成功・状態表示で主見出しを一重化する。
- 既存の`convertToLocation`が返す`lat`、`lng`、`address`のJSON形式と、ホーム画面が読む`destination`クエリは変更しない。
- 共通レイアウトの`KoFiSupport`は場所詳細本文とは別の既存カードとして扱い、提供情報のカード廃止対象に含めない。
- 実ブラウザ確認には、既存のNext.js開発サーバーとPuppeteer等の利用可能な検証手段を使う。外部CDNの最新データそのものの一意性はfixtureだけで断定せず、必要な検証結果を別途記録する。
- 既存の未コミット差分は本仕様の開始時点の作業材料として保持し、reset、clean、commit、pushはユーザーの明示指示なしに行わない。

## Out of Scope

- 認証の振る舞い・データフロー、レート制限、場所一覧カード、場所データの収集元、目的地設定のドメインロジックの変更。
- `KoFiSupport`、`SidebarLayout`、Ko-fi iframeのカード構造・表示位置の変更。
- 新しい永続化、API、認証方式、場所識別子形式、クエリ形式の導入。
- 場所詳細の要件と無関係な大規模な配色・レイアウト変更。ただし、認証UIを含むアプリ全体の通常UIを16px相当以上にするために必要な既存文字サイズ・色の是正は本featureの対象とする。
- native dialog、focus trap、router遷移を別のUI部品へ置き換えること。
- 仕様承認前の`plan.md`、`tasks.md`作成、実装の追加、コミット、push、PR作成。
