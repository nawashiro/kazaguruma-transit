# Polisに着想を得た合意分析

> この文書は理論背景と現行実装の対応を説明します。現行仕様の正本ではありません。数値、型、境界条件は[`evaluation-service.ts`](../../src/lib/evaluation/evaluation-service.ts)と[`polis-consensus.ts`](../../src/lib/evaluation/polis-consensus.ts)を参照してください。

## 位置づけ

Polisは、多数の自由記述と投票から参加者の意見空間を整理するオープンソースプロジェクトです。公式資料は次です。

- [Polis公式リポジトリ](https://github.com/compdemocracy/polis)
- [Polis: Scaling Deliberation by Mapping High Dimensional Opinion Spaces](https://www.e-revistes.uji.es/index.php/recerca/article/view/5516/6558)

本アプリはPolisの考え方を参考にします。公式Polisのサーバーや`math`モジュールを実行しません。現行コードはTypeScriptで`ml-matrix`、`ml-pca`、`ml-kmeans`を使います。

## 現行パイプライン

```text
評価イベント
  ↓
承認済み投稿だけを選択
  ↓
参加者 × 投稿の投票行列
  ↓
PCAまたはSVD
  ↓
K-meansとCalinski-Harabasz Index
  ↓
クラスタ横断合意と代表性
  ↓
Benjamini-Hochberg補正
  ↓
画面表示
```

`EvaluationService`は評価と投稿を投票データへ変換します。`PolisConsensus`はその投票データを分析します。会話詳細画面は、承認が確定した投稿だけを分析へ渡します。

## 1. 投票行列

評価者を`pid`、投稿を`tid`で識別します。評価値は次へ変換します。

- `1`: 賛成
- `-1`: 反対
- `0`: パス、または未投票

前処理は参加者と投稿の全組み合わせを行列にします。存在しない組み合わせは0になります。したがって、現行コードはパスと未投票を区別しません。

参加者と投稿がそれぞれ2件未満なら、分析を中止します。

## 2. 次元削減

`runPCA(2)`は参加者行列を2次元へ変換します。コードは次の密度を計算します。

```text
sparsity = 1 - 非ゼロ要素数 / 全要素数
```

`sparsity > 0.5`ならSVDフォールバックを使います。それ以外では`ml-pca`を使います。PCAまたはSVDが失敗した場合は、元データの先頭列を使い、不足する次元を0で埋めます。

この50%は運用上の切り替え値です。欠測機構を推定する統計モデルではありません。閾値の妥当性を保証しません。

## 3. K-meansとクラスタ数

2次元データにK-meansを適用します。参加者が3件未満なら全員をクラスタ0に置きます。候補数の上限は次です。

```text
maxK = min(10, 2 + floor(参加者数 / 12), 参加者数)
```

候補は`k=2`から`maxK`です。各候補は最大100回反復し、許容差は`1e-6`です。各クラスタの評価にCalinski-Harabasz Index（CHI）を使います。

```text
CHI = (BCSS / (k - 1)) / (WCSS / (n - k))
```

`BCSS`はクラスタ間平方和、`WCSS`はクラスタ内平方和、`n`は参加者数です。CHIが最大の`k`を採用します。候補実行または最終実行に失敗した場合は単一クラスタへフォールバックします。

シルエット係数、Gap統計、GMM、クラスタ安定性は現行コードにありません。理論上の比較案を実装済みと扱いません。

## 4. クラスタ横断合意

クラスタ`g`と投稿`t`について、0を除く投票を使います。`A`を賛成票数、`S`を0以外の投票数とすると、現行コードはJeffreys型の平滑化を次で計算します。

```text
P(g,t) = (A + 0.5) / (S + 1.0)
```

`S=0`なら`P(g,t)=0.5`です。投稿の合意スコアは、全クラスタの確率の積です。

```text
consensus(t) = Πg P(g,t)
```

積は、複数クラスタに広く支持された投稿を選びます。この積は公式Polisの標準仕様を意味しません。クラスタ間の独立性、クラスタ数、クラスタサイズの影響を別途検証していません。

## 5. クラスタ内の代表性

各投稿と各クラスタについて、クラスタ内と他クラスタの差を調べます。賛成と反対を別々に計算します。比率の分母はクラスタ内の全参加者です。0の投票も分母に残ります。

```text
差分 = クラスタ内の比率 - 他クラスタの比率
```

### Network Algorithmとmid-P

コードは`calculateNetworkMidPValue`という関数で2×2表を評価します。実際の処理は次です。

1. `a=x1`、`b=n1-x1`、`c=x2`、`d=n2-x2`の表を作ります。
2. 可能な`a`を`max(0, k1-n2)`から`min(n1,k1)`まで列挙します。
3. 組み合わせを対数空間で計算します。
4. 観測確率より小さい確率を合計します。
5. `extremePValue + 0.5 × observedProb`をmid-P値とします。

この実装は関数名とコメントでMehta & Patel（1983）のNetwork Algorithmと呼びます。ただし、外部Polisの実装と同一とは確認していません。ネットワークを使う専用実装ではなく、可能な表を列挙して対数超幾何確率を合計するコードです。

### 代表性と補正

賛成と反対の全比較でp値を集めます。対象はクラスタ、投稿、投票種別の組み合わせです。Benjamini-Hochberg法を逆順に適用し、単調性を保った調整済みp値を作ります。

既定のFDR閾値は`0.05`です。賛成・反対の代表性スコアから大きい方を選び、次の条件を満たす場合だけ表示候補にします。

- 調整済みp値が`0.05`未満
- 代表性スコアが正

代表性スコアは次です。

```text
repnessScore = 差分 × (1 - p値)
```

コードは補正後p値から逆正規分布の近似値を`zScore`として保存します。出力型の`reppnessScore`という綴りを変更しません。

## 6. 出力とUI

`PolisConsensus`は次を返します。

- `groupAwareConsensus`: 投稿IDと合意スコアの対応
- `groupRepresentativeComments`: クラスタIDと代表的な投稿の対応

`EvaluationService`は投稿オブジェクトを結果へ結合します。合意結果をスコア降順で最大10件に制限します。各クラスタの代表的な投稿を最大5件に制限します。

会話詳細画面は合意結果の先頭5件を表示します。代表的な投稿はクラスタ別タブで表示します。画面には「共通の意見」と「グループA」以降のタブがあります。合意スコアの数値は画面に表示しません。

## 最低条件とエラー

分析は次の条件で空結果になります。

- 評価が5件未満
- 承認済み投稿が2件未満
- 変換後投票が5件未満
- 参加者が2人未満
- 投稿が2件未満

行列やクラスタデータが不正な場合はログを出し、空結果または単一クラスタへフォールバックします。分析失敗時、`EvaluationService`は空の合意結果と代表結果を返します。

## 理論と実装の境界

この文書は、投票を意見空間へ写像し、クラスタを見つけ、クラスタ横断の支持を説明する理論を整理します。次の内容は現行実装の保証ではありません。

- 棄権または未投票の生成過程を推定するMNARモデル
- クラスタ選択後の推論やサンプル分割
- 50%閾値の性能検証
- クラスタ数の安定性評価
- BHの依存構造に対するFDR保証
- 積以外の合意集約
- 公式Polisとの数値一致

これらは査読上の検討事項です。実装仕様へ追加する場合は、コード、テスト、referenceを別に更新します。
