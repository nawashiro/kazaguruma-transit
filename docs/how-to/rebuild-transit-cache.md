# 交通キャッシュの再生成

交通DBはGTFSから再生成するキャッシュです。`npm run dev` と `npm start` は、起動のたびに設定先のDBを破棄し、スキーマ作成・GTFS取込・検証を済ませてから配信を始めます。同じDBにあるAPIレート制限のカウンターもリセットします。

## 設定と生成

`transit-config.json` の `sqlitePath` にSQLiteファイルの保存先を設定してください。CLI、GTFS取込、アプリは同じ保存先を使います。相対パスは実行ディレクトリから解決します。設定・GTFS入力と別の場所を指定し、DBの親ディレクトリを作成できる権限を用意してください。

```bash
npm ci
npm run build
npm start
```

`npm ci` はPrismaクライアントを `src/generated/prisma/` へ生成します。生成物はGitへ含めません。この生成だけなら交通設定は不要です。`build` は交通DBを作成・変更せず、GTFSも取得しません。公開設定や場所データなど、他のビルド入力は必要です。`start` と `dev` には交通設定と、その時点で取得・読取可能なGTFS入力が必要です。

起動処理は設定先のDBと同名の `-wal`・`-shm`・`-journal` を削除し、Prismaのスキーマを作成します。続いてGTFSを取り込み、必須交通データとRateLimitの読書きを検証します。GTFSが追加するテーブルと運行日例外も取り込みます。

## キャッシュの破棄と再取込

1. アプリを停止してください。
2. GTFSの元ファイル、または設定した取得先を更新してください。
3. 配信せずに再生成だけを行う場合は、次を実行してください。

   ```bash
   npm run import-gtfs
   ```

4. `npm start` または `npm run dev` で起動してください。起動時にも再生成します。
5. 停留所、出発時刻、運行日例外を確認してください。

通常の更新に手動DB削除や再ビルドは不要です。稼働中に入力を変更しても時刻表は変わらず、再起動後に反映します。再生成中に同じDBを使うアプリや取込処理を並行して起動しないでください。

取込・検証に失敗した場合は非ゼロで終了し、配信を始めません。旧DBでの配信へ切り替えることもありません。入力や権限などの原因を直してから起動し直してください。失敗途中のDBも次回の起動時に破棄します。GTFSの元ファイルと設定ファイルは保持してください。

## 隔離環境での検証

```bash
npm test -- --runInBand scripts/__tests__/transit-cache-rebuild.test.ts scripts/__tests__/transit-cache-boundaries.test.ts
```

このテストは一時ディレクトリに合成GTFSと交通設定を配置します。通常と異なる保存先で、DBの手動削除なしに時刻表を入れ替え、検索とカウンターのリセットを確認します。DB不在・旧スキーマ・破損ファイル、取得失敗後の再実行も確認します。稼働DBは変更しません。
