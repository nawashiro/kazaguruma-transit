# Kazaguruma Transit憲章

## KISS

KISS（Keep It Simple, Stupid）を開発の基本原則とする。

- 風ぐるまの利用に必要な経路案内を、簡潔な構成で提供する。
- 一つの目的に必要な機能だけを実装する。
- 旧経路を保つためだけのフォールバックや二重実装を追加しない。
- 使わないコード、設定、画面を残さない。

## TDD

TDD（Test-Driven Development）で動作を変更する。

- 先に意味のあるテストを書き、RED（失敗）を確認する。
- テストが示す動作を実装し、GREEN（成功）を確認する。
- 実装を整理し、要求した動作と既存の不変条件を保つ。
- 実在しない機能を前提にしたテストを書かない。

## Accessibility

Webページ全体を対象に、WCAG 2.2（Web Content Accessibility Guidelines）AA適合レベルを目標とする。

- 意味のあるHTML、キーボード操作、可視フォーカス、明確なラベルを実装する。
- 状態、エラー、動的な通知を支援技術へ伝える。
- ルビを除くユーザー向け文字の算出フォントサイズを16px未満にしない。
- UIのアイコンには`lucide-react`のアイコンを使う。
- 該当する達成基準をチェックリストと公式原文で確認する。
- 方針と実装都合が衝突したら、方針を優先し、理由と代替案を作業文書へ残す。

## プロジェクトの範囲

千代田区地域福祉交通「風ぐるま」の非公式Webアプリケーションとして、利用者の移動計画を支援する。

### 範囲内

- 出発地、目的地、時刻から風ぐるまの経路を検索する。
- バス停、時刻表、乗換、徒歩区間などの経路情報を示す。
- 福祉施設などの目的地を選ぶための場所情報を示す。
- 障害や高齢による利用上の制約を考慮した情報を示す。

### 範囲外

- 行政の公式システムとしての正確性や互換性を保証する。
- 風ぐるま以外の交通機関を網羅する総合乗換案内を提供する。
- 後方互換性だけを目的に旧実装や旧設定を保つ。
- Docker運用でデータの恒久保存を保証する。
