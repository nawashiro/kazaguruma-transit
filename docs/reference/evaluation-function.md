# 会話評価関数リファレンス

## 位置づけ

この文書は、現在の評価実装の入力、判定、出力制限を説明します。実装の正本は[`evaluation-service.ts`](../../src/lib/evaluation/evaluation-service.ts)と[`polis-consensus.ts`](../../src/lib/evaluation/polis-consensus.ts)です。Polisの理論背景は[`polis-consensus-algorithm.md`](../explanation/polis-consensus-algorithm.md)で説明します。

評価の表示と合意分析は別の段階です。現在の合意分析は、承認済み投稿をクラスタ単位で処理します。

## 入力

`EvaluationService.analyzeConsensus`は次を受け取ります。

- `PostEvaluation[]`: 投稿ID、評価者公開鍵、`+`または`-`、作成時刻
- `DiscussionPost[]`: 投稿本文、投稿者、会話ID、承認状態、任意のバス停タグ

サービスは承認済み投稿だけを分析します。評価の投稿IDが入力投稿にない場合、その評価を投票へ変換しません。

評価は次の投票へ変換します。

- `+` → `1`（賛成）
- `-` → `-1`（反対）
- 評価がない参加者と投稿の組み合わせ → `0`（パス）

`pid`は評価者公開鍵、`tid`は投稿IDです。投票行列は参加者を行、投稿を列に置きます。

## 最低データ条件

サービスは条件を満たさない場合、空の分析結果を返します。

- 評価が5件未満
- 承認済み投稿が2件未満
- 変換後の投票が5件未満
- ユニーク参加者が2人未満
- ユニーク投稿が2件未満

会話詳細画面も、評価5件未満または承認済み投稿2件未満なら分析を開始しません。部分取得で承認状態が`unknown`の投稿は分析に渡しません。

## 分析処理

`PolisConsensus.runAnalysis()`は次の順に処理します。

1. 参加者と投稿の識別子から投票行列を作ります。
2. 疎密度に応じてPCAまたはSVDを実行します。
3. K-meansで参加者をクラスタに分けます。
4. クラスタ横断の合意を計算します。
5. 各クラスタの代表的な投稿を計算します。
6. Benjamini-Hochberg法でp値を補正します。

### クラスタ横断の合意

クラスタ`g`の投稿`t`について、0を除いた投票数を`S`、賛成票数を`A`とします。現在のコードは次で平滑化します。

```text
P(g,t) = (A + 0.5) / (S + 1.0)
```

`S`が0の場合は0.5とします。投稿の合意スコアは、全クラスタの`P(g,t)`の積です。

このスコアは、全クラスタで支持される投稿を高くします。統計モデルとしての独立性やクラスタ数への影響を解決するものではありません。

### 代表的な投稿

クラスタと他クラスタで、賛成率と反対率を別々に比べます。比率の分母には0の投票も含めます。各比較のp値は`calculateNetworkMidPValue`で求めます。

現行コードの処理は次です。

1. 2×2表を作ります。
2. `a`の可能範囲を`max(0, k1 - n2)`から`min(n1, k1)`まで列挙します。
3. 組み合わせを対数で計算し、超幾何確率を求めます。
4. 観測値より極端な確率を合計します。
5. `極端な確率 + 観測確率 × 0.5`でmid-P値を作ります。

賛成と反対の全p値をまとめてBenjamini-Hochberg法で補正します。補正後p値は単調性を保ちます。既定のFDR閾値は`0.05`です。

代表性スコアは次で計算します。

```text
差分 = クラスタ内の比率 - 他クラスタの比率
代表性スコア = 差分 × (1 - p値)
```

賛成と反対のうちスコアが大きい方を採用します。補正後p値が`0.05`未満で、スコアが正の場合だけ代表的な投稿にします。`zScore`は補正後p値から逆正規分布を近似します。出力フィールド名`reppnessScore`は実装の綴りを維持します。

## 結果の制限

`EvaluationService`は次の制限を適用します。

- 合意投稿はスコア降順で最大10件
- 各クラスタの代表的な投稿は最大5件
- 投稿情報が見つからない結果は除外

会話詳細画面は合意投稿を先頭5件まで表示します。代表的な投稿は、クラスタごとのタブに最大5件表示します。画面は合意スコアの数値ランキングを表示せず、賛成率と反対率を表示します。

## UIの流れ

[`/discussions/[naddr]`](../../src/app/discussions/[naddr]/page.tsx)は、承認済み投稿と評価を読み込みます。`EvaluationComponent`で投稿を評価します。評価後に合意分析を実行します。

分析結果には次のタブを表示します。

- 共通の意見
- グループA以降の代表的な意見

データが不足する場合は「分析された投稿がまだありません。」と表示します。分析中、部分取得、通信失敗は状態メッセージで示します。

## 実装上の境界

この実装はPolisの考え方を参考にしたTypeScript処理です。公式Polisのサーバーや数学モジュールを直接実行しません。Python、Clojure、scikit-learn、SciPyのコードを実行しません。

現在の依存関係は`ml-matrix`、`ml-pca`、`ml-kmeans`です。実装の詳細と数値はコードとテストを正本とします。理論上の改善案、統計的な妥当性、将来の代替手法はこの文書の現行仕様ではありません。

関連テストは[`polis-consensus.test.ts`](../../src/lib/evaluation/__tests__/polis-consensus.test.ts)で確認します。
