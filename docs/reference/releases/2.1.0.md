## 公開アプリ設定

- 公開アプリ設定を、開発用の`app-config.local.json`と本番用の`app-config.json`に分けました。どちらもGitで管理せず、`app-config.json.example`を開発用の値を持つテンプレートとして使います。
- 読み込むファイルはビルド時に決まります。`NODE_ENV=production`のビルドは本番用を、開発サーバーとテストは開発用を読み、`APP_CONFIG_ENV=local`または`production`で明示的に選べます。
- 開発用Dockerイメージは、ビルド時に開発用の設定を選びます。
- 位置情報artifactの生成と目的地目録の更新も、本体と同じ設定ファイルを読みます。
- 設定の検証エラーは、`app-config.json`ではなく公開アプリ設定の不備として表示します。

## 互換性のない変更

### 設定ファイルの分割

公開アプリ設定は`app-config.json`1つで運用していましたが、2ファイルに分かれました。どちらのファイルも必要で、片方でもない場合、`npm run dev`、`npm test`、`npm run build`、`npm start`、Dockerイメージのビルドは非ゼロで終了します。

```bash
cp app-config.json.example app-config.json
cp app-config.json.example app-config.local.json
```

- `app-config.json.example`は開発用の値を持つテンプレートです。`app-config.local.json.example`はありません。
- 開発用の`app-config.local.json`は、テンプレートをコピーしてそのまま使えます。
- 本番用の`app-config.json`は、`appUrl`、`discussion`、`announcement`を配布先の値へ書き換えます。
- 旧`app-config.prod.json`は使いません。

### Quality Gate

Quality Gateは、`app-config.json.example`から`app-config.json`と`app-config.local.json`を一時作成してから、ビルドとテストを実行します。
