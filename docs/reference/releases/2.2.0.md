## 利用状況の計測

- 経路検索の実行（経路が見つからなかったときも含む）、住所検索の結果、地点の選び方、GPSの結果、地点を確定しないままの送信、PDFとカレンダーの出力を、GA4のイベントとして記録します。ページビューだけでは分からなかった、どこで迷って離脱したかを追えます。
- 座標、住所、停留所名、入力した文字列は送りません。
- 開発環境では送信せず、コンソールへ出力します。測定IDが空のときも送信しません。

## 運営者のアクセスの除外

- 除外したいブラウザで本番のURLに`?owner=1`を付けて開くと、そのブラウザの計測が内部トラフィックの印付きになります。`?owner=0`で解除します。IPアドレスでは判定しません。
- 印はブラウザごとに保存します。シークレットウィンドウや、保存データを消したあとは設定し直します。
- `?owner=1`を付けても、画面、検索結果、共有URLは変わりません。

## GA4の管理画面設定

- カスタムディメンション5種（入力項目、入力の入口、入力の結果、未確定の項目、出力の種類）と、カスタム指標「経過時間（ミリ秒）」を登録します。登録しないと、探索レポートの条件に使えません。
- データ保持期間を14か月にします。
- 拡張計測機能の「履歴変更によるページビュー」と「フォーム操作」をオフにします。前者はページビューの二重計上、後者はフォームを区別できないイベントの原因になります。
- データフィルタの「内部トラフィック」と「開発者トラフィック」を有効にします。最初はテストのまま1日置き、翌日の標準レポートで運営者のアクセスが出ないことを確認してから有効にします。データフィルタは元に戻せません。

## アップグレード

- アプリの設定ファイルを変更する必要はありません。画面、URL、経路検索の動作は変わりません。
