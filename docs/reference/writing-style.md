# 文書執筆規範

## Diátaxisの4分類

文書の目的を一つに定め、次の分類から配置先を選ぶ。

### チュートリアル

初学者が学習を進める順序を示す。説明と操作を一つの学習体験にまとめる。配置先は`docs/tutorials/`とする。

### How-to

読者が特定の作業を完了する手順を示す。前提、操作、結果を短く書く。配置先は`docs/how-to/`とする。

### Reference

読者が事実、仕様、設定、契約を確認する資料とする。項目を網羅し、解釈を混ぜない。配置先は`docs/reference/`とする。

### Explanation

設計の理由、背景、選択肢を説明する。手順や仕様の正本を重ねない。配置先は`docs/explanation/`とする。

## 正本の扱い

- 現行の方針は対応する`docs/reference/`文書を正本とする。
- 現行の動作は実装、設定、生成物、workflowが示す範囲だけを書く。
- READMEと`AGENTS.md`は入口に限定し、詳細を正本へ委ねる。
- 文書を移動したら、現行文書とOpenSpec成果物のリンクを新しいパスへ更新する。
- 一つの規則を複数の正本へ重複して定義しない。

## 履歴資料と外部原文

- 調査、ログ、レビュー、旧仕様は`docs/records/`へ置き、記録時点と状態を示す。
- `docs/records/`の記述を現行仕様や現行手順として案内しない。
- `archive/v2/**`は旧Spec Kit資産として保存し、現行OpenSpecの正本にしない。
- `docs/accessibility/Understanding/**`、保存した`NIP-*.md`、`docs/discussion/nosskey.md`、`docs/discussion/nostr-tools.md`は外部原文として凍結する。
- 凍結した原文は本文とパスを変更せず、プロジェクト固有の正本と区別して案内する。

## 日本語技術文書の表記規則

- 日本語を使い、主語と行為者を明示して能動態で書く。
- 一文を短くし、一文に一つの指示だけを書く。
- 一段落に一つの話題だけを置く。複数の条件や手順は縦のリストにする。
- 一般的でない略語は、初出で`略語（正式名称）`と書く。
- 英語の技術語、API名、コマンド名、識別子を削除しない。
- CJK文字とラテン文字の間に半角スペースを入れない。ただしMarkdownの構文境界は除く。
- ファイル名、パス、コマンド、URL、設定キーはバッククォートで囲み、値を変えない。
- 見出しとリンク名は対象の目的を明示する。曖昧な「こちら」や「詳細はこちら」を使わない。
- 現行でない内容には、履歴、廃止、未実装などの状態を明記する。
