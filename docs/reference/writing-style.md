# 文書執筆規範

## Diátaxisの4分類

文書の目的を一つに定め、次の分類から配置先を選ぶ。

- Tutorial: 初学者が学習を進める順序を示す。説明と操作を一つの学習体験にまとめる。`docs/tutorials/`
- How-to: 読者が特定の作業を完了する手順を示す。`docs/how-to/`
- Reference: 読者が事実、仕様、設定、契約を確認する資料とする。`docs/reference/`
- Explanation: 設計の理由、背景、選択肢を説明する。`docs/explanation/`

## 文書の扱い

- README と `AGENTS.md` は入口に限定し、詳細を文書へ委ねる。
- 一つの規則を複数の正本へ重複して定義しない。

## 履歴資料と外部原文

- 外部から取り込んだ原文は`external-docs/`へ置き、本文を変更しない。
- 調査、ログ、レビュー、旧仕様は`archive/v1/`へ置き、記録時点と状態を示す。

## 表記規則

- 日本語で書く。
- 主語と行為者を明示して能動態で書く。
- 動詞は命令形、非過去形、単純過去形のみ使う。
- 複雑な動詞構文で助動詞を使用しない。
- 手順は 20 語以内、説明は 25 語以内で書く。
- 文を短くするために、主語や動詞を省略しない。
- 一文に一つの指示だけを書く。
- 一段落に一つの話題だけを置く。
- 複数の条件や手順はリストにする。
- 各段落は 6 文以内にする。
- 安全に関する指示は、明確な命令または条件から始める。
- 一般的でない略語は、初出で `略語（正式名称）` と書く。
