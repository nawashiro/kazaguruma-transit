# Design

## Context

- 既存の送信は[useGA.ts](../../../src/lib/analytics/useGA.ts)が明示的にページビューを送るだけで、`send_page_view: false`により初期自動ページビューは無効。URLはクエリ除去済み。
- カスタムイベント用の`sendEvent(category, action, label, value)`は定義だけされ、呼び出し元が存在しない。GA4では`action`がイベント名になるため、この形ではイベント名とパラメーターを表現しにくい。
- トップページにはフォームが3つある：目的地の住所検索、出発地の住所検索（どちらも`preventDefault`の非同期検索）、最終検索（`method="get" action="/routes"`の普通のフォーム送信）。
- 結果ページはサーバー描画で、フォーム送信はフルページ遷移になる。クライアント側の状態は遷移で失われる。
- サーバー側の利用記録は持たない（GAのみ）。運営者の回線は動的IP。
- [analytics-privacy](../../../openspec/specs/analytics-privacy/spec.md)により、GAへ送るURLにクエリを含めない。

## Goals / Non-Goals

**Goals:**

- 経路検索の実行回数を、GA4の明示イベントとして数えられるようにする。
- 住所検索・GPS・未確定送信の結果を項目別に分け、どの段で止まるかを四半期単位で読めるようにする。
- 運営者自身のアクセスをIPに依存せず除外できるようにする。
- 位置情報を一切送らずに、上記を実現する。

**Non-Goals:**

- サーバー側の集計、アプリ内の統計画面。
- ヒートマップ、セッションリプレイ、BigQueryエクスポート。
- 統計的な有意性を確保すること。月50〜70人では段ごとの差はノイズとして扱う。
- 同意バナーやCookie設定の追加。

## Decisions

### D1: 運営者の識別はブラウザの印で行う

`?owner=1`を開いたら`localStorage`に印を保存し、以後のページビューとイベントに`traffic_type=internal`を付け、初期化時は`debug_mode=true`にする。`?owner=0`で解除。どちらの場合も`history.replaceState`で`owner`を消す。

- 代替案：IP許可リスト。動的IPでは毎回更新が必要で、忘れると数字が汚れる。却下。
- 代替案：運営者専用の測定ID。データが分散し、比較が面倒になる。却下。
- `traffic_type`と`debug_mode`の両方を送るのは、GA4のデータフィルタ「内部トラフィック」と「開発者トラフィック」のどちらでも除外できるようにするため。`traffic_type`の手動付与が無視される場合に備え、`user_type=owner`もカスタムディメンションとして送り、探索レポートの比較条件で除けるようにする。
- データフィルタは不可逆なので、まず「テスト」状態で自分のアクセスが標準レポートに出ないことを確認してから有効化する。

### D2: `route_search`は結果ページから送る

フォーム送信時に`sessionStorage`へ開始時刻を保存し、結果ページのクライアント側で、その時刻が存在する場合だけ`route_search`を1回送って時刻を削除する。`elapsed_ms`は「入力画面を表示してから結果が表示されるまで」のミリ秒。

- 送信時にイベントを送らない理由：フルページ遷移でヒットが失われる可能性があり、検索が成功したかも分からない。
- 結果ページから送る理由：サーバー側で検索が成立した表示だけを数えられる。結果URLの直接オープンや再読み込みは開始時刻が無いので数えない。仕様の「1回だけ」「直接オープンでは送らない」を、URL照合ではなく開始時刻の有無で満たせる。
- 代替案：URLに`?internal_search=1`のような目印を付ける。共有URLを汚し、仕様の「共有URLを変えない」に反する。却下。
- `sessionStorage`が使えない環境ではイベントを送らない（取りこぼしは許容し、誤計上はしない）。
- 結果ページの`RouteSearchTracker`は、root layoutの`useGA`が`config`を送るより先にマウントされることがある。`ReactGA.event`は初期化前でも`dataLayer`へ積めてしまうが、gtag.jsは`config`より前のイベントを処理しない。そのため`track`は未初期化のあいだイベントを保持し、`useGA`が初期化直後に`flushPendingEvents`で送る。保持は最大20件で、超過分は古いものから捨てる。

### D3: イベント送信APIをGA4の形に置き換える

`sendEvent(category, action, label, value)`を、`track(eventName, params)`に置き換える。開発環境ではイベント名とパラメーターをログに出すだけ。測定IDが空なら送らない。呼び出し元がゼロなので互換層は作らない。

- 代替案：既存のシグネチャに`params`を足す。イベント名が第2引数に埋もれ、GA4のレポート名と対応しなくなる。却下。

### D4: 住所検索の計測はフック、地点確定の計測は確定箇所で行う

- `place_search`は`useGeocodingSearch`の結果で送る。どの項目かを知るため、フックに`field`（`origin`/`destination`）を渡す。
- `place_select`は確定した場所で送る。住所検索の成功はフックから`source=address`、施設一覧は`catalog`、GPSは`gps`、施設詳細からの引き継ぎは`detail`。
- `gps_result`は`navigator.geolocation`のコールバックで送る。`GeolocationPositionError.code`の1を`denied`、3を`timeout`、それ以外を`denied`として扱い、非対応ブラウザは`unsupported`。
- `validation_failed`は[HomeRouteForm.tsx](../../../src/components/features/HomeRouteForm.tsx)の検証で送る。`preventDefault`の後、不足している項目を`missing`に入れる。

### D5: 結果後の行動は出力の開始時だけ送る

`result_action`はPDF出力とカレンダー出力のボタンで送る。停留所の議論・メモは結果ページを開くと自動で読み込まれるため、利用者の操作ではなく送らない。

### D6: パラメーターは5つのカスタムディメンションと1つのカスタム指標に収める

`field`、`source`、`outcome`、`missing`、`action`をイベントスコープのカスタムディメンション、`elapsed_ms`をカスタム指標として登録する。座標・住所・停留所名・自由入力は送らない。カーディナリティは最大でも数種類で、GA4の上限に対して余裕がある。

### D7: GA4側の設定はコードではなく運用手順として残す

以下を[docs/how-to/analytics.md](../../../docs/how-to/analytics.md)に手順として書き、リポジトリで追跡する。

- データ保持期間を14か月にする（将来「使われている証拠」を出せるようにする唯一の投資）。
- 拡張計測の「履歴変更によるページビュー」をオフ（`useGA`が自前で送っているため二重計上になる）。
- 拡張計測の「フォーム操作」をオフ（`form_submit`はフォームを区別できず、明示イベントに置き換える）。
- 内部トラフィックと開発者トラフィックのデータフィルタを有効化。

## Risks / Trade-offs

- [GAは広告ブロックで欠測する] → 数字は下限として扱い、月次の増減ではなく四半期の傾向と前後比較で判断する。仕様にも「件数は下限」とは書かず、運用手順に明記する。
- [`traffic_type`の手動付与がGA4に無視される] → `debug_mode`と`user_type`を併用し、データフィルタが効かない場合は比較条件で除く。データフィルタの有効化前にテスト状態で確認する。
- [データフィルタは不可逆] → 自分のアクセスを除外する目的に限定し、テスト状態での確認を必須にする。
- [フルページ遷移で開始時刻が失われる] → `sessionStorage`に保存する。使えない環境では`route_search`を送らない（過小計上を選ぶ）。
- [初期化前のイベントがgtag.jsに捨てられる] → `track`が保持し、初期化後にまとめて送る。並び順を保つため配列で持つ。
- [イベントを増やしすぎる] → 6イベント、パラメーターは5種に固定。追加はこの仕様の変更として扱う。
- [月50〜70人では段ごとの差が読めない] → 段は4つまで、判断は四半期。原因究明はGAではなく数人の操作観察で行う。

## Migration Plan

1. コードを配布する（イベントと`?owner=1`の識別）。
2. 運営者が`?owner=1`を各ブラウザ・端末で開く。
3. DebugViewで`traffic_type=internal`と`debug_mode`が付くこと、`route_search`が1回だけ送られることを確認する。
4. データフィルタを「テスト」で1日置き、翌日の標準レポートに自分のアクセスが出ないことを確認してから有効化する。
5. 拡張計測の該当項目をオフにし、データ保持を14か月に変更する。
6. 印の無いブラウザで検索し、翌日の標準レポートに`route_search`が出ることを確認する。

ロールバックはコードの revert で足りる。データフィルタは不可逆だが、運営者以外を巻き込まない設定にとどめる。
