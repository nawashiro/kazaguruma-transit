# Design

## Context

ICSはブラウザ内で生成している。HTML標準では `download` 属性があるリンクはダウンロードとして扱われ、それ以外は通常のリンクとして処理される。[HTML標準](https://html.spec.whatwg.org/multipage/links.html#following-hyperlinks)

## Goals / Non-Goals

**Goals:** ファイルを開く際の処理をブラウザと端末へ委ね、読み込み前のURL破棄を防ぐ。

**Non-Goals:** カレンダーアプリの指定、共有メニューの追加、サーバーへの予定送信。

## Decisions

- 既存のBlob URLを通常のリンクとして開く。サーバーAPIの追加を避け、端末内でのファイル生成を維持する。
- 作成したURLはコンポーネント内で保持し、アンマウント時にまとめて解放する。即時解放や固定時間後の解放では、ブラウザが読み込む前にURLを無効にする可能性がある。再クリック時にも古いURLを解放せず、先に開いたファイルの読み込みを妨げない。
- 通常のリンクでは `download` による保存名指定を使わないため、専用の保存名生成処理を削除する。

## Risks / Trade-offs

- ブラウザや端末によって保存になる場合がある → アプリでは処理先を固定しない。
- 連続操作でBlobが保持される → コンポーネントのアンマウント時に全URLを解放する。
- 通常のBlob URLでは保存名が端末任せになる → ファイル名の指定を要件に含めない。
