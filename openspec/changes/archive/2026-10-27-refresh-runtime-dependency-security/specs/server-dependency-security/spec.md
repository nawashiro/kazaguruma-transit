# Spec Delta

## Purpose

公開サーバーの依存更新と本番実行環境の検証に、確認可能な受入条件を定める。修正した脆弱性、保留した警告、未確認の本番環境を区別し、更新の結果を利用者と運用者へ正確に伝える。

## ADDED Requirements

### Requirement: 公開サーバー依存の修正版を使用する

配布物は Server Actions のサービス拒否（GHSA-p3m5-59mp-jv5r）と画像処理の任意コード実行（GHSA-2464-fhr4-w9xw）について、公開情報の修正条件を満たす依存を使用しなければならない（MUST）。依存宣言と配布物の解決結果の両方を確認する。

#### Scenario: 修正版へ更新する

- **WHEN** 更新後の依存をロックファイルから導入する
- **THEN** 宣言下限と解決値が対象脆弱性の修正条件を満たす
- **AND** 同じ対象の脆弱性が依存監査に残らない

#### Scenario: 古い依存へ後退する

- **WHEN** 宣言下限または解決値が対象の修正版を下回る
- **THEN** 依存の検査が失敗する

### Requirement: 地図・画像・PDF の契約を保つ

システムは依存更新後も地図の取得、画像の表示、PDF の出力について既存の入出力契約を保たなければならない（MUST）。更新によって API の認証、レート制限、PDF の内容と用紙設定を変更しない。

#### Scenario: 既存の入力で利用する

- **WHEN** 利用者が既存形式の地図リクエストまたは PDF 生成リクエストを送る
- **THEN** システムは既存形式の結果を返す
- **AND** 対象画面の画像表示と PDF 出力が機能する

### Requirement: 残存警告を実行経路で評価する

更新結果の報告は全依存と本番依存の監査結果を区別しなければならない（MUST）。残存警告には依存経路、攻撃成立条件、対応または保留の理由を記す。到達性が未確認の警告を、影響なしと断定しない。

#### Scenario: 本番依存に検査用ツールが含まれる

- **WHEN** 本番依存の監査がビルドまたは CLI 用の依存を検出する
- **THEN** 報告は実際の用途と外部入力の到達性を示す
- **AND** 監査の分類だけで公開リクエストからの攻撃成立を断定しない

#### Scenario: 警告を保留する

- **WHEN** 更新後にも警告が残る
- **THEN** 報告は残存する警告と保留理由を示す
- **AND** 全脆弱性を解消したと報告しない

### Requirement: 本番ランタイムの修正状況を確認する

本番反映の完了報告は稼働する Node.js と PDF 生成用 Chrome の実バージョン、および確認日時を示さなければならない（MUST）。タグ名、ビルド成功、Puppeteer の更新だけを根拠に、ランタイムの修正完了を宣言しない。

#### Scenario: 再取得して本番反映する

- **WHEN** 運用者が実行環境のセキュリティ更新を本番へ反映する
- **THEN** ベースイメージと Chrome の取得処理を再実行する
- **AND** 生成イメージと稼働コンテナで実バージョンを確認する
- **AND** 確認した版を反映時点の公開セキュリティ情報と照合する

#### Scenario: 本番へアクセスできない

- **WHEN** 作業者がローカル検証だけを完了する
- **THEN** 報告は本番反映と稼働版の確認を未実施と明記する
- **AND** ローカル検証の完了を本番の修正完了として扱わない
