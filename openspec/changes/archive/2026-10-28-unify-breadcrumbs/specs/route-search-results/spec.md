# Spec Delta

## MODIFIED Requirements

### Requirement: 検索失敗と利用制限

結果ページは条件不正、経路なし、検索処理の失敗を識別できる表示を提供しなければならない（SHALL）。サーバー描画経由でも既存の利用制限を適用し、上限到達時は`/rate-limit?source=routes`へ案内する。検索経路を変えることで利用制限を迂回したり、1回の検索を二重計上したりしてはならない。エラー表示の際もパンくずから入力画面へ戻れる。

#### Scenario: 条件が不正である
- **WHEN** 必須パラメーターが不足、または座標・日時・真偽値が不正である
- **THEN** 条件不正を日本語で表示し、経路計算は実行しない
- **THEN** h1より上のパンくずから入力画面へ戻れる

#### Scenario: 経路がない
- **WHEN** 検索処理は成功したが該当経路がない
- **THEN** 経路がない旨をHTMLで表示し、パンくずから入力画面へ戻れる

#### Scenario: 検索処理が失敗する
- **WHEN** サーバーの経路取得に失敗する
- **THEN** 日本語のエラーを表示し、パンくずから入力画面へ戻れる

#### Scenario: 利用制限に達する
- **WHEN** 同じ利用者の検索が既存の利用上限に達する
- **THEN** サーバー描画の結果ページでも利用制限画面へ案内する
- **THEN** 経路APIを直接使った場合と同じ制限を受ける

### Requirement: 検索結果の意味構造とスタイル

結果ページは経路情報を見出し・リスト・区切り線で整理し、カードの多重囲みを使わずに表示しなければならない（SHALL）。既存テーマと統一したスタイルを使い、ルビ以外の利用者向け文字を算出サイズ16px以上とする。各乗車区間は乗車停留所・路線名・降車停留所の順に示し、路線名と停留所名は同じ文字サイズとする。ページのh1と重複する「経路」見出しは置かない。全体リセットは表示せず、h1より上にパンくず（トップ > 経路検索結果）を表示する。

#### Scenario: 直通と乗換の結果を表示する
- **WHEN** 直通または乗換の経路を表示する
- **THEN** 経路と各区間の関係を見出し・リストから理解できる
- **THEN** 320 CSS px相当の幅でも時刻と停留所名を省略せず読める
- **THEN** ライト・ダークの両テーマで路線名と停留所名の算出フォントサイズが同じで16px以上となる
- **THEN** 各乗車区間のDOM順と表示順が乗車停留所・路線名・降車停留所となり、ページのh1に加えて重複する「経路」見出しを表示しない
- **THEN** 「検索条件をリセット」ではなく、h1より上のパンくずから入力画面へ戻れる

#### Scenario: ルビ付きの戻るリンクを読む
- **WHEN** ルビを有効にした結果画面で「トップ > 経路検索結果」のパンくずを表示する
- **THEN** 基底文字とルビはインラインの文章として表示され、単語やルビごとに別の行へ分割されない
- **THEN** 狭い画面で自然に折り返しても読め、パンくずの読み上げ名と入力画面への遷移先を保つ
