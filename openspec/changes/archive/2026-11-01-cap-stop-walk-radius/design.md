# Design

## 方針

絞り込みは補正後の徒歩距離で行う。条件式は次のとおりとする。

```
calculateGridWalkingDistanceKm(stop.distance) <= radiusKm
```

上限の値は `TRANSIT_PARAMS.DEFAULT_SEARCH_RADIUS = 500` のままにする。この定数は直線の半径から最悪徒歩距離の上限へ意味が変わるため、コメントを更新する。倍率を別の定数に分けないのは、`walking.ts` の `calculateGridWalkingDistanceKm` を絞り込みでもそのまま使うことで、補正係数の正本を一つに保つためである。

## 従来経路の上限

`searchRoute` の従来経路は `findNearestStop` が返す最寄りバス停1件だけを候補とする。この候補にも同じ上限を適用する。出発地と目的地の両方で補正徒歩距離を計算し、どちらか一方でも上限を超えれば従来経路は経路なしを返す。

従来経路が経路なしを返したとき、`searchRoute` は既存のフォールバックで周辺バス停経路を検索する。周辺バス停経路も同じ上限で絞り込むため、両方の経路で歩ける範囲が一致する。

## 代替案

`DEFAULT_SEARCH_RADIUS` を500mから354m（500/√2）に直接変え、絞り込みは直線距離のままにする案もある。上限値の意味が直線距離の実数値になり、定数から歩ける範囲が読み取れないため採用しない。

## 期待する動作の例

- 直線350mのバス停は補正後約495mで採用する。
- 直線360mのバス停は補正後約509mで不採用にする。

## 対象外

`getStopsWithinRadius` が最初の10件だけを取得する問題は、別のchangeで修正する。
