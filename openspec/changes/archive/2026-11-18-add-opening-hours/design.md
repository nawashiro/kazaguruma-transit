# Design

## Context

`add-location-accessibility`の後、場所詳細は`public/generated/location-data.json`の`sources.locations`を読む。`add-location-facts`が電話・ウェブサイト・Wikipedia・OSM編集リンクを足す。営業時間はその後、バリアフリー情報の下、基本情報の上に入る。

OSMタグミラーには40件の`opening_hours`がある。規則は`Tu-Su 10:00-17:30`のような単純なものから、`Mo-Fr 08:30-17:00; PH off; Dec 29-Jan 03 off`、`Sa[1] off`、`Mo-Su 11:00-08:00`、`24/7`まで幅がある。CoMapsなどの編集ツールは祝日指定を書けず、曜日だけの規則になりやすい。第何週かの例外も書かれないことが多い。

`opening_hours` 3.16.0はLGPL-3.0で、ESMは生1.1MB、gzip 157KB。`getState`、`getNextChange`、`getOpenIntervals`を提供し、Nominatim形式の`{lat, lon, address: {country_code, state}}`を与えると日本の祝日（`PH`）を評価できる。評価はJavaScriptのローカル時刻を使うため、プロセスのTZに依存する。この環境のTZはUTCで、そのまま呼ぶと9時間ずれる。

`/locations`のlayoutは`force-dynamic`だが、詳細ページは`force-static`を指定している。

## Goals / Non-Goals

**Goals:**

- 現在の営業状態と先一週間の予定を、日本時間で正しく表示する。
- 祝日・第N週の抜けを、警告と注意書きで補う。
- パーサをクライアントへ送らず、実行時に外部取得もしない。

**Non-Goals:**

- 一覧カードの営業状態。
- ページを開いたままの自動更新。
- 祝日カレンダーの表示や、祝日の名称の表示。
- 営業時間の編集。
- 営業時間による検索・絞り込み。

## Decisions

### サーバーで評価し、詳細ページを動的にする

「今」と「先一週間」はリクエスト時に決まる。詳細ページを`force-dynamic`にし、サーバーで1件分だけ評価する。`/locations`のlayoutは既に`force-dynamic`なので、構成上の無理はない。

パーサをクライアントへ送る案は、gzip 157KBとLGPL-3.0の配布条件を持ち込むため採らない。ビルド時に週間表と例外を正規化してクライアントで評価する案は、12か月分の例外を再生成する必要があり、祝日・第N週の規則変更に追従しにくい。内部APIへ問い合わせる案は、静的ページにJSと取得を足すだけで、サーバー描画より複雑になる。採用しない。

artifactはビルド後不変なので、`readLocationArtifact`の結果をモジュールスコープでキャッシュし、リクエストごとの再読込を避ける。

### 日本時間への変換はアダプタで行い、グローバルTZを変えない

ライブラリは`Date`のローカル時刻を読む。プロセスのTZがUTCなら、日本時間の壁時計を見せるためにDateを+9時間ずらして渡し、戻り値を戻す。

```ts
const JST_OFFSET_MINUTES = 540;

function toLibraryDate(date: Date): Date {
  return new Date(
    date.getTime() +
      (JST_OFFSET_MINUTES + date.getTimezoneOffset()) * 60_000,
  );
}

function fromLibraryDate(date: Date): Date {
  return new Date(
    date.getTime() -
      (JST_OFFSET_MINUTES + date.getTimezoneOffset()) * 60_000,
  );
}
```

UTCでは+9時間、Asia/Tokyoでは0時間、ニューヨークでは14時間ずれる。`getTimezoneOffset`を日付ごとに使うため、プロセスTZに夏時間があっても大きくは崩れない。日本には夏時間がない。

グローバルな`TZ`をAsia/Tokyoへ変える案は、GTFSの時刻や既存の日付処理へ影響が広がるため採らない。TZ=UTCのまま動くことをテストで確かめる。

### 評価と整形

`nominatim`は場所の緯度経度と`{country_code: "jp", state: "東京都"}`を渡す。

- `getState(now)`で「営業中」「営業時間外」を決める。
- `getNextChange(now)`で次に変わる時刻を出し、「17:30まで」「明日10:00から」と添える。`24/7`は次がなく「24時間営業」にする。
- `getOpenIntervals(todayStart, todayStart + 7日)`で先一週間を取り、日本時間の日付ごとにまとめる。`from`は今日の00:00にする。`getOpenIntervals`は`from`で切り取るため、00:00から始めないと今日の開店時刻が欠ける。
- 深夜跨ぎの規則はライブラリが日付境界で分割する。1日に複数の時間帯がある場合は「10:00-12:00、13:00-17:00」と並べる。
- 表示は`Intl.DateTimeFormat`の`timeZone: "Asia/Tokyo"`で行い、`<time dateTime="...">`を使う。

解釈に失敗した場合は、営業中・営業時間外を断定しない。生の規則を`<code>`で出し、OSMの編集リンクへ誘導する。1件の不正な規則でページ全体を失敗させない。

### 警告と注意書き

常に「目安なので、正確な時間は施設に問い合わせてください。」を出す。

規則に`PH`または`SH`がない場合だけ「祝日は通常と異なる場合があります。」を足す。CoMapsは祝日指定を書けず、曜日だけの規則が残る。第何週かの例外も書かれないことが多く、注意書きだけでなく祝日警告も必要になる。`PH`がある規則はライブラリが日本の祝日を評価できるため、祝日警告は出さない。

`PH`・`SH`の有無は生の規則に対する`\b(PH|SH)\b`で判定する。文法を再実装しない。

### 営業時間はバリアフリー情報の下、基本情報の上に置く

詳細ページの順序は、見出し、地域、画像と帰属、バリアフリー情報、営業時間、基本情報、提供、経路へのリンクとする。画像は場所の文脈を示すため先頭に置き、営業時間はバリアフリー情報の下、基本情報の上に置く。

見出しは`h2`、状態は可視テキストで出す。色だけで状態を伝えない。`role="alert"`や`aria-live`は付けない。動的な通知ではない。

### artifactには生の規則だけを持たせる

`sources.locations`の各場所へ`openingHours?: string`を足す。ビルドでは解釈せず、文字列であることだけを検証する。ビルド時に全件を解釈して失敗させる案は、公開データの1件の構文ミスで全ページのビルドを止めるため採らない。解釈不能は、その場所だけ生の規則表示へ落とす。

## Risks / Trade-offs

- [プロセスTZの夏時間で変換が1時間ずれる] → `getTimezoneOffset`を日付ごとに使う。日本は夏時間がなく、UTCとAsia/Tokyoの両方でテストする。
- [ライブラリが規則を解釈できない] → 状態を断定せず、生の規則と編集リンクを出す。ページは成功させる。
- [ページを開いたまま状態が古くなる] → 読み込み時点の表示を正とする。自動更新は別change。
- [PH指定があるのに祝日例外が不完全] → 常時の注意書きで補う。祝日警告はPH・SHがない場合に限る。
- [曜日だけの規則が祝日に誤る] → ライブラリの日本祝日評価と、PH・SHがない場合の警告で知らせる。
- [動的描画でリクエストごとにartifactを読む] → モジュールスコープでキャッシュする。
- [LGPL-3.0の依存を配布物へ含める] → サーバー専用にし、クライアントバンドルへ含めない。依存ライセンスの出力に載せる。
- [`opening_hours`の規則が月次で変わる] → 生の規則をartifactに持ち、次のビルドで追従する。
- [深夜営業の日別表示が読みにくい] → ライブラリの分割に従い、各日の時間帯として表示する。表現の改善は表示を見てから行う。

## Migration Plan

1. `opening_hours@3.16.0`を依存へ追加する。
2. artifactの各場所へ`openingHours`を追加し、文字列の検証を足す。
3. JSTアダプタ、評価、日別整形、警告のモジュールを追加する。
4. 詳細ページを`force-dynamic`にし、営業時間セクションを画像とバリアフリー情報の下・基本情報の上へ入れる。
5. UTCとAsia/Tokyo、祝日、第1土曜、深夜跨ぎ、24/7、解釈不能のテストを通す。
6. 文書と依存ライセンスの表示を更新し、`npm run build`で確認する。
7. ロールバックは、営業時間セクションと依存を削除し、詳細ページを`force-static`へ戻す。
