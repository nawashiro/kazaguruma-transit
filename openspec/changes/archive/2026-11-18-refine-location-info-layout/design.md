# Design

## Context

`LocationDetailContent`は、編集リンク、地域、画像、`BarrierDetailBlock`、`OpeningHoursSection`、`BasicInfoSection`、`ProviderSection`、目的地リンクの順に並べる。編集リンクは画面上部にあり、提供元は独立したセクションとして基本情報の後ろにある。`BarrierDetailBlock`は「バリアフリー情報」の1セクションに、車いすの状態バッジ・説明・WheelMapリンク・関連ページをまとめている。`OpeningHoursSection`は状態バッジと一週間の一覧を独立したセクションとして持つ。

状態バッジと参照リンクは、`.ruby-text`を付けたセクションの内側にある。Rubyful v2は`.ruby-text`の子孫のHTMLを`<ruby>`と`<rt>`に置き換えるため、固定高のバッジでは「営業時間外」が折り返され、ボタンではルビの注釈が上に付いてラベルが上端へ寄る。Rubyfulには特定の子孫を除外する設定がない。

状態が「情報なし」の説明文は「バリアフリー情報がありません。」で、バッジの「情報なし」と重複している。営業時間の一覧は今日を`11/18(水)`と表示し、写真帰属は一覧カードで「写真」「ライセンス」の2行になっている。一覧の状態バッジは情報なしの場所だけ表示されず、バッジの描画条件が分岐している。

## Goals / Non-Goals

**Goals:**

- 車いすの状態と外部リンクを別のセクションに分け、状態はバッジと説明の横並びで示す。
- ルビ表示を有効にしても、バッジの文言を折り返さず、ボタンのラベルを中央に保つ。
- 営業状態と営業時間を基本情報の中の別々の行に置き、一覧の先頭を「今日」にする。
- 写真帰属を「写真 作者・ライセンス」の1行にする。
- 車いす情報と基本情報のデータの直後に出典を置き、独立した提供元セクションをなくす。
- 一覧の「情報なし」にもバッジを出し、バッジの表示条件をなくす。
- 編集リンクを基本情報の情報行の後ろへ移し、左寄せに統一する。
- セクション間の余白を広げる。

**Non-Goals:**

- 場所artifact、OSM・WheelMapのURL、営業時間の評価、電話・ウェブサイト・Wikipediaの解決を変えない。
- 一覧カードに営業状態のバッジを追加しない。
- Rubyful本体の設定やCSSを変更しない。
- 状態文言「全面」「一部」「非対応」「情報なし」を変えない。

## Decisions

### 1. 車いす情報とバリアフリー情報を別のセクションにする

`BarrierDetailBlock`を、車いすの状態を示す`WheelchairInfoBlock`と、外部リンクを示す`BarrierInfoBlock`に分ける。`BarrierBadge`と`getWheelchairStatus`はそのまま使う。

- 車いす情報は`h2`「車いす情報」、状態バッジ、説明文、出典、WheelMapまたはOpenStreetMapの参照リンクを持つ。
- バリアフリー情報は`h2`「バリアフリー情報」と関連ページのリンク一覧だけを持つ。関連ページがないときはセクションごと表示しない。
- セクションのIDは`wheelchair-heading`と`barrier-heading`に分ける。

状態と説明は`flex flex-wrap items-center gap-2`の行に置く。狭い画面で説明が次の行へ折り返すのは許すが、バッジの文言は折り返さない。

### 2. バッジとボタンをRubyfulの対象外にする

セクション全体に付けていた`.ruby-text`を外し、見出しと文章の要素に付ける。状態バッジと参照リンクは`.ruby-text`の外に置く。

- 車いす情報の`h2`と説明文には`ruby-text`を付ける。状態バッジは説明文の外に置く。
- バリアフリー情報の`h2`と各リンクの名前には`ruby-text`を付ける。
- 基本情報では、`h2`、各`dt`、電話・ウェブサイト・Wikipediaのリンク文字、目安の注意書きと祝日の警告に`ruby-text`を付ける。状態バッジ・時刻・営業時間の一覧には付けない。
- 車いす情報と基本情報の出典行は英語と記号だけなので`ruby-text`を付けない。
- 営業時間の一覧（日付・曜日・時間帯）は`ruby-text`の外に置く。

バッジには`whitespace-nowrap`を追加し、文言を1行に固定する。参照リンクは`py-2`を外し、`h-auto min-h-[44px]`と`btn`の`align-items: center`に任せる。ルビの注釈がなくなるため、ラベルは上下の中央に戻る。

代替案として、`.badge ruby`や`.btn ruby`にCSSを足す方法がある。しかしRubyfulが挿入する構造に依存し、ボタンの上寄せも残るため採用しない。

### 3. 営業時間を基本情報の2行にする

`OpeningHoursSection`を独立したセクションとして描画するのをやめ、`BasicInfoSection`の中で営業状態と営業時間の行を出す。`evaluateOpeningHours`はこれまでどおりサーバーで実行する。

基本情報の表示条件は、電話・ウェブサイト・Wikipedia・営業状態・営業時間・編集リンクのどれかがあることにする。行の順は、電話、ウェブサイト、Wikipedia、営業状態、営業時間とする。

- 営業状態の行は`dt`「営業状態」と`dd`に状態バッジと次に変わる時刻、今日が祝日のときは祝日の警告、目安の注意書きを置く。注意書きで複数行になるため、`items-start`で上端を揃える。状態が解釈できないときは行を出さない。
- 営業時間の行は`dt`「営業時間」と`dd`に一週間の一覧と目安の注意書きを置き、`items-start`で上端を揃える。目安の注意書きは両方の行に置く。
- `24/7`は営業状態の行に「24時間営業」の成功色バッジを出し、営業時間の行に7日分の一覧を出す。
- 規則がないときは2行とも出さない。解釈できないときは営業状態の行を出さず、営業時間の行に生の規則と目安の注意書きを出し、祝日の警告は出さない。
- 情報行の後に編集リンクを置き、その下に出典行を置く。

一週間の一覧は`WeekSchedule`をそのまま使い、`index === 0`の日付表示を「今日」に変える。`time`要素の`dateTime`は当日のISO日付のまま残す。

祝日は`opening_hours`の`PH`を東京の設定で評価して判定する。`new opening_hours("PH", { country_code: "jp", state: "東京都" })`の`getState`がtrueの日だけ警告を出す。規則に`PH`/`SH`がある場合は警告しない。判定はサーバーの場所詳細表示時に1回行い、パーサはモジュールで1つだけ作る。

代替案として、営業時間を`h3`の小さなセクションとして基本情報の中に置く方法がある。基本情報の他の項目と揃えるため、`dl`の行にするほうが一貫する。

### 4. 参照リンクの文言を短くする

`wheelchair-status.ts`の`linkLabelMain`を、状態が分かるとき「編集する」、状態が「情報なし」のとき「追加する」に変える。relationは「編集する」にする。`linkLabelSub`は「（WheelMapを開きます）」「（OpenStreetMapを開きます）」のまま残す。

`BarrierDetailBlock`は、主文言と副文言を1つの`span`に連結して表示する。編集リンクと参照リンクの見た目は`btn btn-secondary h-auto min-h-[44px] rounded-full dark:rounded-sm text-base`を基本にし、`py-2`を使わず、`whitespace-normal`で折り返しを許す。

### 5. 写真帰属を1行にする

一覧カードの`card-body`から`dl`を外し、次の1行にする。

```
<p className="text-base">写真 {image.creator}・{imageLicenseLabel(image.license)}</p>
```

ライセンスはテキストのままとし、詳細ページのリンクに委ねる。カード自体をリンクにする構造、`figure`を最初の子に置く構造、上端だけの角丸は変えない。

### 6. 編集リンクを情報行の後ろへ移す

`EditLocationLink`を`LocationDetailContent`の先頭から外し、`BasicInfoSection`の情報行の後に置く。編集リンクは左寄せにし、`w-full sm:w-auto`で幅を決める。出典行は編集リンクの下に置く。

基本情報は、編集リンクだけでも表示する。電話・ウェブサイト・Wikipedia・営業時間・編集リンクのどれもない場合だけ、セクションを表示しない。

代替案として、編集リンクを基本情報の外のまま画面下部へ移す方法がある。ユーザーが情報を確認した流れで編集できるよう、基本情報の中に置く。

### 7. 提供元セクションをなくし、出典を操作ボタンの後に置く

`ProviderSection`を削除する。代わりに、車いす情報と基本情報のデータ表示の直後に、次の出典行を置く。

```
<p className="mt-2 text-base">
  © <a href="https://www.openstreetmap.org/copyright" ...>OpenStreetMap contributors</a> ODbL-1.0
</p>
```

- 車いす情報の出典行は状態・説明・参照リンクの後に置く。基本情報の出典行と同じ文言にする。
- 基本情報の出典行は情報行と編集リンクの後に置く。
- バリアフリー情報は外部リンクだけなので、OSMの出典行を置かない。
- 画像の作者とライセンスは、これまでどおり画像の直後に残す。

出典行は英語と記号だけなので、`ruby-text`を付けない。独立した「提供」の見出しは作らない。

### 8. 一覧の情報なしにもバッジを出す

`BarrierBadge`の`null`返却をやめ、`wheelchair`が`null`または未知の値でも「情報なし」の無彩色バッジを描画する。`WheelchairStatusBadge`はすでに`情報なし`を受け取れるため、状態の分岐は`BarrierBadge`の中だけに閉じる。

一覧のカードは常にバッジを持つ。色は全面=成功色、一部=警告色、非対応=エラー色、情報なし=無彩色とし、文言を必ず入れる。

### 9. セクション間の余白を広げる

`LocationDetailContent`の`space-y-4`を`space-y-8`にし、画像・車いす情報・バリアフリー情報・基本情報・目的地の間に2remの余白を置く。見出しの切れ目を明確にし、前のセクションの出典が次の見出しに近づきすぎないようにする。

### 10. ドキュメントを表示に合わせる

`docs/how-to/update-location-data.md`の営業時間の配置、画像帰属、情報なしの案内、出典の表示位置を、今回の表示に合わせる。「営業時間は画像とバリアフリー情報の下、基本情報の上」という記述を削除し、基本情報の中の2行であることを書く。

## Risks / Trade-offs

- [ルビの適用範囲が狭くなり、これまでルビが付いていた文章に付かなくなる] → 見出し、説明文、リンク名、基本情報の項目に`ruby-text`を明示する。テストで、説明文にはルビが付き、バッジとボタンには付かないことを確認する。
- [バッジとボタンを`.ruby-text`の外に出すため、セクションのマークアップが増える] → 表示の安定を優先する。ルビの一括適用より、要素ごとの指定を選ぶ。
- [基本情報の`dl`の中に一週間の`dl`を入れ子にする] → `dd`の中の`dl`は妥当なHTMLで、支援技術も定義リストとして読む。`dt`「営業時間」と`dd`の一覧の対応を保つ。
- [「今日」の判定を先頭要素に依存する] → `buildWeek`と`buildAllDayWeek`は日本時間の当日から7日を作る。テストは固定した日時で先頭が「今日」になることを確認する。
- [参照リンクの文言が短くなり、リンク先が分かりにくくなる] → 副文言「（WheelMapを開きます）」を残し、新しいタブで開くことを`sr-only`で伝える。
- [写真帰属の1行化で、作者とライセンスの区切りが読み取りにくくなる] → 「・」で区切り、作者とライセンスの順を固定する。ライセンス名は`imageLicenseLabel`の表記を保つ。
- [祝日判定のパーサを毎回作ると重い] → 東京用の`PH`パーサをモジュールで1つだけ作り、`getState`だけを日付ごとに呼ぶ。
- [セクション間隔を広げるとページが長くなる] → 2remに抑え、画像と本文のまとまりを崩さない。
- [出典行がセクションごとに増える] → 車いす情報と基本情報の2か所だけにし、画像の帰属とは分ける。独立した提供元セクションは作らない。
- [編集リンクが画面下部へ下がる] → 基本情報の情報行と出典の直後に置き、右寄せのセカンダリボタンとして残す。基本情報が空でも編集リンクだけで表示する。
- [一覧の情報なしバッジが状態不明を「問題なし」と誤解させる] → 無彩色に「情報なし」と明記し、状態色を使わない。

## Migration Plan

UIだけの変更で、データ移行はない。デプロイ後に場所一覧と場所詳細をライト・ダークの両テーマ、ルビON・OFFの両方で確認する。問題があれば変更をrevertする。
