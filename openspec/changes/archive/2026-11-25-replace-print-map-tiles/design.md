# Design

## Context

`src/app/api/pdf/generate/route.ts` の `generateRouteHTML` は、`@googlemaps/google-maps-services-js` の `Client.directions` で徒歩ポリラインを取得し、`maps.googleapis.com/maps/api/staticmap` のURLを組み立てて `<img src>` に埋め込む。Puppeteerは `setContent` でそのHTMLを読み、`page.pdf` で印刷する。`@googlemaps/google-maps-services-js` の利用箇所はこのファイルだけである。

外側の制約として、次の4点を実測で確認した。以降の決定はすべてここから導いている。

| 制約 | 実測 |
|---|---|
| 本番と同じChrome起動フラグ（`--disable-gpu`、`--disable-accelerated-2d-canvas`）でWebGLが使える | MapLibreが描画でき、`idle` 到達まで約1.0〜1.8秒 |
| 2枚の地図を1ページに置いても同時に描ける | 2枚とも `idle` に到達。ズームは範囲の自動フィットで決まる |
| 日本語の注記が実際に描かれる | symbol層を外した画像との差分が3.26%、強差分0.6%。字形が無いと0%になる |
| WebGLのcanvasは `page.pdf` にそのままでは載らない | 要素のスクリーンショットはインク10.55%、同じページのPDFは内側0% |
| 背景タイルの取得元 | OpenFreeMapのスタイル・タイル・glyphはいずれも `access-control-allow-origin: *` を返す |

## Goals / Non-Goals

**Goals:**

- Google のAPIキーなしで、地図入りのPDFを生成できる。
- 地図は必ず描かれる。描けないときはPDFを返さず、失敗を明示する。
- 徒歩区間の座標の出どころだけを差し替え可能にし、描画コードを1本に保つ。

**Non-Goals:**

- 徒歩経路の実探索。Issue #151 の範囲であり、本変更は折れ線を受け取る口だけを作る。
- バリアフリー評価と、勾配・段差の警告。歩行空間ネットワークデータは千代田区の歩行可能網624.5kmに対して28.4km（4.5%）しか収録がなく、バス停79件のうち100m以内に接続できるのは18件である。OSM側も歩行系ウェイ21,006本に対して `wheelchair` タグは56本で、区内全域の評価に足りない。
- Webページ上の地図表示と Google マップへのリンク。Issue #157 の範囲。

## Decisions

### 1. 地図はPuppeteerの描画中にMapLibreで描く

PDFの地図は、`setContent` したページの中でMapLibreにcanvasを描かせ、そのまま `page.pdf` で印刷する。地図画像を別途生成して合成する工程は作らない。

代替として、サーバー側でタイルを取得してPDFに画像として貼る案（`pdf-lib` などを併用）を検討した。しかしタイルの取得、投影、クリップ、ラベルの配置を自前で実装することになり、KISSに反する。OpenFreeMapのスタイルはラベル配置まで含んでおり、ブラウザで描かせればその恩恵をそのまま受けられる。

### 2. MapLibre GL JSを依存に加え、配信物はリポジトリから読む

`maplibre-gl` を `dependencies` に加え、`node_modules/maplibre-gl/dist/maplibre-gl.js` と `.css` を `page.addScriptTag`／`addStyleTag` で読み込む。CDNから読み込まない。

理由は2つある。1つは、PDF生成が外部のCDNの可用性に依存すると、原因の切り分けが難しい失敗が増えること。もう1つは、`idle` 待ちの対象にCDNの取得が混ざると、待ち時間の上限を意味のある値に決められないことである。`addScriptTag` はローカルのパスから注入でき、`setContent` の後でも動くことを確認した。

### 3. 徒歩区間は「座標の出どころ」だけを差し替える

PDF生成の要求に `walkPaths` を任意の項目として足す。

```ts
walkPaths?: {
  originToStop?: [number, number][];
  stopToDestination?: [number, number][];
}
```

描画側は、折れ線があればそれを、無ければ2地点を結ぶ直線を破線で描く。**どちらでも同じレイヤーと同じ描画関数を使う。** 折れ線の有無で分岐するのは座標の配列だけで、経路本文・時刻・乗換・メモの生成は一切変わらない。

こうしておくと、#151 が本物の徒歩幾何を返せるようになったとき、クライアントが配列を埋めるだけでPDFが変わる。描画コードを書き換える必要がない。

破線にするのは、直線が実在の歩行経路ではないことを線種で示すためである。実経路を直線で描くと、利用者は「この道を歩けばよい」と読み違える。

### 4. WebGLのcanvasを2Dのcanvasへ写し、モノクロと印刷可能な画像を同時に得る

MapLibreが描くcanvasはWebGLで、そのままでは `page.pdf` に内容が載らない。実測では、要素のスクリーンショットでは10.55%のインクがある一方、同じページを `page.pdf` にすると内側のインクが0%になった。空のキャンバスとして印刷される。

そこで `idle` の後に、WebGLのcanvasを2Dのcanvasへ `drawImage` で写し、その2Dのcanvasで `filter = "grayscale(1)"` を当て、PNGにしたものを `<img>` として元のcanvasと置き換える。置き換え後はPDFの内側インクが10.89%、平均彩度0.000になることを確認した。

CSSの `filter` を要素に当てる案は、WebGLのcanvasが印刷に載らない以上、単独では成立しない。MapLibreのスタイルを書き換えて色を落とす案も検討したが、Positronのスタイルは25000バイト超のJSONで、色の指定が数百箇所に散っている。写しの段階で1回フィルタを掛ける方が簡潔である。

`contrast()` を足す案は採らない。実測で `grayscale(1) contrast(1.15)` は、200未満の画素を14.9%から1.7%へ落とした。Positronはもともと淡色で、明るい側に寄せると細い道路と注記が紙から消える。淡色のまま刷る方が読める。

### 5. 地図の失敗はPDF生成の失敗にする

地図の描画は、`Promise.race` で上限時間を設けて待つ。タイルが取れない、`idle` に到達しない、MapLibreの読み込みが失敗する、のいずれでもPDFを返さず、500と「PDFを生成できませんでした」の日本語メッセージを返す。

地図を欠いたPDFを返す案も検討したが、採らない。このPDFの用途は印刷して持ち歩くことであり、地図の無い紙は「どの停留所まで歩くのか」という最も必要な情報を落としている。しかも利用者はそれが欠けていることに気づかないまま印刷する。欠けた成果物を正常な成果物として渡すより、失敗を明示して再試行させる方が誠実である。既存のPDF生成も、失敗時は500とメッセージを返す契約になっている。

### 6. 失敗の検知は全地図の完了を待ってから判定する

地図は最大2枚（出発地→乗車停留所、降車停留所→目的地）ある。待ち合わせは `Promise.all` で行い、1枚でも失敗すればPDFを返さない。全体で1つのタイムアウトを共有すると、1枚目の失敗が2枚目の時間を奪うため、上限時間は地図ごとに設ける。ただし部分的な成功を成果物にしないため、判定は全地図の完了後に行う。

## Risks / Trade-offs

- [タイル配信元が落ちるとPDFを生成できない] → 地図の欠けたPDFを黙って渡さない取引である。タイルの出典を設定ではなくコードに固定し、切り替えの判断を1箇所に集める。失敗は500と日本語メッセージで明示し、利用者は再試行できる。
- [OpenFreeMapの公開インスタンスは可用性の保証がない] → 規約上、印刷物への利用は認められている。SLAが無いことは既知のリスクとして受け入れる。将来セルフホストへ移す場合も、スタイルURLの差し替えだけで済む形にする。
- [MapLibreの描画はCPU描画になり、遅い環境では上限時間を超える] → 上限超過はPDF生成の失敗として扱う。上限時間は描画の実測（約1.8秒）に対して十分な余裕を取る。
- [帰属表示が地図を覆う] → 紙面の下部に置き、地図の描画領域の外へ出す。地図の中に重ねない。
- [依存の追加でライセンス表示が増える] → MapLibreはBSD-3-Clause。既存の依存ライセンスの収集対象に入るため、ライセンスページは自動で追随する。
- [Google SDKを消すと他の用途が壊れる] → 利用箇所はPDF生成の1ファイルだけであることを `grep` で確認済み。削除後にビルドと全テストで確認する。

## Migration Plan

1. `maplibre-gl` を追加し、PDF生成の描画を差し替える。この時点ではGoogle SDKを残さない（同じファイル内で置き換わるため、部分的な併存は作らない）。
2. `@googlemaps/google-maps-services-js` を削除し、`GOOGLE_MAPS_API_KEY` の記述を環境変数の例とドキュメントから消す。
3. 出典をライセンスページと紙面へ追加する。
4. 契約テストを追加し、`npm test`、`npm run lint`、`npm run build` を通す。

切り戻しは、この変更のコミットを戻すだけで完了する。データの移行や保存形式の変更はない。
