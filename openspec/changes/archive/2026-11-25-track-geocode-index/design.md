# Design

## Context

索引の書き出しは `src/lib/location/geocode-index.ts` の `serializeGeocodeIndex` が担い、`JSON.stringify(index, null, 0)` で1行のJSONを出力する。生成側の `scripts/lib/geocode-build.ts` には `indexDigest`（生成日時を除いた内容のSHA-256先頭16桁）が既にあるが、書き込みの判断には使われていない。

`generatedAt` は実行時刻をそのまま記録するため、OSM と位置参照情報が同一でも実行のたびに値が変わる。1行JSONでは差分が「1行の全置換」になるため、変更点が人間にも git にも読めない。

索引の大きさは 1.27MB、gzip で 251KB、xz で 185KB。名前索引が 1,016KB、街区が 138KB、町字ポリゴンが 111KB。

このリポジトリは既に `public/images/route.gif`（14MB）と `locations.gif`（11MB）を追跡しており、`.git` は 40MB。

## Goals / Non-Goals

**Goals:**

- クローン直後から、外部取得なしで地点検索が動く。
- 索引の差分を人間が読める形にする。
- 内容が同じ実行で差分を出さない。

**Non-Goals:**

- 索引の内容そのものの見直し（種別の絞り込みなど）。`location-search` の要求は変えない。
- 索引の圧縮やバイナリ形式への移行。
- Git LFS の導入。

## Decisions

### 追跡する

1.27MB を追跡する。このリポジトリは既に 25MB の GIF を追跡しており、`.git` は 40MB ある。索引の追加は相対的に小さい。

却下した代替案は次のとおり。

| 案 | 却下の理由 |
| --- | --- |
| gitignore してビルド時に生成 | ビルドが 133MB の OSM 抽出取得に依存し、上流が止まれば全ビルドが失敗する。design.md（`geocode-local-index`）で却下済みの方針に反する |
| gitignore して手動生成を必須にする | 索引なしのクローンで `/api/geocode` が静かに失敗し、原因が分かりにくい |
| 公共性の高い種別だけ残す | 1,028件・102KB まで落ちるが、`location-search` は「千代田区の範囲にある名前付きの地点から作る（MUST）」と定めており、種別で絞る根拠がない。実装都合で仕様を曲げることになる |

### 1エントリ1行に整形する

`serializeGeocodeIndex` を、`boundary`・`blocks`・`names` の各要素を1行のJSONとして並べる形に変える。

サイズへの影響は測って確認済み。10件の座標を変えてコミットし、`git gc` 後のパックサイズを比べた結果、1行版が 251KB、1エントリ1行版が 252KB で差はなかった。git は圧縮チャンク単位で差分を取るため、整形の有無はリポジトリの太り方に影響しない。整形の利点は `git diff` が「どの地点が変わったか」を示すことにある。

### 内容が同じなら書き換えない

`indexDigest` を書き込み前に使い、既存索引のダイジェストと比較する。同じなら書き換えず、`generatedAt` も更新しない。

ダイジェストの対象は `version`・`boundary` の名前・`blocks`・`names` で、`generatedAt` は含まない。既存の実装がそのまま使える。

比較対象の既存索引が読めない・壊れている場合は、書き換える側に倒す。壊れたファイルを温存する理由がない。

### 更新コマンドの報告を分ける

書き換えた場合は `索引を書き出しました`、書き換えなかった場合は `索引に変更はありません` と報告する。作業者が「実行したのに差分が出ない」を異常と誤解しないようにするため。

## Risks / Trade-offs

- [索引が大きいまま履歴に残る] → 1エントリ1行にするため差分は小さく、内容が変わらなければコミットも発生しない。将来サイズが問題になったら、その時点で圧縮形式か LFS を検討する。
- [整形によって既存の索引ファイルが一度大きく差分になる] → 追跡の初回コミットで1回だけ全行が追加される。以降は1エントリ単位の差分になる。
- [OSM 抽出の更新で索引が大きく変わる] → OSM の更新は月次程度で、変化は名前の追加・削除に限られる。1エントリ1行の整形により、影響範囲は diff で確認できる。
- [手順書の確認コマンドが古いまま] → `generatedAt` の表示を外し、代わりにダイジェストか件数を示す形に直す。

## Migration Plan

1. `serializeGeocodeIndex` を1エントリ1行へ変え、往復（書き出し→読み戻し）のテストを追加する。
2. 生成側にダイジェスト比較を入れ、内容が同じなら書き換えないことをテストで固定する。
3. 索引を再生成し、整形後の内容で追跡を開始する。
4. 手順書を更新する。

ロールバックは索引ファイルと生成スクリプトの差分を戻すだけ。実行時の検索経路には影響しない。
