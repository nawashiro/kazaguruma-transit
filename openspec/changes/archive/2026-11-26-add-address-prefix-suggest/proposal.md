# Proposal

## Why

住所を途中まで打っている間、候補が出ない。`千代田区神田和泉町` まで打っても0件で、`千代田区神田和泉町1` と番地の数字を足した瞬間に初めて1件出る。索引を使った検証では、59町のうち54町が町名を打ち終えた時点で候補ゼロであり、5文字以上を打って候補が空になる組み合わせは168通りあった。数字を足せば59町すべてで出るので、候補が出るかどうかは「数字が入ったか」の一点で決まっている。

町名で候補が出ているように見える場合も、出しているのは住所ではない。名前索引に町名と同名の地点があるだけで、`神田和泉町` の候補は住所欄が `千代田区神田佐久間町三丁目22番` を名乗る。町名と同名の92件のうち14件は、自らの町ではない住所を示す。

同じ解決器は番地の「号」も取り違える。`隼町4-1` は `千代田区隼町1番` を返し、`一番町25-1` は `千代田区一番町1番` を返す。2つ目の数字を常に街区として読むため、丁目を持たない28町では最初の数字が消える。

## What Changes

- 住所の入力に対して、町・丁目・街区の順に一段ずつ候補を返す。町名だけでも、町名の途中でも、候補が出る。
- 住所候補は常に街区代表点とする。丁目だけの住所は返さない。
- 候補は名前索引の候補と一つの一覧にまとめる。住所の接頭辞として解釈でき、かつ町が一意に決まるときは、住所候補を名前候補より先に置く。町が複数に割れる語（`神田` で28町）では住所候補を出さず、名前索引の候補に譲る。
- 名前索引の照合で、検索語の先頭の `千代田区` と `東京都` を落としても照合する。`千代田区神田和泉町` のような区名付きの入力で、区名のない名前索引の地点に当たる。
- 番地の数字の意味を町の構造から決める。丁目を持つ町では1つ目を丁目、持たない町では1つ目を街区として読み、3つ目の数字（号）があっても街区を取り違えない。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `location-search`: 住所の途中入力に対する段階的な候補（新しい要件）、候補の順位付け（住所候補の位置）、番地の解決（号を含む住所と町の構造による数字の解釈）、別名と表記ゆれによる照合（区名・都名の接頭辞）を改める。

## Impact

- サーバー: `src/lib/location/geocode-search.ts` の `GeocodeSearcher` に段階的な住所候補を加え、`findAddress` を同じ規則へ寄せる。`src/lib/location/geocode-address.ts` の正規化と `parseAddressQuery` を共用する。
- API: `/api/geocode` の契約は変わらない。応答の `kind` に住所候補を示す値が加わる。
- 索引: `data/geocode-index.json` の再生成は要らない。街区1,398件をそのまま使う。
- クライアント: 変更なし。
- テスト: `src/lib/location/__tests__/geocode-search.test.ts`、`src/lib/location/__tests__/geocode-address.test.ts`、`src/app/api/__tests__/geocode-route.test.ts`。
- 仕様: `location-search`。
