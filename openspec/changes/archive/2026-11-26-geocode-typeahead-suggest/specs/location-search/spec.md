# Spec Delta

## ADDED Requirements

### Requirement: 地点検索の利用回数による拒否の禁止

地点検索と住所の逆引きは、IPアドレスあたりの利用回数を理由に要求を拒否してはならない（MUST NOT）。`/api/geocode` は入力中の打鍵ごとに呼ばれ得るため、入力の確定を待たずに候補を出す使い方を妨げない。

#### Scenario: 入力中に繰り返し検索する

- **WHEN** 利用者が同じ利用元から短時間に何度も地点検索を送る
- **THEN** サーバーはすべての要求を索引の探索で処理し、429を返さない

#### Scenario: 逆引きを繰り返す

- **WHEN** 利用者がGPSの取得を繰り返し、そのたびに住所を逆引きする
- **THEN** サーバーはすべての逆引きを処理し、429を返さない

## REMOVED Requirements

### Requirement: 検索の利用制限

**Reason**: 地点検索と逆引きはサーバー内の静的索引だけを読み、外部サービスや共有資源を使わない。打鍵ごとに検索する入力では、1時間600回の上限が通常の操作を妨げ、上限に達すると入力途中の文字を捨てて利用制限画面へ遷移していた。制限が守っていた資源がないため、地点検索の制限だけを外す。

**Migration**: 経路検索・PDF生成・結果ページの利用制限は`checkRateLimit`と`appRouterRateLimitMiddleware`を使い続け、変更しない。`/rate-limit`画面と`source`の戻り先もそのまま残す。地点検索のクライアントは429分岐と利用制限画面への遷移を削除し、`GeocodingStatus`から`rate-limited`を除く。
