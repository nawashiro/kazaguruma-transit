# Design

## Context

npubは `NpubDisplay`（`src/components/ui/NpubDisplay.tsx`）が表示し、`UserIdentity` とモデレーター管理の各画面がこれを使う。表示箇所は次の4系統に集まる。

| 画面 | 部品 | 表示する値 |
|---|---|---|
| 設定（アカウント情報） | `UserIdentity` | ログイン中の利用者のpubkey |
| モデレーター管理（`ModeratorManagementSection`、`DiscussionManagementModeratorPage`、`/discussions/[naddr]/moderators`） | `UserIdentity`、`NpubDisplay` | モデレーターと申請者のpubkey |
| 会話の作成・編集 | `UserIdentity` | 入力済みのモデレーター |
| 追加予定のモデレーター | `NpubDisplay` | 入力したnpub、または16進数から変換したnpub |

`NpubDisplay` は今、npubを `code` 要素に全文表示し、`truncate` で見た目だけを切っている。コピーボタンは全文をクリップボードへ渡す。

会話の作成・編集画面の削除ボタンは、読み上げ名にnpub全文を入れている（`aria-label="モデレーター <npub> を削除"`）。`ModeratorManagementSection` のチェックボックスは、日本語の呼び名を読み上げ名に使っている。

## Goals / Non-Goals

**Goals:**

- 表示する文字列の上限を決め、どの画面でもnpubが周りの情報を押し出さないようにする。
- 読み手に意味のない識別子を、読み上げでも聞かせない。

**Non-Goals:**

- 識別子の書式やコピーする値の変更。
- naddr、note、neventなどnpub以外の識別子の表示。
- 狭い画面で `…` まで見えなくなることの防止。行がはみ出さないことを優先する。

## Decisions

### 1. 表示文字列の上限を9文字に切り、`…` を足す

先頭9文字を取り出し、末尾に `…` を連結した文字列を描画する。9文字は「npub1」と続く4文字にあたる。`…` を足して表示は10文字になる。元の値が9文字以下なら短縮せず、`…` も足さない。

省略記号を自分で足すのは、狭い画面でも切れた位置が分かるようにするためである。CSSだけに任せると、長い値がどこで切れたのか読み手に伝わらない。

### 2. 幅に収まらないときは `truncate` に任せる

`truncate` と `min-w-0` は残す。10文字が入らない幅では、CSSが `npub1` 以降を途中で切る。`…` まで見えなくなる場合もあるが、これを欠陥としない。npubを読むことより、行を短く保って隣の日本語の呼び名や操作を読みやすくするほうが、この画面では大事である。幅に合わせて文字数を変える実装（`ch` 単位の幅指定やJSでの計測）は、フォント描画に依存するうえ、狭い画面で見える文字数がさらに減るだけで利点がない。

### 3. 短縮は `NpubDisplay` の内部で行い、propsを増やさない

呼び出し側は `pubkey` を渡すだけで、表示の長さは決めない。表示の長さを画面ごとに変える要求は今のところない。将来、全文を見せたい場面が出たら、そのとき `title` や別部品で対応する。

`NpubDisplay.tsx` に `formatNpubForDisplay(npub: string): string` をexportし、`NpubDisplay.test.tsx` から直接テストする。境界（9文字、10文字）と `…` を足さない条件を1か所で固定できる。

### 4. 削除ボタンの読み上げ名を日本語の呼び名へ変える

会話の作成・編集画面の削除ボタンは、`UserIdentity` の直上に出ているのと同じ日本語の呼び名を読み上げ名に使う（`formatBip39JapaneseMnemonicPreviewFromPubkey`）。npubはどの部分も人物の区別に使えず、63文字を読み上げるのは聞き手の負担になるだけである。

呼び名が同じモデレーターが2人並ぶと、読み上げ名も同じになる。区別は画面の並び順と、各項目の中身で行う。npubを短縮して名前に足す案は、区別に使えない9文字を読み上げに加えるだけで、採らない。読み上げ名を短くするために、名前を削る代わりに利用者ごとの通し番号を足す案は、画面に出ていない番号を読み上げにだけ持ち込むので採らない。

## Risks / Trade-offs

- [短縮後のnpubでは利用者を目視で見分けにくい] → 直上に日本語の呼び名が出る画面がほとんどで、見分けの手がかりはそちらが担う。全部が必要な場面はコピーで取り出す。
- [日本語の呼び名が衝突すると、削除ボタンの読み上げ名も同じになる] → 画面の並び順で対象を選ぶ。`ModeratorManagementSection` のチェックボックスも同じ呼び名を使っているので、この画面だけが新たに衝突を増やすわけではない。衝突しても、操作の誤りは取り消しで戻せる。
- [狭い画面で `npub1` の続きが4文字未満しか見えない] → 表示の上限は4文字として決めてあり、それより短く見えることは許す。値は読ませるためのものではない。
- [表示文字列に `…` が入るため、npubを選択してコピーすると短縮された値が入る] → コピーボタンが全文を渡す。テキスト選択によるコピーは補助的な手段だったので、これ以上の対応はしない。
- [既存テストが全文表示とnpub入りの読み上げ名を期待している] → 期待値を新しい文字列へ書き換える。コピーの期待値は全文のままで、変更しない。
