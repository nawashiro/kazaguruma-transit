# Proposal

## Why

麹町出張所を目的地にしたPDFの地図で、目的地のマーカーからOSMの道へ伸び、そのまま同じ道へ戻る「^」形の線が現れる。徒歩経路の折れ線が、地点から最寄りノードまでの接続区間（直線）を両端に含んでいるためである。麹町出張所では目的地と最寄り停留所が同じノードに接続するので、折れ線は「目的地（建物の中）→32メートル離れた道の上のノード→目的地」の3点になる。この往復は実在の道ではなく、地図に載せると徒歩経路として読まれてしまう。

## What Changes

- 徒歩経路の折れ線から、地点と最寄りノードを結ぶ接続区間を除く。折れ線は道の上のノード列だけを持つ。徒歩距離の定義（接続区間を含む）は変えない。
- 折れ線が2点に満たない区間は、線を描かず地点のマーカーだけを置く。同じノードに接続する2地点では、歩くのは建物の中だけで、地図に引ける道がないためである。
- **BREAKING**（出力内容）: 折れ線がないときに始点と終点を結ぶ破線を廃止する。地図に描くのは実在の道の上の実線だけにする。破線も、実在の道ではない線である点は同じである。
- 地点のマーカーを、Lucideのバスアイコン（停留所）と地図ピンのアイコン（出発地・目的地）に置き換え、地名の文字を地図から外す。停留所は黒地に白、地点は白地に黒と縁取りで塗り分ける。地名は地図の読み上げ名に残す。
- マーカーが地図の外へはみ出さないよう、地図の表示範囲を折れ線と両端の地点から求める。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `walk-network`: 徒歩経路の折れ線が、起点・到着点そのものではなく道の上のノード列だけを持つように変わる。
- `printed-route-map`: 破線を描く要求を廃止し、折れ線が2点未満の区間を線なしで描く要求と、地点マーカーをLucideのアイコンで描く要求を加える。

## Impact

- `src/lib/transit/walk-network.ts`: `walkLeg` が返す折れ線の作り方。距離の計算はそのまま。
- `src/lib/pdf/print-map.ts`: 破線の描画指定と `followsWalkNetwork` を削除し、線を引かない場合と表示範囲の求め方を足す。地点マーカーをLucideのアイコンへ置き換え、`lucide` を取り込む。
- `src/lib/pdf/route-html.ts`: `walkPaths` の項目の説明。受け取る項目の形は変えない。
- テスト: `src/lib/transit/__tests__/walk-network.test.ts`、`src/lib/pdf/__tests__/print-map.test.ts`、`src/app/api/__tests__/pdf-route-contract.test.ts`、`src/app/api/__tests__/pdf-print-map-html.test.ts`。
- 影響を受けない: 徒歩距離・徒歩時間・候補の絞り込み・順位、PDFの経路本文、地図のタイルと帰属。
