# Spec Delta

## ADDED Requirements

### Requirement: 最終検索ボタンの見た目と名前

最終経路検索のsubmitは可視文字「経路を検索」を表示し、同じ名前で読み上げる（SHALL）。ルビON / OFFでも可視文字を保つ。検索画面への移動リンクや、GPS取得・再編集など検索以外の操作はアイコン化の対象に含めない。

#### Scenario: 最終検索ボタンを表示する
- **WHEN** 経路条件を送信する最終検索ボタンを表示する
- **THEN** 可視文字「経路を検索」と同じアクセシブルな名前を持つsubmitを表示する
- **THEN** ルビON / OFFでも可視文字を保つ

### Requirement: 住所欄に専用の検索ボタンを置かない

住所・場所名の入力欄に、虫眼鏡アイコンの専用検索ボタンを置いてはならない（MUST NOT）。住所検索は、入力中の候補表示とEnterによる確定で行う。

#### Scenario: 住所欄にボタンを置かない
- **WHEN** 目的地または出発地の入力欄を表示する
- **THEN** 入力欄に隣接する虫眼鏡アイコンの検索ボタンは存在しない
- **THEN** 入力中の候補表示とEnterによる検索で地点を探せる

## MODIFIED Requirements

### Requirement: 検索フォームの送信対象と操作性

住所検索は対応するフォームの送信として実行し、キーボードでも操作できなければならない（SHALL）。住所検索で最終経路検索を開始したり、ほかの必須項目の未入力によって住所検索を妨げたりしてはならない。最終経路検索のsubmitは44 CSS px以上の幅と高さを持ち、可視フォーカスを提供する。

#### Scenario: 住所検索を先に実行する
- **WHEN** ほかの条件が未入力の状態で、住所欄のフォームを送信する
- **THEN** 対象地点の住所だけを検索し、最終経路検索は開始しない
- **THEN** ほかのフォームの必須項目は住所検索を妨げない

#### Scenario: キーボードで検索する
- **WHEN** キーボードで住所欄に入力し、候補を選ぶかEnterで確定する
- **THEN** フォーカス位置を視認でき、入力中の候補へキーボードで移動して選択できる
- **THEN** 最終経路検索のsubmitも44 CSS px以上の操作領域と可視フォーカスを持つ

## REMOVED Requirements

### Requirement: 検索ボタンの見た目と名前

**Reason**: 住所検索を打鍵に応じた候補表示とEnterへ移し、虫眼鏡アイコンの専用ボタンを廃止する。最終経路検索の規定は「最終検索ボタンの見た目と名前」へ、住所欄の扱いは「住所欄に専用の検索ボタンを置かない」へ移す。

**Migration**: 住所欄の`SearchButton`を削除し、`aria-label="検索"`のアイコン専用submitを期待するテストを、候補表示とEnter検索を確認するテストへ置き換える。最終経路検索の可視文字「経路を検索」は変えない。
