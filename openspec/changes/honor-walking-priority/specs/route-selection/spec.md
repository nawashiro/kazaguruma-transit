# Spec Delta

## Purpose

検索が見つけた複数の経路候補から、利用者が選んだ優先条件に従って1つを選ぶ。歩きやすさを重視する利用者には乗換の手間をコストとして数え、速さを重視する利用者には到着の早さだけを比べる。

## ADDED Requirements

### Requirement: 優先条件による候補の選択

経路検索は、見つかった全ての候補から優先条件に従って1つを選ばなければならない（MUST）。徒歩優先では、乗換1回につき10分を到着時刻へ足した値を比較する。はやさ優先では到着時刻だけを比較する。乗換コストは、速さの差がこれを上回るときだけ乗換を選ばせる。

#### Scenario: 直通と乗換の到着が5分違う

- **WHEN** 徒歩優先で、直通が11時00分着、乗換が10時55分着で、総徒歩距離がどちらも同じである
- **THEN** 直通を選ぶ。乗換は10分のコストを足して11時05分となり、直通より遅くなる

#### Scenario: 乗換の到着が35分早い

- **WHEN** 徒歩優先で、直通が11時30分着、乗換が10時55分着である
- **THEN** 乗換を選ぶ。乗換はコストを足しても11時05分となり、直通より早い

#### Scenario: はやさ優先で同じ候補を比べる

- **WHEN** はやさ優先で、直通が11時00分着、乗換が10時55分着である
- **THEN** 乗換を選ぶ。到着時刻だけを比べ、乗換を避けない

### Requirement: 比較の同値時の順序

乗換コストを足した値が同じときは、総徒歩距離の短い経路を選ばなければならない（MUST）。総徒歩距離も同じときは、乗換回数の少ない経路を選ぶ。これらも同じときは、出発時刻指定では出発の早い経路、到着時刻指定では到着の早い経路を選ぶ。

#### Scenario: 到着と徒歩距離が同じ

- **WHEN** 徒歩優先で、2つの候補の到着時刻と総徒歩距離が同じで、乗換回数だけが1回と0回で違う
- **THEN** 乗換回数の少ない経路を選ぶ

#### Scenario: 徒歩距離だけが違う

- **WHEN** 徒歩優先で、2つの候補の到着時刻と乗換回数が同じで、総徒歩距離が0.09kmと0.35kmである
- **THEN** 総徒歩距離の短い0.09kmの経路を選ぶ

### Requirement: 到着時刻指定での比較

到着時刻指定の検索では、比較の向きを反転しなければならない（MUST）。遅く出発して到着に間に合う経路を優先する。徒歩優先では、乗換1回につき10分を出発時刻から引いた値を比較する。はやさ優先では出発時刻だけを比較する。

#### Scenario: 到着時刻を指定して徒歩優先で探す

- **WHEN** 到着時刻を11時00分に指定し、直通が10時35分発、乗換が10時50分発である
- **THEN** 出発の遅い乗換を選ぶ。乗換はコストを引いても10時40分となり、直通より遅く出発できる

### Requirement: 全ての検索経路での選択規則の適用

選択規則は、最寄り停留所1組だけを対象とする検索でも、周辺の停留所を組み合わせる検索でも同じでなければならない（MUST）。優先条件を読み取らないまま探索結果の先頭を使う経路を残してはならない（MUST NOT）。

#### Scenario: 最寄り停留所1組の検索で優先条件を変える

- **WHEN** 同じ出発地・目的地・時刻で、徒歩優先とはやさ優先を切り替えて検索する
- **THEN** どちらの検索でも、指定した優先条件で候補を比較して選ぶ

### Requirement: 乗換の範囲

乗換は、同じ停留所で降りて同じ停留所から乗り直す乗り継ぎに限らなければならない（MUST）。異なる停留所へ歩いて乗り継ぐ経路は探索しない。乗換の徒歩距離は0として扱い、乗換コストだけで評価する。

#### Scenario: 乗換停留所が同じ

- **WHEN** 乗換を含む経路の降車停留所と乗車停留所が同じである
- **THEN** 乗換の徒歩距離は0となり、乗換コスト10分だけが比較に加わる

#### Scenario: 離れた停留所への乗換を探さない

- **WHEN** 経路を探索する
- **THEN** 降車停留所と異なる停留所から乗り継ぐ候補を生成しない
