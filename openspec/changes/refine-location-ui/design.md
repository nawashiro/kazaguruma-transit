# Design

## Context

場所詳細は`LocationDetailContent`が、編集リンク、地域、画像、`BarrierDetailBlock`、営業時間、基本情報、提供元、目的地リンクの順に並べる。一覧は`LocationSummary`がDaisyUIのカードを組み立てる。

現状は次の点で標準から外れている。

- `BarrierDetailBlock`は`rounded-box border-l-4 bg-base-200 p-4`のブロックをセクション内に置き、状態を`text-xl`の文字と色付きアイコンで示す。アイコンは`size-4`で文字より小さく、`text-warning`などが背景とのコントラストを下げる。
- `BarrierBadge`は`badge-outline`を使う。営業状態はバッジではなく文字だけである。
- 編集リンクとバリアフリーの参照リンクは`btn-outline`で、角丸の指定がない。ほかのボタンは`rounded-full dark:rounded-sm`、`min-h-[44px]`、`text-base`を使う。
- 基本情報は`dl.list`の`list-row`に`min-h-[44px]`のリンクを入れるため、dtとddの文字の中心がずれる。
- 提供元は「座標・電話・ウェブサイト・営業時間」「バリアフリー情報」「画像」の3行に分かれ、同じOSM出典を重複して示す。画像の帰属は写真の直下にもある。
- 一覧カードは`<div class="card">`の中に`<a>`があり、その中に`figure`がある。DaisyUIの`card :where(figure:first-child)`は親から角丸を継承するため、`figure`の親が角丸を持たないこの構造では上端の角丸が効かない。写真帰属は`card-body`の外にあり、コロンとスラッシュで連結している。

テーマはcupcake（既定）とdarkで、`--radius-box`は1remである。ユーザー向け文字は16px以上とする憲章の制約がある。

## Goals / Non-Goals

**Goals:**

- 7項目の見た目の指摘を、DaisyUIの標準構造と既存のボタン規約で解消する。
- 状態を色付きバッジと文言の両方で示し、色だけに意味を持たせない。
- 出典と写真帰属を、重複のない1か所に置く。
- 一覧と詳細で同じ状態色の対応を使う。

**Non-Goals:**

- 場所artifact、OSM・WheelMapの参照URL、電話・ウェブサイト・Wikipediaの解決、営業時間の評価を変えない。
- 一覧カードに営業状態のバッジを追加しない（今回の対象は詳細の営業状態だけ）。
- `Card`コンポーネントやディスカッション画面のボタンを共通化しない。
- 状態文言を変えない。「一部」の意味はアイコンの代替テキストで補う。

## Decisions

### 1. 表示規約を新しい`location-ui` capabilityに置く

場所のデータ仕様は`location-catalog`・`location-facts`・`wheelchair-accessibility`・`opening-hours`としてメイン仕様に同期済みである。表示の規約はデータ要件から独立してテストでき、既存の要件の振る舞いも変えない。そのため、既存要件を`MODIFIED`で写し直すのではなく、新しい`location-ui`として追加する。状態の写像や営業時間の解釈は既存の仕様をそのまま使う。

### 2. バリアフリー情報はセクションと標準バッジにする

`BarrierDetailBlock`から色付きの入れ子ブロックを削除し、`section`の直下にバッジ、説明文、参照リンク、関連ページを置く。

バッジは`badge badge-lg text-base`に意味色を付け、アイコンと状態文言を入れる。アイコンは`size-5`（20px）とし、バッジの文字（16px）より大きくする。色はバッジの意味色が持つ`*-content`を使うため、アイコンを個別に`text-warning`などで塗らない。

アイコンの代替テキストは、SVGの`aria-label`ではなく、隣に置く`sr-only`の「車いす」で与える。理由は2つある。既存のソース契約テストが`aria-label`による可視文言の上書きを禁じていること、リンクやバッジのアクセシブルな名前を可視文言のまま保てることである。読み上げは「車いす」「一部」の順になる。

状態色の対応は`全面=success`、`一部=warning`、`非対応=error`、`情報なし=neutral`とし、一覧の`BarrierBadge`と詳細で同じ関数を使う。

### 3. 操作ボタンはセカンダリに揃える

編集リンクとバリアフリーの参照リンクを`btn btn-secondary`にする。形は既存の「ここへ行く」に合わせ、`min-h-[44px]`、`text-base`、`rounded-full dark:rounded-sm`、`gap-2`、`whitespace-normal`を使う。編集リンクは`w-full sm:w-auto`のまま上部に置く。

参照リンクの可視文言は、2行に分けず「詳細を見る・編集する（WheelMapを開きます）」の1文にする。支援技術向けの「（新しいタブで開きます）」は`sr-only`で残す。

代替案として、参照リンクを`link`にすることも考えた。しかし外部の編集導線であり、ユーザーが「アウトラインばかり」と指摘した対象でもあるため、セカンダリボタンに揃える。

### 4. 基本情報は行の中央で揃える

`dl.list`の各`list-row`に`items-center`を追加する。リンクの`min-h-[44px]`は残し、行全体の高さの中でdtとddを中央に置く。dtとddの文字サイズはグローバルCSSの16pxのままとする。

代替案として`list`をやめてグリッドの`dl`にすることが考えられるが、DaisyUIの標準構造を残すほうが変更が小さく、区切り線も維持できる。

### 5. 提供元はOSM1件の文にする

提供元セクションは`dl`をやめ、1段落にする。

> 施設情報とバリアフリー情報（wheelchairタグ）は、OpenStreetMap contributors（ODbL 1.0）から提供されています。

「OpenStreetMap contributors」を著作権ページへのリンクにし、新しいタブで開くことを`sr-only`で伝える。これで、バリアフリー情報がOSMの`wheelchair`タグに基づくことを求める既存仕様を1回の言及で満たし、項目列挙と画像行をなくす。

### 6. 一覧カードはカード自体をリンクにする

`LocationSummary`を次の構造にする。

```
<Link class="card ...">          // カード全体がリンク
  <figure>                       // 最初の子。カードの角丸を上端だけ継承
    <img>
  </figure>
  <div class="card-body">
    <h3>
    <バッジと地域>
    <dl>写真 / ライセンス</dl>
  </div>
</Link>
```

`figure`をカードの最初の子にすると、DaisyUIの`card :where(figure:first-child)`が親の角丸を上端にだけ継承し、下端は`unset`にする。`rounded-t-box`のユーティリティに頼らず、標準構造で上端だけ丸くなる。

帰属は`card-body`の中の`dl`にし、`dt`「写真」と`dd`作者、`dt`「ライセンス」と`dd`ライセンス名を`gap-x-4 gap-y-1`で並べる。コロンとスラッシュを使わず、左右の余白もカード本文に揃う。ライセンスはテキストだけにし、詳細ページのリンクへ委ねる。カード内にリンクを入れ子にしないため、リンクの入れ子も避けられる。

代替案として、カードを`div`のままにして内側の`a`と`figure`を維持する方法がある。しかし角丸の継承元が`a`になり、DaisyUIの標準から外れるため採用しない。

### 7. 営業状態をバッジにする

`OpeningHoursSection`の状態表示を`badge`にする。`open`と`all-day`は`badge-success`、`closed`は`badge-error`とし、次に変わる時刻はバッジの外にテキストで添える。解釈できない規則はバッジを出さず、従来どおり規則文と注意書きを表示する。

### 8. 独自の見た目を増やさない

新しいCSSクラスやコンポーネントを作らない。状態色の対応は`BarrierAccessibility.tsx`内の小さな関数にまとめ、一覧と詳細で共有する。カードはDaisyUIの`card`・`figure`・`card-body`、状態は`badge`、操作は`btn`、情報行は`list`を使う。

## Risks / Trade-offs

- [視覚契約テストがクラス名と文言に依存している] → 実装と同じ変更で、意味のある期待（塗りバッジ、代替テキスト、リンクなし、上端だけの角丸）へ更新する。テストはDOM構造とクラスの契約を確認し、見た目そのものは手動確認に委ねる。
- [`btn-secondary`のコントラストが両テーマで不足する] → cupcakeとdarkの`secondary`は`secondary-content`を文字色に持つ。`scripts/check-button-contrast.mjs`が使える環境では実行し、不足する場合は`btn-neutral`へ切り替えるのではなく、テーマ側の色を調整する。
- [カード全体がリンクになり、帰属文までリンク名に入る] → 読み上げが長くなるが、カード内の情報はすべて同じ場所への導線であり、リンクの入れ子を避けられる。詳細ページのライセンスリンクは独立したまま残す。
- [提供元を1件にすると、どの項目がOSM由来か分からなくなる] → 「施設情報とバリアフリー情報」と範囲を明記する。バリアフリー情報の更新導線はセクション内のWheelMapリンクに残る。
- [アイコンの代替テキストが「車いす 情報なし」と読める] → 状態文言は変えないという決定に従う。読み上げの順序は自然で、意味は通る。
- [長いライセンスURIがカード本文で折り返す] → テキストとして折り返しを許す。リンクではないため操作領域の崩れはない。

## Migration Plan

UIだけの変更で、データ移行はない。デプロイ後に一覧と詳細をライト・ダークの両テーマで確認する。問題があれば変更をrevertする。
