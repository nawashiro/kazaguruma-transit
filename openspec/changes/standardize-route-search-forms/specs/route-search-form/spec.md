# Spec Delta

## Purpose

地域福祉交通の経路検索に必要な目的地・出発地・日時・優先条件を、標準のフォーム要素で入力できるようにする。住所の確定と再編集を個別に行い、施設選択やGPS取得を使いながら条件を送信できるようにする。

## ADDED Requirements

### Requirement: 入力グループの初期表示と意味構造

画面は目的地・出発地・日時・優先条件を初期表示からこの順に縦一列で提供しなければならない（SHALL）。関連項目をfieldsetとlegendでまとめ、必要な見出しとsectionを使い、入力とlabelを関連付ける。項目の確定によって次のグループを出現させてはならない。

#### Scenario: 未入力の画面を開く
- **WHEN** 利用者が目的地を指定せず入力画面を開く
- **THEN** 4つの入力グループが最初から存在し、任意のグループを操作できる
- **THEN** 狭い画面と広い画面で表示順と操作順が一致する

### Requirement: 標準フォームによる最終検索

最終検索は名前と値を持つフォーム項目とsubmitボタンで送信しなければならない（SHALL）。住所検索用フォームと最終検索フォームを入れ子にしてはならない。必要な住所が未確定、または日時が不正な場合は結果へ進まず、不足・不正な項目を識別できるようにする。

#### Scenario: 条件を送信する
- **WHEN** 両地点を確定し、有効な日時と優先条件を指定して最終検索フォームを送信する
- **THEN** 座標、日時、出発・到着の区別、優先条件を含む既存形式の結果URLへ遷移する
- **THEN** ポインターによるクリック以外のフォーム送信でも同じ条件が送られる

#### Scenario: 条件が不足している
- **WHEN** 地点が未確定、または日時が空欄・不正な状態で最終検索を試みる
- **THEN** 不完全な条件で経路検索せず、修正すべき項目が分かる
- **THEN** ほかの入力済み条件は保持される

### Requirement: 住所の確定と個別の再編集

住所検索は先頭の検索結果を採用し、確定後は同じfieldset内に住所表示と「なおす」を提供しなければならない（SHALL）。「なおす」は該当地点だけを編集状態に戻す。再編集を始めた地点は再確定するまで最終検索に使用せず、入力画面に全体リセットを置かない。

#### Scenario: 複数の住所検索結果を受け取る
- **WHEN** 名前で検索し、複数の結果が返る
- **THEN** 先頭の住所と座標を確定し、その住所と「なおす」を表示する

#### Scenario: 確定した住所を直す
- **WHEN** 利用者が目的地の「なおす」を押す
- **THEN** 目的地を再入力でき、出発地・日時・優先条件は変わらない
- **THEN** 目的地を再確定するまで以前の座標で最終検索されない

#### Scenario: 住所検索が失敗する
- **WHEN** 検索結果がない、または住所検索に失敗する
- **THEN** 該当地点の入力と関連付けたエラーを表示し、入力内容とほかの条件を保持する

### Requirement: GPSと目的地リンクの継続利用

GPS取得は「端末のGPSを許可する」というボタンから開始し、施設詳細から渡された目的地も確定済みの地点として利用できなければならない（SHALL）。GPSで座標を取得できた場合、住所の逆引きだけが失敗しても座標を出発地として使えるようにする。

#### Scenario: GPSを使用する
- **WHEN** 利用者が「端末のGPSを許可する」を押し、位置情報を取得できる
- **THEN** 出発地を確定し、ほかの条件を保持する
- **THEN** 住所の逆引きに失敗した場合は座標を表示して続行できる

#### Scenario: GPS取得を拒否する
- **WHEN** 位置情報の利用を拒否する、または取得に失敗する
- **THEN** 出発地に取得失敗を表示し、名前による検索を利用できる

#### Scenario: 施設詳細から入力画面を開く
- **WHEN** 有効な既存形式の目的地パラメーター付きリンクで入力画面を開く
- **THEN** 指定された目的地と「なおす」を表示し、ほかの入力グループも最初から表示する

### Requirement: 日時と優先条件の選択

日時は端末の現在日時と出発時刻の選択を初期値とし、固定ラベル「日時」で提供しなければならない（SHALL）。優先条件は「なるべく歩きたくない、時間がかかってもいい」と「歩いてもいい、早く着きたい」の排他的なラジオボタンとし、localStorageの既存設定を読み書きする。未保存時は前者を選択する。

#### Scenario: 初期値と出発・到着を操作する
- **WHEN** 未保存の端末で入力画面を開き、出発時刻から到着時刻へ変更する
- **THEN** 初期日時は端末の現在日時で、ラベル「日時」と入力済み日時は変更されない
- **THEN** 初期の優先条件は「なるべく歩きたくない、時間がかかってもいい」である

#### Scenario: 優先条件を保存して送信する
- **WHEN** 「歩いてもいい、早く着きたい」を選び、画面を再度開いて検索する
- **THEN** 同じ条件が復元され、結果URLにははやさ優先が明示される
- **THEN** この選択で歩行速度自体は変更されない

### Requirement: 施設カテゴリの折りたたみ一覧

施設カテゴリは標準のdetailsとsummaryで縦に並べ、施設をリストで提供しなければならない（SHALL）。施設名を省略せず折り返し、箇条書きの代わりのピンアイコンを置かない。カテゴリと施設一覧に固定の高さ制限や内部スクロールを設けず、ページ全体でスクロールできるようにする。

#### Scenario: カテゴリを開いて施設を選ぶ
- **WHEN** 利用者がキーボードでカテゴリを開き、施設を選ぶ
- **THEN** 施設が目的地として確定し、ほかの入力グループは表示されたままである

#### Scenario: 長い名前を狭い画面で読む
- **WHEN** 320 CSS px相当の表示幅で長いカテゴリ名と施設名を表示する
- **THEN** 名前を全文読め、一覧内またはページの横スクロールを必要としない

### Requirement: 入力画面のスタイルと名前

入力画面は既存テーマと背景・枠線付きのfieldsetを使い、確定住所を別カードにしない構成で表示しなければならない（SHALL）。ルビ以外の利用者向け文字は算出サイズ16px以上とする。可視ラベルのあるGPS・日時・優先条件はそのラベルをアクセシブルな名前に使い、エラー説明の関連付けは保持する。

#### Scenario: フォームを表示して読み上げる
- **WHEN** 初期状態または住所確定後のフォームを表示する
- **THEN** 各グループを区別でき、住所のための追加カードは生成されない
- **THEN** GPS・日時・優先条件の名前は可視ラベルと一致し、エラーがあれば該当項目から参照できる
- **THEN** ライト・ダークの両テーマで文字サイズ条件を満たす
