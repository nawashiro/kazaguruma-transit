# Spec Delta

## Purpose

URLで指定された地域福祉交通の検索条件から、サーバーで検索した経路情報をHTMLとして提供する。利用制限とエラー表示を保ち、Nostrやファイル出力などブラウザで動く機能を待たずに経路本文を読めるようにする。

## ADDED Requirements

### Requirement: 経路本文のサーバー描画

結果ページは指定された条件の検索と経路本文のHTML生成をサーバーで行わなければならない（SHALL）。経路、停留所、時刻、乗換情報、地図リンクの表示を、ブラウザからの経路API取得やNostr取得の完了に依存させてはならない。

#### Scenario: 有効な条件で結果URLを開く
- **WHEN** 有効な検索条件の結果URLを直接開く
- **THEN** サーバーから返るHTMLに検索結果の経路本文が含まれる
- **THEN** 経路本文を表示するためにブラウザから経路APIを再取得しない

#### Scenario: 検索条件を変えて開く
- **WHEN** 日時、地点または優先条件が異なる結果URLを開く
- **THEN** 指定した条件に対応する結果を表示し、別条件の結果を混在させない

### Requirement: URLとAPIの互換性

結果URLは既存の座標・日時・出発到着・優先条件の形式を受け付け、結果の判断を端末の保存設定に依存させてはならない（SHALL）。既存の経路APIのGET・POST契約も維持する。

#### Scenario: 保存済みの結果URLを開く
- **WHEN** 既存形式の有効な結果URLを、異なるlocalStorage設定の端末で開く
- **THEN** URLで指定された条件で検索し、端末設定で優先条件を上書きしない

#### Scenario: 既存のAPIを呼ぶ
- **WHEN** 既存形式で経路APIにGETまたはPOSTを送る
- **THEN** 既存の入力形式、成功・失敗のレスポンス形式を維持する

### Requirement: 検索失敗と利用制限

結果ページは条件不正、経路なし、検索処理の失敗を識別できる表示を提供しなければならない（SHALL）。サーバー描画経由でも既存の利用制限を適用し、上限到達時は`/rate-limit?source=routes`へ案内する。検索経路を変えることで利用制限を迂回したり、1回の検索を二重計上したりしてはならない。

#### Scenario: 条件が不正である
- **WHEN** 必須パラメーターが不足、または座標・日時・真偽値が不正である
- **THEN** 条件不正を日本語で表示し、経路計算は実行しない
- **THEN** 入力画面へ戻るリンクを利用できる

#### Scenario: 経路がない
- **WHEN** 検索処理は成功したが該当経路がない
- **THEN** 経路がない旨をHTMLで表示し、入力画面へ戻れる

#### Scenario: 検索処理が失敗する
- **WHEN** サーバーの経路取得に失敗する
- **THEN** 日本語のエラーと入力画面へ戻るリンクを表示する

#### Scenario: 利用制限に達する
- **WHEN** 同じ利用者の検索が既存の利用上限に達する
- **THEN** サーバー描画の結果ページでも利用制限画面へ案内する
- **THEN** 経路APIを直接使った場合と同じ制限を受ける

### Requirement: クライアント機能の独立

Nostrに関係する表示とPDF・カレンダー出力は、必要なクライアント処理を保持しなければならない（SHALL）。それらの初期化や失敗で経路本文を隠してはならない。掲示板機能の有効・無効設定と、既存のPDFへのメモ連携を維持する。

#### Scenario: Nostr取得が遅延または失敗する
- **WHEN** 経路がある状態でNostr取得が遅れる、または失敗する
- **THEN** 経路本文と地図リンクを読める状態を維持する
- **THEN** PDF・カレンダーの既存操作が、経路データを受け取った状態で利用できる

#### Scenario: 掲示板機能を無効にする
- **WHEN** 掲示板機能が無効な設定で結果を表示する
- **THEN** Nostr取得を開始せず、経路本文と出力操作を表示する

### Requirement: ルビ有効時のPDF・カレンダー出力

通常のスクリプト読み込みでRubyfulを有効にしたあとも、PDFとカレンダーの既存出力を利用できなければならない（SHALL）。ON / OFF切替後も経路本文、経路データとPDF用メモを保持し、ルビを無効にせず出力を完了できることとする。

#### Scenario: 通常読み込み後にPDFとカレンダーを出力する
- **WHEN** 経路のある結果画面で通常のスクリプト読み込み後にルビが有効になり、PDFとカレンダーの出力をそれぞれ実行する
- **THEN** 既存形式のPDFとカレンダーを出力し、地点・時刻・経路とPDF用メモの連携を維持する
- **THEN** 出力中と完了後も経路本文と操作を維持し、状態更新による実行時エラーが発生しない

#### Scenario: ルビ切替後に出力を繰り返す
- **WHEN** 利用者がルビをOFF、ONへ繰り返し切り替えたあと、PDFとカレンダーの出力をそれぞれ繰り返す
- **THEN** 切替前と同じ経路データを使って出力を完了し、経路本文と利用可能なPDF用メモを保持する
- **THEN** 切替後も対象ラベルのルビ表示を利用できる

### Requirement: 検索結果の意味構造とスタイル

結果ページは経路情報を見出し・リスト・区切り線で整理し、カードの多重囲みを使わずに表示しなければならない（SHALL）。既存テーマと統一したスタイルを使い、ルビ以外の利用者向け文字を算出サイズ16px以上とする。各乗車区間は乗車停留所・路線名・降車停留所の順に示し、路線名と停留所名は同じ文字サイズとする。ページのh1と重複する「経路」見出しは置かない。全体リセットは表示せず、入力画面へ戻る通常のリンクを提供する。

#### Scenario: 直通と乗換の結果を表示する
- **WHEN** 直通または乗換の経路を表示する
- **THEN** 経路と各区間の関係を見出し・リストから理解できる
- **THEN** 320 CSS px相当の幅でも時刻と停留所名を省略せず読める
- **THEN** ライト・ダークの両テーマで路線名と停留所名の算出フォントサイズが同じで16px以上となる
- **THEN** 各乗車区間のDOM順と表示順が乗車停留所・路線名・降車停留所となり、ページのh1に加えて重複する「経路」見出しを表示しない
- **THEN** 「検索条件をリセット」ではなく、入力画面へ戻るリンクを利用できる

#### Scenario: ルビ付きの戻るリンクを読む
- **WHEN** ルビを有効にした結果画面で「入力画面に戻る」リンクを表示する
- **THEN** 基底文字とルビはインラインの文章として表示され、単語やルビごとに別の行へ分割されない
- **THEN** 狭い画面で自然に折り返しても文として読め、リンクの読み上げ名と遷移先を保つ

### Requirement: 開発環境と本番環境での結果操作

開発環境と本番環境のどちらでも、結果画面のJavaScriptを構文エラーなく実行し、ルビ切替とPDF・カレンダー出力を利用できなければならない（SHALL）。開発時に観測した文字列のSyntaxErrorを修正し、結果URLへの直接アクセスと入力画面からの遷移でも操作を保つ。

#### Scenario: 両環境で結果を開いて出力する
- **WHEN** 各環境で結果を直接開く、または入力画面から遷移し、通常読み込み後にルビをON / OFFしてPDFとカレンダーを出力する
- **THEN** JavaScriptのSyntaxErrorや状態更新による実行時エラーが発生せず、経路本文を読め、両方のダウンロードが完了する
- **THEN** 地点・日時・経路と利用可能なPDF用メモを保持する
