# Design

## Context

daisyUI 5.7はTailwindのプラグインとして導入済みで、既存の戻るリンクは`btn`系のクラスと`link`クラスの混在である（提案の動機はproposal.mdを参照）。ページ先頭の見出しは`PageHeader`コンポーネントが担い、h1の上の要素は各ページが個別に描画している。

## Goals / Non-Goals

**Goals:**

- パンくずをPageHeaderの一部として描画し、「h1より上」という配置を構造で保証する。
- DaisyUI breadcrumbsの構造（nav、ul、li）をそのまま使う。

**Non-Goals:**

- パンくずの見た目の新規設計。DaisyUIの既定のスタイルとテーマ変数に任せる。
- 親階層の自動推定。各ページがパンくずの項目を渡す。
- 会話機能のタブナビゲーション（`DiscussionTabLayout`）の変更。パンくずはタブより上に置く。

## Decisions

**PageHeaderに省略可能な`breadcrumbs`スロットを足す。** パンくずの描画をPageHeaderの外に置くと、各ページが配置を覚えて守ることになる。スロットにすれば、h1より上という不変条件が一つのコンポーネントで保証され、Lintやレビューに頼らず守れる。項目（ラベル、href、現在位置かどうか）だけをページが渡し、構造は共通の小コンポーネントに任せる。

**パンくずの項目はプレーンなオブジェクト配列で受け取る。** JSXをスロットに渡す方式よりも、ページごとの書きぶれを防ぎ、テストで構造を検証しやすい。現在位置の`aria-current`は、配列の最終項目として渡されたときに共通コンポーネントが付ける。

**場所詳細の`LocationBackLink`をパンくずの項目生成に置き換える。** 現状はカテゴリが判明するときカテゴリにしか戻れないが、パンくずなら場所一覧とカテゴリの両方へ戻せる。代替として既存の単一リンクを残す案があったが、KISSの原則から二重実装はしない。

**経路検索結果の戻るリンクはRouteSearchResultsから外し、ページ側のパンくずへ移す。** ナビゲーションは結果コンポーネントではなくページ階層が担う。エラー・制限済み・正常のどの状態でもパンくずはページ先頭に表示される。

## Risks / Trade-offs

- [会話画面でパンくずとタブの視覚的な重なりが乱れる] → DiscussionTabLayoutの間隔（余白）をパンくずの高さに合わせて調整し、visual-contractテストで確認する。
- [パンくずの現在位置とh1の文字列の重複で読み上げが冗長になる] → 現在位置はページ名を省略せずそのまま渡し、読み上げの冗長さより「今どこにいるか」の明示を優先する。実装後に支援技術での読み上げを確認する。
- [ルビ有効時の折り返し] → 既存の「ルビ付きの戻るリンク」のテストをパンくず向けに移し替え、インラインでの表示と折り返しを検証する。

## Migration Plan

PageHeaderのスロット追加は既存の呼び出しに影響しない（省略可能なため）。置き換えは画面単位で進め、各画面のテストを同時に移し替える。戻す場合は各画面のリンクを元に戻すだけでよく、データ移行はない。
