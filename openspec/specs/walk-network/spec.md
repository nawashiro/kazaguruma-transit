# walk-network Specification

## Purpose
歩ける道のネットワークをビルド時に確定し、徒歩距離を実際の経路の長さで測れるようにする。直線距離に係数を掛ける近似を廃止し、同じデータから経路の形も取り出せるようにする。

## Requirements

### Requirement: 徒歩ネットワークartifactの形式

徒歩ネットワークは、リポジトリに置く生成物`data/walk-network.json`として保持しなければならない（MUST）。ファイルはノードとエッジの2つの配列を持ち、ノードは`[OSMノードID, 緯度×10^6, 経度×10^6]`、エッジは両端のOSMノードIDの組`[a, b]`とする（MUST）。エッジの長さは両端の座標からハバーサインで求める。1要素を1行に書き、要素の並びはIDの昇順とする（MUST）。

#### Scenario: 徒歩ネットワークを読む

- **WHEN** 実行時が`data/walk-network.json`を読む
- **THEN** ノードのOSMノードIDと座標、およびエッジの両端のIDが得られる
- **THEN** 各エッジの長さは両端の座標から計算できる

#### Scenario: 同じ入力から作り直す

- **WHEN** 同じOSM抽出から徒歩ネットワークを作り直す
- **THEN** ノードとエッジの並びは前回と同じになる

### Requirement: 徒歩ネットワークの対象範囲

徒歩ネットワークは、千代田区の町字ポリゴンの内側にあるノードと、いずれかの停留所から300メートル以内にあるノードを含めなければならない（MUST）。エッジは両端のノードが対象範囲にあるものだけを含める（MUST）。さらに、ノードとエッジは最大の連結成分だけを残す（MUST）。

#### Scenario: 区の外にある道を含めない

- **WHEN** 町字ポリゴンの外にあり、どの停留所からも300メートルを超える道がある
- **THEN** その道は徒歩ネットワークに含まれない

#### Scenario: 建物の下の停留所をつなぐ

- **WHEN** 停留所が区の外側にある建物の中にあり、最寄りの歩行ノードが町字ポリゴンの外にある
- **THEN** そのノードは停留所から300メートル以内であるため含まれる

#### Scenario: つながらない道を除く

- **WHEN** 対象範囲に、最大の連結成分とつながらない小さな歩道がある
- **THEN** その歩道のノードとエッジはartifactに含まれない

### Requirement: 徒歩ネットワークの更新と出典

徒歩ネットワークは作業者の明示的なコマンド`npm run update-walk-network`で更新しなければならない（MUST）。更新は地点索引と同じOSM抽出のキャッシュを共用する（MUST）。ビルドと起動はartifactを読むだけで、外部へ取得要求をしてはならない（MUST NOT）。fileの内容が前回と同じときは書き換えず、そのことを報告する（MUST）。

#### Scenario: 作業者が更新する

- **WHEN** 作業者が`npm run update-walk-network`を実行する
- **THEN** 地点索引と同じキャッシュのOSM抽出から徒歩ネットワークを生成し、`data/walk-network.json`を書き換える

#### Scenario: 内容が変わっていない

- **WHEN** 更新コマンドを実行し、生成結果が前回と同じである
- **THEN** ファイルを書き換えず、書き換えなかったことを報告する

#### Scenario: ビルドする

- **WHEN** アプリケーションをビルドまたは起動する
- **THEN** 外部から徒歩ネットワークを取得せず、リポジトリのartifactを読む

### Requirement: 徒歩距離の定義

徒歩距離は、起点から徒歩ネットワークの最寄りノードまでの直線距離、そのノードから到着点の最寄りノードまでのネットワーク上の最短距離、到着点の最寄りノードから到着点までの直線距離の和としなければならない（MUST）。直線距離に係数を掛けた近似を徒歩距離として使ってはならない（MUST NOT）。到着点が停留所のときは、停留所の座標までの接続区間を含める。

#### Scenario: 道の上にある2地点の距離

- **WHEN** 2地点のどちらも徒歩ネットワークのノードの上にある
- **THEN** 徒歩距離はネットワーク上の最短距離になる

#### Scenario: 道から離れた地点の距離

- **WHEN** 出発地が建物の中にあり、最寄りのノードまで40メートルある
- **THEN** 徒歩距離は40メートルとネットワーク上の距離の和になる

#### Scenario: 直線距離の補正を使わない

- **WHEN** 徒歩距離を求める
- **THEN** 直線距離に√2を掛けた値を距離として返さない

### Requirement: 徒歩距離の対称性

同じ2地点の徒歩距離は、向きを入れ替えても同じ値でなければならない（MUST）。接続区間とネットワーク上の距離の和は、両端で同じ計算をする。

#### Scenario: 向きを入れ替える

- **WHEN** 出発地と目的地を入れ替えて徒歩距離を求める
- **THEN** 2つの値は一致する

### Requirement: 徒歩時間の算出

徒歩時間は、徒歩距離を歩行速度で割って求めなければならない（MUST）。歩行速度は`TRANSIT_PARAMS.WALKING_SPEED_KM_H`を使う。直線距離を入力に取る時間計算を残してはならない（MUST NOT）。

#### Scenario: 徒歩時間を求める

- **WHEN** 徒歩距離が600メートルで、歩行速度が時速3キロメートルである
- **THEN** 徒歩時間は12分になる

#### Scenario: 補正係数を通さない

- **WHEN** 徒歩時間を求める
- **THEN** 距離に√2を掛け直さない

### Requirement: 徒歩経路の折れ線

徒歩距離を求めたとき、その経路の折れ線を`[経度, 緯度]`の配列として取り出せなければならない（MUST）。折れ線は起点、通過したノードの座標、到着点の順に並べる（MUST）。経路検索の結果は、出発地から乗車停留所までと、降車停留所から目的地までの折れ線をPDF生成へ渡さなければならない（MUST）。

#### Scenario: 折れ線を取り出す

- **WHEN** 出発地から乗車停留所までの徒歩距離を求める
- **THEN** 起点と到着点を含み、通過したノードを順に並べた座標列が得られる

#### Scenario: PDFへ渡す

- **WHEN** 経路のある検索結果からPDFを生成する
- **THEN** 徒歩区間の折れ線がPDF生成の要求に含まれる

### Requirement: 徒歩ネットワークを読めないときの挙動

徒歩ネットワークを読み込めない、または形式が不正なときは、経路検索をエラーとして返さなければならない（MUST）。直線距離による判定へ切り替えてはならない（MUST NOT）。

#### Scenario: artifactがない

- **WHEN** `data/walk-network.json`が存在しない状態で経路検索をする
- **THEN** 検索はエラーを返し、直線距離で経路を返さない

#### Scenario: artifactが壊れている

- **WHEN** artifactの形式が不正である
- **THEN** 検索はエラーを返し、外部サービスへ代替の要求を送らない
