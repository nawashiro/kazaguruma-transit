# Feature Specification: 認証・場所詳細・レート制限の専用ページ化

**Feature Branch**: `fix/issue-67-semantic-a11y-navi`

**Created**: 2026-08-14

**Status**: Approved

**Input**: User description: "ダイアログを無理に設置せず、ログインとアカウント作成、場所詳細、レート制限を専用ページとして提供する。ログインとサインアップは相互にリンクし、場所詳細は専用URLから開けるようにする。既存の主要操作と見た目を維持しながら、ダイアログ固有の複雑なアクセシビリティ処理を減らす。仕様作成にはSpecifyを使用する。"

> この仕様は、Issue #67の「可能な範囲でネイティブ部品を優先する」という目的を、ダイアログ統一ではなく通常のページ遷移で達成する案として整理する。既存の認証、場所データ、レート制限の意味は変更せず、利用者が直接開ける文書ページとして公開する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ログインとアカウント作成を専用ページで行う (Priority: P1)

利用者は、ログインが必要な投稿・評価・設定の操作から、通常のログインページまたはアカウント作成ページへ移動できる。ログインページとアカウント作成ページはそれぞれ独立したフォームを持ち、互いに移動できる。利用者は、タブウィジェットやダイアログを操作しなくても認証を完了できる。

**Why this priority**: 認証は複数の画面から呼ばれる共通経路であり、専用ページ化によるアクセシビリティ改善の効果が最も広い。

**Independent Test**: 未認証状態の設定画面またはDiscussion画面からログイン導線を開き、ページ見出し、フォームラベル、認証処理、エラー表示、ログイン・アカウント作成間のリンクを単独で確認できる。

**Acceptance Scenarios**:

1. **Given** 利用者が未認証でログインが必要な操作を開始した、**When** ログイン導線を選択する、**Then** 利用者は専用のログインページへ移動し、ページの主見出しとログインフォームを確認できる。
2. **Given** 利用者がログインページを表示している、**When** アカウント作成へのリンクを選択する、**Then** 専用のアカウント作成ページへ移動する。
3. **Given** 利用者がアカウント作成ページを表示している、**When** ログインへのリンクを選択する、**Then** 専用のログインページへ移動する。
4. **Given** 認証処理が失敗した、**When** 認証結果が表示される、**Then** フォームの入力内容を不必要に失わず、日本語のエラー内容をフォーム付近で確認できる。
5. **Given** 認証処理が成功した、**When** ページが完了状態になる、**Then** 利用者は安全な同一サイト内の戻り先へ移動できる。

### User Story 2 - 場所詳細を直接開いて確認する (Priority: P1)

利用者は、場所一覧のカードまたは共有された場所詳細URLから、場所の詳細を通常のページとして開ける。ページには場所名、説明、地域、提供情報、ライセンス、外部サイトへのリンク、目的地として設定する主要操作が表示される。

**Why this priority**: 場所詳細は独立した情報資源であり、ダイアログよりも戻る・再読み込み・共有・直接アクセスに適したページとして扱える。

**Independent Test**: 場所一覧から一意な場所詳細リンクを選択し、詳細ページの主見出し、本文、提供情報、リンク、目的地設定、無効な識別子のエラー状態を確認できる。

**Acceptance Scenarios**:

1. **Given** 場所一覧に有効な場所が表示されている、**When** 場所詳細リンクを選択する、**Then** 一意な場所を表す専用URLへ移動し、場所名が主見出しとして表示される。
2. **Given** 利用者が有効な場所詳細URLを直接開いた、**When** 場所データの読み込みが完了する、**Then** 一覧ページを経由せずに説明、地域、提供情報、ライセンス、外部リンクを確認できる。
3. **Given** 詳細ページに目的地設定の操作が表示されている、**When** 利用者がその操作を選択する、**Then** 既存のホーム画面の目的地設定へ移動し、対象場所が目的地として引き継がれる。
4. **Given** URLの場所識別子が存在しない、**When** 詳細ページを開く、**Then** 空の詳細を表示せず、場所が見つからないことと一覧へ戻る導線を日本語で表示する。
5. **Given** 場所データの取得に失敗した、**When** 詳細ページを開く、**Then** IDが存在しない場合とは異なるデータ取得失敗の説明と一覧へ戻る導線を日本語で表示し、空の詳細を表示しない。

### User Story 3 - レート制限を専用ページで理解して再試行する (Priority: P1)

利用者は、住所検索などがレート制限に達したとき、ダイアログに閉じ込められず、専用のレート制限ページで制限内容と次の行動を確認できる。利用者は発生元に対応する許可済みページへ戻るか、ブラウザの戻る操作で元の画面へ戻れる。

**Why this priority**: レート制限は検索フローを中断する状態であり、認証・場所詳細と同じく通常ページにすると、説明、履歴、再読み込みを標準的な文書遷移で扱える。

**Independent Test**: レート制限状態を発生させ、専用ページへの遷移、制限説明、主見出し、発生元に対応する戻り導線、再表示時の主要操作を確認できる。

**Acceptance Scenarios**:

1. **Given** 住所検索がレート制限状態になった、**When** その結果を利用者へ通知する、**Then** 専用のレート制限ページへ移動し、制限時間または再試行に関する説明を表示する。
2. **Given** 利用者がレート制限ページを表示している、**When** 発生元に対応する戻り導線を選択する、**Then** 許可済みの固定ページへ戻り、レート制限ページの表示状態だけを理由に同じ検索またはAPI要求を自動送信しない。
3. **Given** 利用者がレート制限ページを再読み込みまたは直接開いた、**When** ページを表示する、**Then** 認証や場所データを要求せず、説明と戻り導線を安定して表示する。
4. **Given** レート制限がホーム、場所検索、経路検索のいずれかで発生した、**When** 利用者がレート制限ページの戻り導線を選択する、**Then** 許可済みの発生元に対応する固定された同一サイト内ページへ移動し、任意のURLへは移動しない。

### User Story 4 - 通常ページとしてキーボードと支援技術で移動する (Priority: P2)

利用者は、専用ページ間を通常のリンク、見出し、フォーム、ボタンで移動できる。ページを開いたときはページタイトル、主見出し、主要ランドマーク、操作名が一貫しており、ダイアログ専用のフォーカス捕捉・復帰を必要としない。

**Why this priority**: ページ遷移へ設計を変える主目的は、複雑なダイアログ挙動ではなく、標準的な文書構造を検証可能にすることである。

**Independent Test**: 各専用ページをキーボードだけで開き、主見出し、フォームコントロール、エラー表示、戻る・相互リンク、主要操作へ到達できることを確認する。

**Acceptance Scenarios**:

1. **Given** 利用者が専用ページを開いた、**When** ページ内をキーボードで移動する、**Then** 操作可能なリンク・ボタン・フォームへ論理的な順序で到達できる。
2. **Given** 利用者が専用ページを開いた、**When** 支援技術がページ構造を読む、**Then**主見出し、フォームラベル、エラーまたは状態メッセージ、リンク目的を識別できる。
3. **Given** 利用者がページから元の画面へ戻る、**When** ブラウザの戻る操作または明示的な戻るリンクを使う、**Then**利用者は予期しないダイアログ状態や重複した送信状態なしに元の画面へ戻れる。

### Edge Cases

- ログイン・アカウント作成ページを直接開いた場合でも、戻り先が指定されていなければ安全な既定ページへ移動する。
- 外部サイトを戻り先として指定された場合は、その値を遷移に使用せず、同一サイト内の既定ページへ移動する。
- パスキーのキャンセル、未対応機能、既存アカウント不在、利用規約未同意などの既存エラーを、ページ上のフォーム状態として表示する。
- 場所データの読み込み中、識別子不一致、重複・不正ID、データ取得失敗、説明文や画像がない場合に、状態を混同せず見出し・主情報・戻り導線を失わない。
- レート制限ページを複数回開いても、表示だけで同じ検索または外部API要求を繰り返さない。
- レート制限ページの発生元が未指定または不正な場合は、許可済みの既定ページへ戻し、任意のreturn URLを解釈しない。
- キーボード利用時に、リンクとボタンの目的が視覚的な位置や色だけに依存しない。
- 認証成功後に元の画面へ戻っても、認証前に開始しかけた投稿・評価などの副作用を無断で自動再実行しない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ログインを専用の`/login`ページで提供しなければならない。
- **FR-002**: システムは、アカウント作成を専用の`/signup`ページで提供しなければならない。
- **FR-003**: `/login`と`/signup`は、互いに目的が明確な通常リンクで移動できなければならない。認証のためにタブウィジェットやダイアログを必須としてはならない。
- **FR-004**: ログインページとアカウント作成ページは、既存のパスキー認証・アカウント作成処理、パスキー名、規約同意、読み込み中、失敗、キャンセルの意味を維持しなければならない。
- **FR-005**: 認証フォームの各入力と同意操作は、表示上およびプログラム上の名前を持ち、エラーは該当するフォーム操作と関連付けて確認できなければならない。
- **FR-006**: 認証成功後の戻り先は、安全な同一サイト内の元の画面とし、認証前に開始しかけた投稿・評価操作は自動再開せず、利用者が元の画面で明示的に再操作するまで実行してはならない。
- **FR-007**: システムは、場所一覧の各場所を、通常のリンクとして一意な場所識別子を含む専用詳細ページへ移動できるようにしなければならない。
- **FR-008**: 場所詳細ページは、場所名を主見出しとし、説明、地域、提供情報、ライセンス、外部サイトへのリンク、既存の目的地設定操作を表示しなければならない。
- **FR-009**: 場所詳細ページは、場所識別子を`/location-detail/[id]`のパスに含め、直接アクセス・再読み込み・ブラウザ履歴から同じ場所を復元できなければならない。
- **FR-010**: 場所データの取得が成功したうえで未知の識別子を受け取った場合、システムは`not-found`状態として場所が見つからないことを日本語で説明しなければならない。重複・不正な識別子は`error`状態、CDN等のデータ取得失敗は`data-load-error`状態として扱い、未知IDと異なる原因を日本語で説明しなければならない。いずれの状態でも空の詳細を表示せず、場所一覧または安全な既定ページへの導線を提供する。
- **FR-011**: システムは、レート制限状態を専用の`/rate-limit`ページで表示しなければならない。
- **FR-012**: `/rate-limit`は、レート制限の理由、再試行の目安、発生元へ戻る導線を表示し、ページ表示だけで同じ検索要求または外部API要求を送信してはならない。戻り先は許可済みの発生元識別子に限り、`home`は`/`、`locations`は`/locations`、`routes`は`/`へ移動し、未指定または不正な値は`/locations`へ移動しなければならない。
- **FR-013**: 専用ページは、ページタイトル、主見出し、主要ランドマーク、論理的な見出し順、通常のリンク・ボタン・フォームを提供し、ダイアログ固有のフォーカス捕捉・復帰・backdrop・Escape処理を必要とする設計にしてはならない。
- **FR-014**: 既存の見た目、主要操作、認証のデータフロー、場所の目的地設定、レート制限の意味を、専用ページへの移行によって意図せず変更してはならない。
- **FR-015**: システムは、認証、場所詳細、レート制限の各専用ページについて、主導線、直接アクセス、読み込み中、成功、失敗、戻り導線、キーボード操作を検証するテストを提供しなければならない。
- **FR-016**: 本featureは、新しい認証方式、新しい永続データ、新しい外部APIレート制限、または既存の場所データ形式を導入してはならない。

### Key Entities

- **Authentication Page**: ログインまたはアカウント作成を行う独立したページ。ページ種別、フォーム状態、既存のパスキー操作、エラー、戻り先を持つ。
- **Safe Return Target**: 認証成功後に戻る同一サイト内のページ。外部URLを含めず、未指定時の既定ページを持つ。
- **Location Detail Page**: 一意な場所識別子に対応する詳細情報を表示するページ。場所名、説明、地域、提供情報、ライセンス、外部リンク、目的地設定操作を持つ。
- **Rate Limit Page**: レート制限の理由と再試行の案内を表示する説明ページ。検索を自動再実行せず、許可済みの発生元識別子に対応した固定ページへの戻り導線を持つ。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 未認証状態からログインまたはアカウント作成を開始する主要導線が、タブやダイアログを経由せず、2回以内の明示操作で対応する専用ページへ到達できる。
- **SC-002**: `/login`と`/signup`の両ページで、キーボードだけを使って主見出し、全フォーム操作、相互リンク、エラー表示、送信操作へ到達できる。
- **SC-003**: 有効な場所識別子を持つ場所詳細URLを直接開いたとき、一覧ページを先に開かなくても、場所名と主要詳細情報が表示される。
- **SC-004**: レート制限状態の発生後、専用ページに表示される説明と発生元に対応する戻り導線が100%の対象ケースで確認でき、ページ表示による重複検索・API要求が0件である。
- **SC-005**: 認証、場所詳細、レート制限の主導線、直接アクセス、成功、失敗、戻り導線を対象とする変更テストがすべて成功する。
- **SC-006**: Issue #67の作業単位1〜3で改善済みの入力ラベル、通常ナビゲーション、ネイティブラジオ、既存の主要操作と見た目が退行しない。
- **SC-007**: 場所詳細で未知ID、重複・不正ID、CDNデータ取得失敗を個別に発生させたとき、それぞれの原因に対応する状態・日本語説明・戻り導線が表示され、同じ空詳細へ収束しない。

## Assumptions

- 既存のパスキー認証コンテキストとブラウザ内の認証情報をそのまま利用し、新しい認証方式やサーバー側セッションを追加しない。
- `/login`、`/signup`、`/rate-limit`を専用URLの既定値とする。
- 場所詳細は一意な既存場所識別子で解決でき、`/location-detail/[id]`で表現する。
- 場所詳細から既存ホーム画面へ目的地を渡す動作は維持する。
- 認証前に開始した投稿・評価の副作用は、明示的な再確認なしには再実行しない。
- レート制限の閾値、時間窓、外部APIのポリシーは変更しない。
- 専用ページは既存の共通レイアウト、ルビ表示方針、レスポンシブ方針を利用し、大規模な配色・レイアウト変更は行わない。

## Out of Scope

- native `<dialog>`の実装を3コンポーネントで統一すること。
- ダイアログのfocus trap、backdrop、Escape、form[method="dialog"]を新規に設計すること。
- 新しい認証方式、パスワードリセット、メール認証、サーバーセッションを追加すること。
- 投稿・評価などの認証前副作用を自動的に再実行するための永続化または複雑な一時状態を追加すること。
- 場所データの収集元、レート制限ポリシー、目的地設定のドメインロジックを変更すること。
- DaisyUIやUIコンポーネントライブラリの全面移行、大規模な配色変更を行うこと。
