# Feature Specification: 場所データページのJavaScript削減

**Feature Branch**: `023-location-data-pages`

**Created**: 2026-09-06

**Status**: Draft

**Input**: Issue #79「chor: jsに頼りすぎている。シンプルに、URIとページにできる。」のうち、場所データ関連（`/locations`、よく利用される施設、場所カテゴリ、場所詳細）を対象とする。主眼はブラウザ側JavaScriptの削減であり、サーバーサイドレンダリング（SSR）と静的サイト生成（SSG）の選択は手段として計画段階で決める。経路検索フォームの責務整理は別feature・別PRで扱う。

## Clarifications

### Session 2026-09-06

- Scope: Issue #79を「場所データ関連」と「経路検索フォーム関連」に分割する。今回の仕様とPRは場所データ関連だけを扱い、経路検索フォームの段階的入力、意味論的HTML化、ホーム側のJavaScript状態整理は別feature・別PRへ送る。
- Baseline: 現行の経路検索結果URL（`/routes`）と検索条件のURI化は既存仕様 `016-bookmarkable-route-results` の契約として扱い、本featureで再設計しない。
- Q1: 既存の場所詳細URL `/location-detail/[id]` は互換リダイレクトを追加せず廃止し、場所詳細の正規URLを `/locations/location-detail/[id]` とする。これはSSGの必須条件ではなく、場所一覧配下の情報階層をURLにも反映するための設計判断である。
- Q2: SSGは必須条件ではなく、SSRまたはSSGを選択できる。共通条件は、場所データをサーバー側のデータ取得境界で扱い、空・不完全な場所データを成功状態として公開しないこととする。SSGを選ぶ場合は取得・検証失敗でビルドを失敗させ、SSRを選ぶ場合は日本語の取得失敗状態を表示する。
- Q3: `[category-id]` は既存の `category:en` を正本とし、その値をURLエンコードして表現する。別のASCII slugやカテゴリ対応表は追加しない。
- Q4: 本featureの主眼はSSG導入ではなく、ブラウザ側JavaScriptを減らすことである。ページ全体を静的化することや、利用者操作に必要なJavaScriptまで一律に削除することは要求しない。
- Q5: 「近いところから表示」は維持するが、GPSによる「近い順に並べる」と、GPSを使わない「町字で並べる」の2つの表示操作に縮小する。場所名・住所による検索、Google Maps APIやジオコーディングへの依存、入力欄は削除する。
- Q6: 場所カテゴリのタブは、カテゴリURLを持つ共通レイアウトのナビゲーションへ置き換える。`/discussions` の `DiscussionManagementTabLayout` が、通常リンク、`nav`、選択状態、`aria-current`、キーボード操作を持つ参照実装となる。ただし、必要なJavaScriptの量と実装境界は本featureの主眼に合わせて計画で決める。
- Q7: `/locations` に直接アクセスしたときは、カテゴリナビゲーションの決定的な順序における先頭カテゴリの正規URLへ解決する。現在のデータ版では「区役所・出張所」カテゴリが先頭である。
- Q8: GPS取得に成功した場合は、現在のカテゴリURLに`origin=<latitude>,<longitude>`を付与し、既存の経路検索結果URLと同じ緯度・経度の順序で距離順表示する。GPS操作はカテゴリナビゲーションの下に置く。
- Q9: GPS座標は現在のカテゴリURLの`origin=<latitude>,<longitude>`として扱う。カテゴリから別カテゴリへ移るナビゲーションリンクは`origin`を維持し、詳細ページやその他のページへのリンクは`origin`を捨てる。永続ストレージには保存しない。
- Q10: カテゴリページ下には「町字で並べる」と「近い順に並べる」の2つの並べ替え操作を置く。「町字で並べる」は現在カテゴリURLから`origin`を削除し、「近い順に並べる」はGPS取得後に`origin`を付与する。表示中モードは選択状態として伝える。
- Q11: `origin`がない場合は通常の「町字で並べる」。千代田区外でも数値として解釈できる緯度・経度は受け入れ、文字列形式不正やNaNなど座標として解釈できない値は日本語エラーを表示しつつ、一覧を通常の「町字で並べる」で利用可能にする。不正な`origin`はカテゴリ間リンクへ引き継がない。
- Q12: 座標として解釈できない不正な`origin`はURLに残し、日本語エラーと通常の「町字で並べる」一覧を表示する。「町字で並べる」を選択したときだけ現在カテゴリURLから明示的に削除する。
- Q13: 有効な`origin`で近い順表示中にGPS再取得が失敗した場合は、既存の距離順表示と`origin`を維持し、日本語の再取得エラーだけを表示する。
- Q14: 存在しないカテゴリURL・場所詳細URL、またはURL識別子が不正な場合は、ページ固有の案内ではなく通常の404を返す。データ取得失敗・重複ID・形式不正データはURL不在とは分けて既存のエラー状態として扱う。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - カテゴリを固有URLで開く (Priority: P1)

利用者は、場所一覧からカテゴリを選ぶと、そのカテゴリを表す固有URLへ移動し、再読み込み・ブックマーク・共有をしても同じカテゴリの場所一覧を直接確認できる。カテゴリ選択がJavaScriptだけの一時状態に閉じ込められない。

**Why this priority**: 場所一覧のカテゴリをページとして公開することが、Issue #79の場所データ側の中心である。固有URLがあれば、戻る・進む、共有、直接アクセスを標準のブラウザ動作に任せられる。

**Independent Test**: 場所一覧を開き、カテゴリの通常リンクを選択して `/locations/[category-id]` を開く。新しいブラウザ状態で同じURLを直接開き、カテゴリ名と場所一覧が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 場所データに複数のカテゴリがある、**When** 利用者が `/locations` を開く、**Then** ナビゲーションの先頭カテゴリの正規URLへ解決し、そのカテゴリの内容と選択済みの先頭ナビ項目を表示する。
2. **Given** 利用者がカテゴリへのリンクを選択した、**When** ページ遷移が完了する、**Then** URLが `/locations/[category-id]` 形式になり、選択したカテゴリの見出しと場所だけが表示される。
3. **Given** 有効なカテゴリURLをブックマークしている、**When** 一覧ページを経由せずURLを直接開く、**Then** 入力操作なしに同じカテゴリの場所一覧を表示する。
4. **Given** 利用者がカテゴリページ間を移動した、**When** ブラウザの戻る・進むを操作する、**Then** URLと表示中のカテゴリが一致する。
5. **Given** 存在しないカテゴリID、空のカテゴリID、または不正なカテゴリ識別子を含むURLを開いた、**When** ページを表示する、**Then** ページ固有の一覧・戻り案内を表示せず、通常の404を返す。

### User Story 2 - カテゴリから場所詳細へ移動し、元のカテゴリへ戻る (Priority: P1)

利用者は、カテゴリページの場所から詳細ページを開き、詳細を確認した後、「〇〇カテゴリに戻る」リンクで元のカテゴリ一覧へ戻れる。場所詳細は一覧画面の一時的な表示ではなく、直接開けるページとして扱う。

**Why this priority**: 場所詳細への移動と戻り先がカテゴリ単位で明確になることで、一覧・詳細間の責務とブラウザ履歴が単純になる。

**Independent Test**: カテゴリページから有効な場所の通常リンクを選択し、`/locations/location-detail/[id]` の詳細表示、カテゴリへの戻りリンク、目的地設定リンクを単独で確認する。

**Acceptance Scenarios**:

1. **Given** カテゴリページに有効な場所が表示されている、**When** 利用者が場所を選択する、**Then** `/locations/location-detail/[id]` の専用URLへ通常リンクで移動する。
2. **Given** 利用者が有効な場所詳細URLを直接開いた、**When** データの表示が完了する、**Then** 場所名、説明、地域、提供情報、ライセンス、外部サイト、既存の目的地設定操作を確認できる。
3. **Given** 利用者がカテゴリページから詳細へ移動した、**When** 詳細ページの戻りリンクを選択する、**Then** 表示中のカテゴリ名を含む「〇〇カテゴリに戻る」リンクで元の `/locations/[category-id]` へ移動する。
4. **Given** 利用者がカテゴリを経由せず詳細URLを直接開いた、**When** 戻り導線を確認する、**Then** 安全な既定値として `/locations` へ戻り、先頭カテゴリへ解決される。
5. **Given** 存在しない場所IDまたはURL識別子として不正な場所IDを含むURLを開いた、**When** ページを表示する、**Then** ページ固有の詳細・エラー案内を表示せず、通常の404を返す。
6. **Given** 利用者が旧 `/location-detail/[id]` URLを開いた、**When** ページを表示する、**Then** 旧URLを正規ページとして提供せず、新URLへの互換リダイレクトも行わない。

### User Story 3 - 場所データを安定して利用する (Priority: P1)

利用者は、ホームの「よく利用される施設」と場所一覧を開いたとき、外部データの取得処理がブラウザ上の一時的なJavaScript状態に依存せず、必要な場所データを安定して確認できる。カテゴリを選んだ後、カテゴリナビゲーションの下にある「町字で並べる」「近い順に並べる」の2つの操作から表示順を選べる。施設を選択した場合は、既存の経路検索フォームへ目的地として引き継げる。場所名による検索は提供しない。

**Why this priority**: 外部CDNのクライアント取得をページ表示のたびに実行すると、通信失敗や表示順序の複雑化が利用者へ直接伝わる。場所データをブラウザ側の一時状態から外し、GPSだけをページ上の明示的な操作として残すことが、JavaScript削減と機能の単純化につながる。

**Independent Test**: ホームと場所カテゴリページを、外部データ提供元へのブラウザリクエストを発生させずに表示できること、カテゴリナビゲーションの下に2つの並べ替え操作があること、GPS成功時の`origin` URLと距離順表示、デフォルト表示への復帰、ホームの施設選択後の目的地引き継ぎを確認する。

**Acceptance Scenarios**:

1. **Given** 設定された場所データが有効である、**When** 利用者がホームまたは場所一覧を開く、**Then** 施設・カテゴリ・場所データがページ表示時点で利用可能になり、ブラウザから場所データCDNへの取得を開始しない。
2. **Given** ホームに「よく利用される施設」が表示されている、**When** 利用者が施設を選択する、**Then** 既存の目的地入力へ場所が引き継がれ、経路検索結果URLの契約は変更されない。
3. **Given** 場所データが取得できない、形式不正である、または識別子が一意でない、**When** 採用したSSRまたはSSGのデータ取得処理が実行される、**Then** 空の場所一覧や誤った場所詳細を成功状態として公開せず、SSGではビルドを失敗させ、SSRでは日本語の取得失敗状態を表示する。
4. **Given** 場所データの任意項目（説明、画像、外部サイト、提供者情報）が欠落している、**When** 場所詳細を表示する、**Then** 利用可能な主要情報と操作を維持し、欠落項目の空ラベルや壊れたリンクを表示しない。
5. **Given** 利用者がカテゴリページを開いた、**When** カテゴリナビゲーションの下を確認する、**Then** 「町字で並べる」と「近い順に並べる」の2つの操作が表示され、場所名・住所の入力欄は表示されない。
6. **Given** GPS未取得のカテゴリページを表示している、**When** 利用者が「町字で並べる」を選択する、**Then** 現在のカテゴリURLから`origin`を削除し、町字によるデフォルト表示と選択中状態を表示する。
7. **Given** GPS未取得または更新したいカテゴリページを表示している、**When** 利用者が「近い順に並べる」を選択しGPS取得に成功する、**Then** 現在のカテゴリURLに`origin=緯度,経度`を付与し、経路検索結果URLと同じ緯度・経度の順序で近い場所から表示する。
8. **Given** GPS取得後に利用者が別カテゴリへ移動する、**When** カテゴリナビゲーションのリンクを選択する、**Then** `origin`を維持したカテゴリURLへ移動し、同じ座標で移動先カテゴリを距離順表示する。
9. **Given** GPS取得後に利用者が場所詳細またはその他のページへ移動する、**When** 通常のリンクを選択する、**Then** 遷移先URLに`origin`を含めず、保存した位置情報をページ間で自動的に引き継がない。

### User Story 4 - 標準的なページ構造で場所を探す (Priority: P2)

利用者は、カテゴリ一覧、カテゴリページ、場所詳細を、共通レイアウトのナビゲーション、通常の見出し、リンク、戻り導線としてキーボードや支援技術から利用できる。カテゴリを切り替えるためだけのクライアント状態や、詳細へ移動するためのJavaScriptクリック処理に依存しない。

**Why this priority**: URLと共通レイアウトナビゲーションを中心にする目的は、見た目を変えることではなく、ページ・リンク・履歴という標準の意味を利用できるようにすることである。`/discussions` の管理ナビゲーションを既存の参照実装として利用する。

**Independent Test**: `/locations`、有効なカテゴリページ、有効な詳細ページ、無効なURLの各状態を、共通レイアウトのナビゲーション、キーボード、見出し・リンクの自動テストで確認する。

**Acceptance Scenarios**:

1. **Given** 利用者が `/locations` を開いた、**When** 共通レイアウトのカテゴリナビゲーションを確認する、**Then** 先頭カテゴリの正規URLへ解決した状態で、すべてのカテゴリがURLを持つ通常リンクとして識別でき、先頭項目が選択中として伝わる。
2. **Given** 利用者がカテゴリページを開いた、**When** 支援技術がページ構造を読む、**Then** カテゴリ名、場所一覧、詳細リンク、カテゴリナビゲーション、ナビゲーションの下にあるGPS操作を識別できる。
3. **Given** 利用者が場所詳細またはエラー状態を開いた、**When** ページ内を移動する、**Then** 主見出し、状態説明、戻り導線、主要操作へ論理的な順序で到達できる。

## Edge Cases

- カテゴリIDが存在しない、空、またはURL識別子として不正な場合は、ページ固有の案内を出さず通常の404を返す。カテゴリデータ自体が0件の場合はデータ取得・表示エラーとして扱う。
- `/locations` を開いた場合は、カテゴリの決定的な表示順を変えず、先頭カテゴリの正規URLへ解決する。カテゴリが0件の場合は解決せず、データ取得・表示エラーとして扱う。
- `category:en` に空白が含まれるカテゴリ（例: `natural environment park`）でも、URLエンコード後に同じカテゴリへ一意に解決する。
- 場所IDが存在しない、またはURL識別子として不正な場合は通常の404を返す。データ内でIDが重複している場合は、任意の場所を選ばずデータエラー状態にする。
- 同じ場所名が複数カテゴリに存在しても、場所名ではなく一意な場所IDで詳細へ移動する。
- 詳細ページを直接開いたときにカテゴリを特定できない場合は、カテゴリ固有リンクを偽って表示せず、`/locations` を既定の戻り先にする。
- CDNまたはデータ提供元が一時的に利用できない、HTTPエラーを返す、JSONが不正、必須フィールドが欠落している場合は、空配列を正常な場所データとして扱わない。SSGでは公開用ビルドを失敗させ、SSRでは日本語の取得失敗状態を表示する。
- 画像、説明、URI、地域、提供情報の一部がない場合でも、場所名、主要操作、利用可能な情報、戻り導線を失わない。
- ブラウザの戻る・進む、再読み込み、共有URLの直接アクセスで、カテゴリと詳細の対応関係が崩れない。
- 旧 `/location-detail/[id]` URLを開いた場合に、新URLへの互換リダイレクトや旧URLの正規ページ表示を行わない。
- GPSが未取得のカテゴリページでは、町字によるデフォルト表示を行い、「町字で並べる」と「近い順に並べる」を提供する。
- GPS取得が成功した場合は、`origin`を緯度・経度の順で解釈し、現在のカテゴリ内だけを距離順に表示する。
- GPS権限拒否、タイムアウト、未対応ブラウザ、GPSが数値を返さない場合は、`origin`を追加せず、日本語の失敗状態を表示する。Google Maps APIや住所検索APIを呼び出さない。
- 有効な`origin`で距離順表示中にGPS再取得が失敗しても、既存の距離順一覧と`origin`を維持し、再取得エラーだけを表示する。
- URLの`origin`が文字列形式不正、NaNなど座標として解釈できない場合は、日本語エラーと通常の町字一覧を表示し、千代田区外でも数値として解釈できる緯度・経度はエラーにしない。
- 「町字で並べる」を選択すると現在カテゴリURLから`origin`を削除し、デフォルト表示に戻る。
- カテゴリナビゲーションは`origin`を維持し、場所詳細リンクとその他のページ遷移は`origin`を転送しない。ブラウザの戻る操作で以前のURLが復元されることを除き、位置情報を永続・共有状態として保持しない。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムは、ホームの「よく利用される施設」と場所一覧の場所データを、利用者のブラウザが外部CDNへ直接取得することなく、サーバー側のデータ取得境界またはページ生成結果として利用可能にしなければならない。SSRとSSGのどちらを採用するかは本仕様で固定しない。
- **FR-002**: 場所データの取得は、既存の配布先設定で選択されたデータ版を正本として扱い、新しい永続化領域や別の場所データ形式を導入してはならない。
- **FR-003**: `/locations` とカテゴリページは、カテゴリ名と各カテゴリの固有URLへの通常リンクを、共通レイアウトのナビゲーションとして提供し、カテゴリ選択をクライアント側だけの一時的なタブ状態として提供してはならない。`/discussions` の管理ナビゲーションを構造・状態・キーボード操作の参照実装とする。
- **FR-004**: 各カテゴリは、既存の `category:en` をURLエンコードした値を `[category-id]` とする `/locations/[category-id]` で直接アクセス、再読み込み、ブックマーク、共有でき、URLに対応するカテゴリの場所だけを表示しなければならない。別のslug対応表を正本としてはならない。
- **FR-005**: 未知、空、またはURL識別子として不正なカテゴリIDでは、空の一覧やページ固有の戻り案内を表示せず、通常の404を返さなければならない。
- **FR-006**: カテゴリページに表示する各場所は、一意な場所IDを含む `/locations/location-detail/[id]` への通常リンクでなければならない。
- **FR-007**: 場所詳細ページは、既存の場所データ形式、場所名、説明、地域、提供情報、ライセンス、外部サイト、目的地設定操作の意味を維持しなければならない。
- **FR-008**: カテゴリページから詳細ページへ移動した場合、詳細ページは表示元カテゴリを特定できる戻り先として `/locations/[category-id]` を提供し、リンク名にカテゴリ名を含めなければならない。直接アクセスなどでカテゴリを特定できない場合は `/locations` を既定の戻り先とする。
- **FR-009**: 場所詳細の正規URLは `/locations/location-detail/[id]` とし、旧 `/location-detail/[id]` は廃止しなければならない。旧URLを正規ページとして残したり、新URLへの互換リダイレクトを追加したりしてはならない。
- **FR-010**: 未知またはURL識別子として不正な場所IDでは通常の404を返さなければならない。データ内のID重複、データ取得失敗、デコード失敗、必須フィールド検証失敗では任意の場所を表示せず、原因に応じた日本語のデータエラー状態と安全な戻り導線を提供しなければならない。
- **FR-011**: 任意の場所情報が欠落している場合、利用可能な情報を表示し、空のラベル、壊れた外部リンク、場所名を重複させる代替テキストを表示してはならない。
- **FR-012**: ホームの施設選択は、選択した場所を既存の目的地入力へ引き継がなければならず、既存の経路検索結果URL・検索条件・API契約を変更してはならない。
- **FR-013**: カテゴリページは、カテゴリナビゲーションの下に「町字で並べる」と「近い順に並べる」の2つの並べ替え操作を提供し、GPS成功時は現在のカテゴリ内の場所を`origin`座標から距離順に表示しなければならない。
- **FR-014**: `/locations`、カテゴリページ、詳細ページ、データエラー状態は、主見出し、通常リンク、キーボードフォーカス、状態説明、戻り導線を持ち、カテゴリの基本遷移と基本情報の表示にJavaScriptを必須としてはならない。未知・不正URLはページ固有の状態ではなく通常の404として扱う。利用者操作に必要なJavaScriptを残す場合は、場所データ取得やURL遷移と責務を混在させてはならない。
- **FR-015**: 本featureは、新しい永続化、新しい外部API、場所データの収集・編集、経路検索フォームの段階的入力や意味論的HTML化を導入・変更してはならない。
- **FR-016**: 採用したSSRまたはSSGのデータ取得・検証で場所データを取得できない、形式不正である、または必須識別子が一意でない場合、空または不完全な場所データを成功状態として公開してはならない。SSGでは公開用ビルドを失敗させ、SSRでは日本語の取得失敗状態を表示しなければならない。
- **FR-017**: カテゴリページの `[category-id]` は既存の `category:en` をURLエンコードした値であり、空白を含む値も同じ正本から一意に解決できなければならない。別のASCII slugやカテゴリ対応表を追加してはならない。
- **FR-018**: カテゴリナビゲーションは、共通レイアウトがURLに基づく現在状態と戻り先を管理し、ページ本体はカテゴリ固有の場所一覧を管理しなければならない。場所ページごとに独自のタブ状態を複製してはならない。
- **FR-019**: `/locations` への直接アクセスは、カテゴリナビゲーションの決定的な順序における先頭カテゴリの正規URLへ解決し、そのカテゴリの場所一覧と先頭ナビ項目の選択状態を表示しなければならない。カテゴリが0件の場合は解決せず、データ取得・表示エラーを表示しなければならない。
- **FR-020**: GPS成功時の現在カテゴリURLは、`origin=<latitude>,<longitude>` の値を持たなければならず、緯度・経度の順序は既存の経路検索結果URLと同じでなければならない。座標はカテゴリページの一時的なURL状態として扱い、ブラウザ内の永続ストレージへ保存してはならない。
- **FR-021**: カテゴリナビゲーションは現在の有効な`origin`を別カテゴリURLへ維持しなければならない。場所詳細リンク、その他のページ遷移、「町字で並べる」操作は`origin`を削除し、GPSで得た座標を詳細ページやその他のページへ暗黙に引き継いではならない。
- **FR-022**: 場所ページは、場所名または住所を入力して検索する機能を提供してはならず、そのためにGoogle Maps API、ジオコーディングAPI、専用のレート制限状態を呼び出してはならない。
- **FR-023**: 「町字で並べる」と「近い順に並べる」は、表示中モードをアクセシブルに伝え、「町字で並べる」選択時はクエリを持たない現在カテゴリURL、「近い順に並べる」選択時は有効な`origin`を持つ現在カテゴリURLと一致しなければならない。
- **FR-024**: `origin`がない場合は通常の「町字で並べる」を表示し、千代田区外でも数値として解釈できる緯度・経度は距離順表示に使用しなければならない。`origin`が文字列形式不正、NaNなど座標として解釈できない場合は、日本語エラーを表示しつつ通常の「町字で並べる」を表示し、不正な`origin`をカテゴリ間リンクへ引き継いではならない。
- **FR-025**: 座標として解釈できない不正な`origin`は現在URLに残し、日本語エラーと通常の「町字で並べる」一覧を表示しなければならない。「町字で並べる」操作を選択したときだけ現在カテゴリURLから`origin`を削除しなければならない。
- **FR-026**: 有効な`origin`で近い順表示中にGPS再取得が失敗した場合、既存の`origin`と距離順表示を維持し、日本語の再取得エラーを表示しなければならない。`origin`を自動削除して町字表示へ戻したり、一覧を空にしたりしてはならない。

### Key Entities

- **場所データセット**: ホームのよく利用される施設、カテゴリ一覧、場所詳細の表示元となる、設定された版のデータ。
- **場所カテゴリ**: 表示名、機械可読なカテゴリ識別子、所属する場所一覧、カテゴリページURLを持つ場所の分類。
- **場所詳細リソース**: 一意な場所IDに対応する名前、位置、説明、提供情報、ライセンス、外部リンク、目的地設定情報。
- **場所ページURL**: `/locations`、`/locations/[category-id]`、`/locations/location-detail/[id]` を通じて、一覧・カテゴリ・詳細を直接参照するURL。
- **カテゴリ戻り先**: 詳細ページの表示元カテゴリを表す安全な同一サイト内のURL。カテゴリを特定できない直接アクセスでは `/locations` を用いる。
- **カテゴリナビゲーション**: 共通レイアウトが提供するカテゴリへの通常リンク群。URL、表示ラベル、現在状態、キーボード操作、カテゴリページ本体との関係を持つ。
- **GPS起点座標**: 現在のカテゴリページでGPSから取得し、`origin`クエリに緯度・経度の順で表現する一時的な位置情報。カテゴリ間では維持するが、詳細・その他のページへは転送せず、距離順表示にだけ使う。
- **並べ替えモード**: `origin`なしの「町字で並べる」と、有効な`origin`を持つ「近い順に並べる」の2つのカテゴリ表示状態。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `/locations`、設定された全カテゴリページ、代表的な有効詳細ページを直接URLで開いた100%のケースで、ブラウザから場所データCDNへの取得を行わず、対応するカテゴリ・詳細情報を表示できる。
- **SC-002**: `/locations` がカテゴリナビゲーションの先頭カテゴリURLへ100%解決し、先頭項目が選択状態になる。全カテゴリが既存の `category:en` をURLエンコードした通常リンクとして公開され、空白を含む代表カテゴリを含む全カテゴリについて、リンク選択・直接アクセス・再読み込み・戻る・進むの各シナリオが100%成立する。
- **SC-003**: カテゴリページの全場所リンクが新しい正規詳細URLへ遷移し、カテゴリ経由で開いた詳細ページの戻りリンクが100%元のカテゴリURLへ戻る。旧URLの代表ケースでは、新URLへの互換リダイレクトが発生せず、旧URLが正規の公開導線として残らないことを確認する。
- **SC-004**: 未知・空・不正なカテゴリURLと未知・不正な場所詳細URLの代表ケースでは、ページ固有の成功・エラー案内を表示せず通常の404を100%返す。データ内ID重複、SSGを選択した場合の取得失敗・形式不正・必須識別子重複ではデータエラーまたはビルド失敗を明確に区別し、SSRを選択した場合は日本語のデータ取得失敗状態を100%表示する。
- **SC-005**: ホームの代表的な施設選択で、既存の目的地入力への引き継ぎが100%成立し、経路検索結果URLの既存契約に変更がない。
- **SC-006**: 欠落する任意項目を含む代表場所で、場所名・主要操作・利用可能な情報・戻り導線が100%確認でき、壊れたリンクと空ラベルが0件になる。
- **SC-007**: `/locations`、カテゴリ、詳細、エラー状態の共通ナビゲーション・キーボード・見出し・リンク契約テストがすべて成功し、カテゴリの基本遷移とページ基本情報の表示にJavaScript実行を必須としない。
- **SC-008**: 代表的なカテゴリページで、「町字で並べる」と「近い順に並べる」の2つの操作が表示され、GPS成功時に`origin`が緯度・経度の順で付与され、カテゴリ内の距離順表示が成立する。場所名・住所入力、Google Maps API、専用の住所検索レート制限導線は0件となる。
- **SC-009**: 本featureの変更差分に、経路検索フォームの段階的入力・意味論的HTML化・`/routes` の検索条件契約に関する変更が0件である。
- **SC-010**: GPS取得後にカテゴリナビゲーションを選択した代表シナリオで、`origin`が維持された移動先カテゴリの距離順表示が100%成立する。場所詳細リンク、その他のページリンク、「町字で並べる」では`origin`転送が0件となる。
- **SC-011**: 空でない場所データを使った直接アクセス、カテゴリから詳細、詳細から戻るの代表シナリオで、URLと選択中ナビ項目と表示中カテゴリの不一致が0件になる。
- **SC-012**: 文字列形式不正・NaNなどの`origin`代表ケースでは、日本語エラーと町字一覧を100%表示し、千代田区外の数値座標代表ケースではエラーにせず距離順表示を100%成立させる。
- **SC-013**: 有効な`origin`で距離順表示中のGPS再取得失敗代表ケースで、既存の距離順一覧と`origin`が維持され、再取得エラーだけが表示される。

## Assumptions

- 場所データは既存の設定されたデータ版を使用し、データ収集元、内容、ライセンス、既存の任意項目の意味は変更しない。
- 場所詳細の正規URLは `/locations/location-detail/[id]` とし、旧 `/location-detail/[id]` は廃止する。既存共有URL維持のための互換リダイレクトは本featureに追加しない。
- `[category-id]` はデータが持つ `category:en` を正本とし、URLエンコードして使用する。表示用の日本語カテゴリ名とは分離し、別のslug規則や対応表は持たない。
- カテゴリの表示順はデータ取得後に決定的に保ち、先頭カテゴリを `/locations` の既定カテゴリとする。現在のデータ版では先頭カテゴリは「区役所・出張所」（`city_office_and_branch_offices`）である。
- 場所IDは、正常なデータではカテゴリをまたいで一意であり、重複時は任意の一件を選ばずエラーとして扱う。
- データ取得・検証はサーバー側のデータ取得境界で行い、公開済みページのブラウザは場所データCDNへ直接アクセスしない。SSRまたはSSGの選択、キャッシュ、再検証の詳細は計画で決める。
- 場所データを取得できない、形式不正である、または必須識別子が重複している場合、空配列・古いスナップショット・成功状態を公開しない。SSGではビルドを失敗させ、SSRでは日本語の取得失敗状態を表示する。
- URL上で存在しないカテゴリ・場所詳細や不正なURL識別子には、共通の通常404を使用し、feature固有のカスタム404を追加しない。URLは存在するがデータ取得・検証に失敗した状態とは分離する。
- 「近いところから表示」はGPSだけを使う2つの表示操作として残し、カテゴリナビゲーションの下に置く。場所名・住所検索、Google Maps API、ジオコーディング、専用のレート制限導線は導入しない。
- GPS成功時は現在のカテゴリURLに`origin`を付与し、カテゴリナビゲーションでは`origin`を維持する。一方、詳細リンク・その他のページリンク・「町字で並べる」では`origin`を削除し、sessionStorage/localStorageには保存しない。通常のブラウザ履歴によるURL復元だけは妨げない。
- カテゴリナビゲーションは共通レイアウトの責務とし、`/discussions` の `DiscussionManagementTabLayout` を参照して通常リンク、`nav`、現在状態、キーボード操作、コンテンツとの関係を確認する。ただし、場所ページへ不要なデータ取得やクライアント状態を持ち込まない。
- 既存の場所詳細アクセシビリティ仕様 `018-accessible-route-pages` および `019-location-detail-accessibility` の表示・状態・アクセシビリティ契約を基礎とし、今回のURL構造変更で矛盾させない。
- 既存の経路検索結果URI仕様 `016-bookmarkable-route-results` と、ホームの目的地クエリ引き継ぎは変更しない。

## Out of Scope

- ホームの経路検索フォームを、段階的なJavaScript表示から常時存在する`section`・`fieldset`・`legend`中心のフォームへ再設計すること。これは別feature・別PRで扱う。
- `/routes` の検索条件URI、検索結果取得、結果表示、PDF・カレンダー出力の変更。
- 旧 `/location-detail/[id]` URLの互換リダイレクト、旧URLを残すための別名ルート、既存共有URLを維持するための後方互換対応。
- 経路検索フォーム側のGoogle Maps API、住所検索、逆ジオコーディング、Issue #80の町字・住所データ方針の変更。場所ページのGPS取得とカテゴリ内距離順表示は本featureの範囲に含む。
- 場所データの収集元、JSONスキーマ、カテゴリ内容、ライセンス、画像、説明文の編集。
- 新しいデータベース、キャッシュ、ブラウザ永続化、新しい外部APIの追加。
- SSRまたはSSGの選択、キャッシュ・再検証方式、データ取得の具体的なモジュール構成など、実装方式の確定。これらはplanで決める。
- ページ固有のカスタム404、カテゴリ・場所詳細だけの404画面、404からのfeature固有の戻り導線の追加。
- 場所ページの大規模な配色・レイアウト刷新。既存の意味、操作、レスポンシブ表示を優先する。
- 認証、Nostrディスカッション、GTFS、経路探索アルゴリズムの変更。
