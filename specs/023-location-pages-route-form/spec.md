# Feature Specification: 施設ページと検索フォームのURL整理

**Feature Branch**: `spec/issue-79-uri-pages`

**Created**: 2026-09-05

**Status**: Clarified（仕様案の確認事項を反映済み。実装未着手）

**Input**: [Issue #79](https://github.com/nawashiro/kazaguruma-transit/issues/79)。施設の表示をビルド時に用意する。カテゴリと詳細を独立ページにする。検索条件をURLで渡し、入力ページを通常のフォームにする。

## User Scenarios & Testing

### User Story 1 - 施設をカテゴリ別のページで探す (Priority: P1)

利用者はカテゴリのURLを直接開き、施設一覧から詳細へ移動する。詳細から所属カテゴリへ戻る。

**Why this priority**: 閲覧のための追加処理と一時状態への依存をなくす。

**Independent Test**: 新しいブラウザでカテゴリURLを開き、詳細とカテゴリへの往復を確認する。ページのスクリプトを無効にした場合も確認する。

**Acceptance Scenarios**:

1. **Given** 公開済みの施設データ、**When** `/locations`を開く、**Then** カテゴリへのリンクと既存の案内・出典を表示する。
2. **Given** 有効なカテゴリ、**When** `/locations/[category-id]`を直接開く、**Then** 対象カテゴリの施設を町字別に表示する。再読み込みしても同じカテゴリを表示する。
3. **Given** カテゴリ内の施設、**When** 詳細リンクを開く、**Then** `/locations/location-detail/[id]`に施設名、提供済みの説明・画像・外部リンク・帰属情報を表示する。
4. **Given** 施設詳細、**When** 「〇〇カテゴリに戻る」を選ぶ、**Then** 所属カテゴリのページを開く。ブラウザ履歴や保存状態を必要としない。
5. **Given** 不明な施設またはカテゴリの識別子、**When** URLを開く、**Then** HTTP 404の共通ページに見出し「ページが見つかりません」と本文「お探しのページは見つかりませんでした。」を表示する。カテゴリ・詳細固有のページや別の施設を推測して表示せず、一覧への戻るリンクも設けない。

6. **Given** 町字別のカテゴリページ、**When** 現在地の利用または住所検索を明示的に行う、**Then** その地点からの距離順に施設を表示する。検索失敗時も施設一覧を失わない。
7. **Given** 距離順表示、**When** カテゴリURLを直接開くか再読み込みする、**Then** 町字別の初期表示へ戻る。位置情報を自動要求しない。

### User Story 2 - 外部リンクから検索条件を入力する (Priority: P1)

利用者は共有リンクや施設の「ここへ行く」から、条件を入力済みのトップページを開く。

**Why this priority**: 入力済み条件を第三者が再現できるようにする。

**Independent Test**: 目的地のみのURLと全条件のURLを、保存設定の異なるブラウザで開く。

**Acceptance Scenarios**:

1. **Given** 施設詳細、**When** 「ここへ行く」を新しいタブで開く、**Then** トップページに目的地を設定する。経路検索は開始しない。
2. **Given** 有効な入力URL、**When** 再読み込みまたは別端末で直接アクセスする、**Then** URLで指定した条件を再現する。読み込み時にURLの条件を削除しない。
3. **Given** 目的地だけを指定したURL、**When** 開く、**Then** 未指定の出発地を入力できる。日時と優先条件も最初から確認・変更できる。
4. **Given** 不正値を含むURL、**When** 開く、**Then** 該当項目へ日本語の修正案内を表示する。有効な他項目は維持し、経路検索を開始しない。
5. **Given** URLと端末の保存設定が異なる、**When** 開く、**Then** URLを優先する。

### User Story 3 - 全項目を確認してから検索する (Priority: P1)

利用者は目的地、出発地、日時、移動の優先条件を任意の順に入力する。最後に「検索」で結果ページを開く。

**Why this priority**: 段階ごとに画面が入れ替わる操作をなくし、入力の全体像を保つ。

**Independent Test**: 日時を先に入力し、目的地と出発地を指定する。一方の場所を修正し、他の条件を維持して検索する。

**Acceptance Scenarios**:

1. **Given** 未入力のトップページ、**When** 開く、**Then** 「目的地を選ぶ」「出発地を選ぶ」「日時を選ぶ」「スピードを選ぶ」と最後の「検索」を最初から表示する。
2. **Given** 場所が未確定、**When** 日時や優先条件を操作する、**Then** 場所の選択を先に要求しない。
3. **Given** 名前で場所を検索する、**When** 検索に成功する、**Then** 該当する場所を確定する。失敗時は他の入力を保持して修正できる。
4. **Given** 出発地を選ぶ、**When** 「端末のGPSを許可する」を押す、**Then** 位置情報を要求する。拒否・未対応・失敗時は名前検索を案内する。
5. **Given** 両地点と日時が確定済み、**When** 一方の場所を修正する、**Then** もう一方の場所、日時、優先条件を保持する。
6. **Given** 全条件が有効、**When** 最後の「検索」を送信する、**Then** `/routes`へ全条件を渡す。入力ページ内では結果を取得・表示しない。
7. **Given** 必須条件が不足、**When** 最後の「検索」を送信する、**Then** 不足項目を日本語で示し、経路検索を開始しない。
8. **Given** キーボードまたは読み上げを使う、**When** 入力から送信まで操作する、**Then** 各項目の名前、選択状態、エラー、操作順序を理解できる。変更のないフォーム全体を繰り返し通知しない。

9. **Given** 日時と出発地を入力済み、**When** トップページ内のカテゴリ別選択欄で施設を選ぶ、**Then** ページ移動せず目的地を確定する。他の条件を維持する。
10. **Given** 確定済みの地点、**When** 「なおす」を押す、**Then** その地点だけ再入力表示に戻り、入力欄へフォーカスが移る。他のセクションは消えない。

### User Story 4 - 施設データの配信障害に左右されず閲覧する (Priority: P2)

利用者は公開済みページで施設を閲覧する。管理者は公開準備時に施設データの更新を反映する。

**Why this priority**: 施設を開くたびの外部データ取得をなくす。

**Independent Test**: 正常データで公開準備を完了した後、データ配信元への接続を遮断して一覧・カテゴリ・詳細・よく利用される施設を確認する。

**Acceptance Scenarios**:

1. **Given** 公開準備済みの施設ページ、**When** 配信元が停止する、**Then** 施設本文とリンクを閲覧できる。外部画像自体の配信はこの保証に含めない。
2. **Given** データ配信元で施設情報が更新済み、**When** 次の公開準備を行う、**Then** 同じ更新版を一覧・カテゴリ・詳細・トップページ内の各対象データへ反映する。
3. **Given** 必須データの取得失敗または形式不正、**When** 公開準備を行う、**Then** 失敗を管理者へ報告する。空一覧として正常公開しない。

### Edge Cases

- 空カテゴリには「該当する施設はありません」を表示する。全データの取得失敗とは区別する。
- 町字を判定できない施設は「地域不明」にまとめる。施設自体は除外しない。
- 施設識別子の不正・重複、カテゴリ識別子の空値・衝突は公開準備のエラーにする。黙って補正しない。
- 施設の所属カテゴリは公開データから確定する。既存契約と同様、施設識別子の重複を許容しない。
- URL内の座標は緯度-90〜90、経度-180〜180とする。空値・非数・範囲外を拒否する。
- 日時は実在する日付と時刻を要求する。真偽値は`true`または`false`とする。
- 同じクエリ名の重複は検索結果の現行契約に合わせ、先頭の有効値を採用する。未知のクエリ名は無視する。
- 日時未指定時は閲覧時の日時を初期値とする。ビルド日時を利用者の出発日時にしない。
- 名前やラベルをURLから受け取る場合も単なる文字列として表示する。座標の代替や操作命令として扱わない。
- 名前検索中の再入力や場所の修正で、古い検索応答が新しい選択を上書きしない。
- 位置情報の要求は明示操作後だけ行う。閲覧だけでは要求しない。

## Requirements

### Functional Requirements

- **FR-001**: `/locations`をカテゴリへの入口とする。カテゴリは`/locations/[category-id]`、詳細は`/locations/location-detail/[id]`で直接参照できる。
- **FR-002**: カテゴリ切替と詳細への移動は通常のリンクにする。スクリプトを無効にしても施設本文と所属カテゴリへのリンクを利用できる。
- **FR-003**: 詳細に所属カテゴリ名を含む「〇〇カテゴリに戻る」を表示する。閲覧元の一時状態に依存しない。
- **FR-004**: 一覧・カテゴリ・詳細・トップページの施設データと町字分類を、本番のビルド時に用意する。閲覧時の外部データ取得や独自の施設配信窓口を必要としない。
- **FR-005**: 施設名、座標、説明、画像、外部リンク、出典、ライセンスを維持する。任意項目の欠落は施設全体の非表示理由にしない。
- **FR-006**: 必須データの取得・検証失敗をビルド失敗として報告する。空配列や旧方式への自動切替で成功扱いしない。
- **FR-007**: トップページ`/`は、結果ページと共通の`origin`、`destination`、`time`、`isDeparture`、`prioritizeSpeed`で初期入力を受け付ける。地点は`緯度,経度`、日時は`YYYY-MM-DDTHH:mm`とする。入力ページでは一部指定を許可する。
- **FR-008**: 「ここへ行く」は目的地座標を持つトップページへのリンクにする。読み込み時に条件を消さない。座標のみでも場所を明示できる表示を用意する。
- **FR-009**: URLの条件は端末内の保存設定より優先する。URL未指定の優先条件は既存設定があれば利用し、それ以外は「歩きを最小限、ゆっくり行く」とする。
- **FR-010**: 全4セクションを最初から表示する。入力順を強制しない。最終送信前に経路検索を開始しない。
- **FR-011**: 目的地は施設選択と名前検索を提供する。出発地は位置情報取得、名前検索の順で提供する。
- **FR-012**: 日時のラベルは「日時」に固定する。「出発時刻」「到着時刻」のラジオボタンで意味を選ぶ。初期値は出発時刻とする。
- **FR-013**: 優先条件は「歩きを最小限、ゆっくり行く」「歩きを許可、はやく行く」のラジオボタンとする。検索計算上の意味は変更しない。
- **FR-014**: 最後の「検索」はフォームの送信操作とする。場所の名前検索と経路検索を区別する。標準の入力、ラベル、グループ構造を使い、フォームを入れ子にしない。
- **FR-015**: 場所の確定後は、その地点だけ「住所などの地点表示＋なおす」に切り替える。他のセクションは常に表示する。「なおす」は該当地点だけを再入力状態に戻し、その入力欄へフォーカスを移す。他の地点、日時、優先条件を消さない。
- **FR-016**: 施設カテゴリページに現在地・住所を基準とする距離順表示を残す。初期表示はビルド時に用意した町字別一覧とし、利用者の明示操作後だけ動的に並べ替える。施設データを再取得しない。位置情報や名前検索の失敗時も一覧を維持する。
- **FR-017**: トップページに「よく利用される施設」を残す。専用の候補集合を維持し、全候補をビルド時に用意する。カテゴリ別の標準的な選択欄で目的地を選び、ページ遷移や候補の追加取得を行わない。選択時に他の入力を消さない。
- **FR-018**: 入力エラーや取得失敗は対象項目の近くに表示し、他の入力を保持する。キーボード操作、フォーカスの可視性、読み上げでの名前・状態・関係を維持する。
- **FR-019**: 旧詳細URL、旧JSON形式の目的地引渡し、置換後に不要な表示経路を削除する。後方互換用の分岐やリダイレクトを追加しない。
- **FR-020**: `/routes`の検索条件、結果表示、出力、エラー、利用制限の現行契約を維持する。施設閲覧以外の動的検索機能を一律に廃止しない。

### Key Entities

- **施設**: 一意の識別子、名称、座標、所属カテゴリ、町字、任意の説明・画像・外部リンク、帰属情報を持つ。
- **カテゴリ**: 安定した識別子、日本語の表示名、所属施設を持つ。
- **入力条件**: 出発地、目的地、日時、出発・到着指定、歩行と速さの優先条件。入力途中では欠落を許可する。
- **公開用施設データ**: 設定済みの更新版に基づく一覧用・選択用データ。公開後は次のビルドまで更新しない。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 公開対象の全カテゴリと全施設を、保存状態のないブラウザで直接開ける。全施設の所属カテゴリリンクが正しいページに戻る。
- **SC-002**: 施設本文とカテゴリ・詳細間の移動は、スクリプト無効時およびデータ配信元の停止時にも全対象で利用できる。
- **SC-003**: 目的地のみ、両地点、全条件の入力URLを直接表示・再読み込みした全ケースで、指定条件を再現する。
- **SC-004**: 未入力時から全4セクションを確認できる。場所・日時の入力順を変えた受入ケースで、他項目の意図しない消失が0件となる。
- **SC-005**: キーボード操作と読み上げの双方で、入力、片地点の修正、最終送信を完了できる。結果ページに渡す条件が入力内容と一致する。
- **SC-006**: 不正URL、名前検索失敗、位置情報拒否の各ケースで、利用者が他項目を再入力せず修正を続けられる。
- **SC-007**: 必須データの取得失敗・形式不正・識別子重複の各ケースで、不完全な施設ページを正常な公開成果物として扱う件数が0件となる。

## Assumptions

- 「ルートページ」は経路結果ではなくトップページ`/`を指す。結果ページ`/routes`とは統合しない。
- 正本は`AGENTS.md`と`.specify/memory/constitution.md`。今回の仕様は対象画面の旧仕様を置き換える。対象外の契約は変更しない。
- カテゴリ識別子は既存データの`category:en`を候補とし、実データの一意性とURLへの適合を計画時に確認する。表示名から暗黙の補正で識別子を作らない。
- トップページの候補と施設一覧は、現行の異なるデータ集合を維持する。データ集合の統合や候補の拡大は行わない。
- 日時の解釈は検索結果の既存仕様を維持する。新たなタイムゾーン変換を追加しない。
- 場所名は検索条件の正本ではない。座標のみの入力では座標表示を許容する。名前の補足だけを目的とする新しい有料問い合わせを追加しない。
- 距離順の基準地点はページ内の一時状態とする。カテゴリ移動・再読み込みでは町字別表示に戻す。距離順状態の共有や永続化は追加しない。
- スクリプトを一律に禁止しない。位置情報取得、名前検索、入力検証など必要な対話処理を残す。経路検索全体のスクリプト無効対応は追加要件としない。
- WCAG (Web Content Accessibility Guidelines) 2.2 AAを目標とする既存方針を適用する。個別基準と検証手順は計画段階で定義する。
- サイト全体のカード撤去はIssue #77、座標から地名への変換サービスの置換はIssue #80で扱う。今回のフォーム構造整理に必要な変更だけを含む。
- 未入力箇所の装飾による強調は追加しない。新規認証、永続化、交通データや経路計算の変更も含めない。
- 拡張フック設定`.specify/extensions.yml`は存在しないため、前後フックは実行しない。
